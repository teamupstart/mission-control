Phase 1 · implementation contract

Provider-neutral Pipeline Engineer host

Make Claude and Codex peers on Mission Control's managed Pipeline launch path while preserving AI Conductor's downstream choices and provider-owned completion.

Full plan · Phase map · Markdown source

Reproduce first

In the built dashboard, enable Conductor, choose Pipeline in Dispatch, and prove the Agent control is disabled and the resulting session is always Claude. Extend e2e/specs/conductor-loops.spec.ts from that exact path.

Target proof

Choosing Codex creates one fake Codex SDK session whose accepted opener includes Codex's Engineer skill invocation and the original intent. No real model tokens are spent.

Implementation sequence

1

Migrate the runtime. Parse legacy claude-sdk as canonical agent-sdk; emit only the canonical value.

2

Derive eligibility. Use shared harness capabilities to require both an SDK driver and an invocable Engineer skill.

3

Separate provider and host. Keep repository consent and run identity in Pipeline resolution. Compose the host-specific Engineer command in the dispatcher.

4

Launch task.agent. Start the generic supervisor with that agent's normal dispatch permission mode and no task-level model or effort override.

5

Align Dispatch. Offer eligible hosts for managed Pipeline tasks, include Agent in guided mode, keep Model and Effort disabled, and make Terminal visibly Claude-only.

6

Pin and document. Add focused contract, HTTP, dispatcher, Settings, and browser coverage before updating docs/pipelines.md.

Prompt contract

Claude: /engineer <intent>
Codex:  $engineer - run this skill now. <intent>

Tests own the final byte shape. The task intent must be preserved after a clear separator.

Safety invariants

  • Reserve the Pipeline run before host launch.
  • Stop a late-starting session after cancellation.
  • Bind the session to the task work episode.
  • Reject unsupported or mismatched hosts.
  • Never fall back to Terminal.

Verification matrix

  • Legacy setting migration
  • Canonical Settings round-trip
  • Claude and Codex eligibility
  • Agent-specific opener bytes
  • Selected agent reaches supervisor
  • Codex permission mode
  • Invalid-host refusal
  • No Terminal fallback
  • Guided Agent question
  • Disabled Model and Effort
  • Terminal Claude-only state
  • Desktop and narrow visual QA
  • Typecheck and lint
  • Full unit suite and build

Non-negotiable boundaries

Do not modify AI Conductor, add native Codex support to conduct-ts engineer, enable Pipeline Recurring Missions or backlog autopilot, expose task-level model or effort controls, or change provider-owned completion.
