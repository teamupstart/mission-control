Investigated findings

No new runtime concept, database migration, API, or Shipping rule is needed. The work is an added compiled Persona, an append-only v9 graph, and a presentation-only distinction between the local and remote roles.

  • The existing generator compiles any eligible personas/*.md file into the packaged catalog.
  • Workflow Personas already receive intent, decisions, prior feedback, local diff, transcript, standards, dirty/untracked work, and evidence fingerprints. They remain tool-less.
  • v8 already verifies the Pull Request action before End, and { kind: "none" } already completes End without consulting the Inspector ledger.
  • v9 must be appended while v1 through v8, their node/edge ids, defaults, policies, and snapshots remain unchanged.
  • All inspector routes, settings keys, database names, events, markers, and completion values remain stable. Only user-visible remote-service language becomes GitHub Inspector.
  • Old and custom workflows may still use the inspector final gate, so those rendered surfaces also adopt the GitHub Inspector name.

Why one phase

The Persona, v9 graph, and product naming form one vertical contract. Splitting them would create an intermediate release where two reviewers share the same name, or where documentation describes a workflow version that does not exist. There is no independent migration or foundation whose early merge reduces risk, so one phase is safer and easier to review.

Dependency and product flows

Cross-phase contracts

  • Identity: add only builtin:code-quality-judge, nmr-code-quality-judge, and builtin-workflow:no-mistakes-review@9.
  • Workflow: v9 adds Code Quality Judge and completion none; v1 through v8 remain frozen and resolvable.
  • Execution: the local role is a normal tool-less Persona selected by the graph, never injected by a setting.
  • PR proof: the existing Pull Request action remains the sole v9 publication proof.
  • Remote behavior: GitHub Inspector keeps its worker, settings, trust, ledger, comments, and Shipping integration.
  • Terminology: user-facing local review says Code Quality Judge; user-facing remote review and legacy/custom final gates say GitHub Inspector; internal identifiers remain stable.

Final verification strategy

  • Regenerate and byte-check the built-in Persona module.
  • Pin v9 topology, snapshots, completion, repair-before-PR ordering, and v1 through v8 immutability.
  • Pin GitHub Inspector wording in render and pure-data tests without renaming internal contracts.
  • Use Playwright with fake agents and fake gh to show Code Quality Judge before Pull Request and the renamed Settings panel.
  • Pass typecheck, lint, full unit tests, build, smoke, and full e2e. Attach successful visual evidence to the implementation PR, never the repository.
