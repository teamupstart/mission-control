01 · Outcome

Configure the common case once

An operator can define what test normally means on this machine without first choosing a repository. Workflows remain portable and resolve the concrete argv only after a run knows its repository.

02 · Product model

A fixed catalog, not another free-form asset system

Shelf

What does each standard gate run?

Four cards always appear in append-only slot order. There is no New or Archive action.

Editor

Default first, exceptions second

The selected slot owns one global command and a collapsible or visually secondary override list.

Workflow

Portable by construction

A workflow adds Command · test, not npm test. Resolution waits for run context.

05 · Safety and copy

Fewer warnings, same enforcement

Keep

Authorization and runtime barriers

  • Machine-wide Allow workflow Commands control
  • Workflows Trust repository grant
  • argv without a shell
  • commit-pinned leased worktree
  • environment scrubbing, bounded output, concurrency, teardown, and recovery
Simplify

One meaningful consent moment

  • One confirmation when enabling or re-enabling
  • One neutral execution note in the editor
  • No persistent red banner around every field
  • No per-command acknowledgement
  • No claim that a global default runs automatically
Not in scope: splitting repair delivery and Command execution into separate Trust grants. That is a policy project with its own migration and UX, not part of relocating this catalog.

06 · Persistence and compatibility

One catalog authority

The daemon owns normalized slot and override records through a store and manager. All four built-in slots are projected even when empty. Browser state rides the existing snapshot and upsert stream.

Seed fixed slots

Fresh databases project all four slot views without adding a creatable asset model.

Migrate old rows as overrides

Group existing checkCommands by slot. Never infer a global default from one repository's argv.

Cut runtime over

The new manager becomes the only persisted command source. Policy remains in workflow config.

Bridge the old editor temporarily

Phase 1 projects catalog overrides through the current config route so Settings stays operable between merges.

Move authoring to Library

Phase 2 consumes the dedicated catalog API and live collection, then removes the old Settings table.
