# Phase 1: Live microphone capture

The [approved source](plan.md) and [implementation index](phased-plan.md) cover the mission-control repository.

## Outcome

An operator can launch the sherpa listener on the test desktop, speak a roster name and message, and see the daemon accept the timed utterance. This supplies the live input for daemon supervision.

## Entry and direct dependencies

Planning publication, the operator’s explicit confirmation of a reserved physical desktop and tester, and the merged task “Voice Addressing for Agents - Phase 16: The sherpa-onnx backend”. Record access before any spike or implementation. Identify audio stack, session, input/output devices and test architecture.

## Scope

Own capture selection, the live mode of the standalone listener and evidence for device closure. Leave daemon startup, desktop reports, spoken playback and Setup rendering to later phases. Keep file-input mode confined to its current development/test use.

## Implementation and compatibility

Compare an installed PipeWire or PulseAudio client against a directly integrated audio library on the operator’s desktop. Measure dependency availability, device enumeration and stable IDs, default and selected input, format conversion to mono 16 kHz, capture timestamps, startup/stop latency, reliable device release, hotplug and recovery. Include CPU/backpressure under recognition. Before selecting a capture backend, prove that the daemon can identify the listener’s own stream before the audio server first reports it active. For each candidate, including any capture helper, prepare an inactive client or stream with a stable server identity and verify its owning process and start identity. Bind that identity to the authenticated standalone listener lease, capture generation and current server generation. Enable recording only after registration is accepted and the grant is still valid. Reject a candidate that starts recording before attribution is established. Select the smallest candidate that can prove all required boundaries. Document required packages and diagnostics for the tested stack. If none qualifies, record the failed measurements and return the choice to the operator before adoption.

In the merged Phase 16 build script and launcher, trace actual model selection, token file and loopback validation. Extend the no-file entry in src/voice-listener/sherpa.ts with a live source. Preserve file recognition coverage including revision invalidation and bounded VAD scanning. Put live hardware lifecycle beside the listener and share decoder/hotword/word merge. Keep device and sample-clock information available to the desktop observer without persisting raw audio.

Keep device probes separate from recording. Report actual permission and device readings, including unknown, denied and selected input lost. Establish readiness without recording while muted. With an authorized current directive, stream bounded in-memory PCM through VAD, roster hotwords, decoding and word timings. Close the input and invalidate stale PCM and decoder work on mute, mode/revision changes, poll failure or lease loss. A wedged decoder must not delay closing the microphone. Apply the existing explicit held-release exception only to audio proven inside that physical key interval. Preserve the deployed protocol major, lease ID, revision, heartbeat and monotonic capture/start/onset/end headers as required by the merged routes. The file helper’s JSON-only directive reader needs access to release/draining headers for live input. Clip and decode again at key-up when required. Discard uncertain audio. Pass only utterances and timing metadata to the daemon. Keep raw samples, recognized text and tokens out of listener logs.

Before sending any directive poll, including the first, record its monotonic start and arm a bounded request deadline. For live Linux input, the daemon must make the directive’s actual authorization expiry knowable on the shared host monotonic clock, bounded by the lease and any earlier expiring prerequisite for that mode. Carry that bound as compatible response metadata if the merged protocol lacks it. The device owner takes the earlier of the request deadline and the authority’s absolute expiry, rechecking immediately before open and on every renewal. An absent, expired or unverifiable bound cannot authorize live capture. A late response gains no extra lifetime from its arrival. The existing 25-second long poll and 30-second lease are distinct limits. Only a fresh authorized directive within its remaining validity can renew capture. A hello heartbeat, queued decode or pending poll cannot extend the deadline. On expiry, close the physical input, discard buffered audio and retire the poll generation independently of request completion. Ignore all callbacks from retired generations. Reacquire only after a new poll under a valid lease explicitly authorizes capture.

Qualify the capture client’s process lifetime as part of backend selection. If capture runs out of process, abruptly kill the listener while the client owns a real input stream. Verify through OS process and audio-server observations that the client exits and releases the microphone. A backend qualifies in Phase 1 only if the standalone entry point independently cleans up after abrupt listener death, including a crash during helper launch. Implement and test that lifetime tie in this phase or reject the candidate. The standalone listener must never depend on a future daemon supervisor to release its microphone. Document the identity and ownership mechanism with the backend choice.

Isolate native recognition from the capture owner’s control loop. A worker or subprocess that blocks inside native decoding must leave the device owner able to process mute, revoke the lease and enforce its monotonic deadline. The owner drops results from invalidated generations even if the decoder eventually returns.

In Phase 1 the daemon applies the auto-mute observation gate before issuing any Linux live capture directive, independently of how the process was launched. With auto-mute enabled, missing, stale or pending microphone activity cannot authorize capture. Before the Phase 3 observer exists, the operator must explicitly disable auto-mute for the live-input spike. Preserve Phase 16’s finite recorded-input CI using its isolated fixture config. Phase 2 reuses this gate when it adds supervision.

Keep capture continuous during healthy renewal. Schedule the pending directive poll to return before the grant’s current absolute deadline with margin for transport and device scheduling, even when the mode and revision have not changed. Wake it when fresh prerequisite observations can extend authority. Re-evaluate lease, activity, mode, hold and all other prerequisites at issuance. A matching listener may atomically renew the same active capture generation before expiry without resetting its stream, VAD or buffered phrase. If no valid extension arrives in time, close as specified. Poll wakeups, repeated key-down snapshots and unchanged responses never manufacture authority or extend a physical hold deadline.

## Verification and merge criteria

Run `node --test --import ./test/setup-state.mjs --import tsx test/voice-listener-protocol.test.ts test/voice-word-merge.test.ts test/voice-utterances-http.test.ts` and new live-source tests with injected PCM, delayed decoding and revoked directives. Delay the very first capture-enabled response until after its absolute expiry and assert that the microphone never opens. Deliver another with only a short validity interval remaining and verify closure at its original deadline. Hold a directive request pending with the input open and keep hello heartbeats succeeding. Advance the clock through expiry and assert the input closes while the request is still pending. Deliver its late capture-enabled response and assert the device stays closed and stale samples never reach the daemon. A subsequent fresh authorized poll may reopen it. Repeat on the physical device with a stalled poll and observe closure from the audio server. Exercise the existing model-backed Linux recognizer job. For the standalone launch, start a second physical recorder before starting the daemon and listener with auto-mute enabled and no observer. Verify the first and subsequent live directives withhold capture and that only the other recorder owns an input stream. Explicitly disable auto-mute, verify eligible live input works, and re-enable it to verify closure. On hardware test first use, selected device loss, physical mute close/reopen, and a phrase cut by mute. Confirm OS capture state independently. Document candidate measurements, no raw recordings, and the chosen backend in docs/voice.md. No passing candidate means this phase stays open.

Run the repository typecheck and lint. Run build and smoke for runtime changes, the applicable unit suite, and browser E2E for visible changes. Use Node 24 or newer and the test-state preload. Keep hardware results and screenshots in PR/workflow evidence. Record measured limitations in the technical guide. Merge when the outcome works through the stated entry point and its failure cases pass.

On the reserved desktop, use an independent audio-server event trace and the standalone listener with auto-mute explicitly disabled. Delay registration for each candidate. Verify that its client stays inactive while a second recorder under the same user appears active. Accept registration, start input, and correlate the very first active event with the registered listener or helper while the other recorder remains distinguishable. Repeat after a server reconnect or recycled client ID, requiring fresh registration before activation. Record the identities and event order with the backend choice. This Phase 1 probe supplies evidence for the Phase 3 observer.

On the reserved desktop, restart the active PipeWire or PulseAudio server mid-phrase with the real selected input open. Verify that the listener closes the failed stream and discards its buffered PCM, in-flight decode and queued utterance. Keep capture closed while the server or selected device is absent and while a fresh capture directive is withheld. Restore the device and fresh authorization, speak a different phrase, and verify exactly one stream opens and only the new phrase is delivered. Record the audio server, device and observed recovery order.

On the real microphone path, deliberately block the native decode worker synchronously at a test barrier after it accepts a segment. Keep the worker blocked and mute from the dashboard. Observe the physical input stream disappear through the audio server before releasing the barrier. Repeat with directive renewal withheld through the lease deadline. A pending JavaScript promise alone does not exercise this failure. In both trials discard the delayed result and verify that only a fresh authorized phrase is delivered after recovery.

On the reserved desktop, run the Phase 1 renewal test with a real microphone and an isolated test daemon. Turn on auto-mute in that fixture and inject timestamped, reconciled idle observations at the daemon’s observation input. Keep injection confined to the test harness. Make the observation lifetime shorter than a normal long poll and speak one phrase across multiple refreshes. Verify each timely refresh wakes the poll, the same input stream stays open, and the complete phrase is delivered once. Withhold the next refresh and verify physical closure at the last observation’s deadline. The normal standalone spike still requires auto-mute explicitly disabled until Phase 3 supplies the observer.

## Downstream handoff and cross-phase audit

Later phases may start the live program without a WAV, select the verified model and identify the running input stream. Capture follows revision-aware directives; an independent reporter may observe the device without becoming its owner. No new persisted setting or route is required. Preserve compatibility for existing listeners while the Linux live source requires verifiable authorization expiry.
