Phase 1

Phase 1: Adopt and Surface the Task-Owned Pipeline Run

Implement one guarded lifecycle transition and carry its durable result to every host surface without changing process ownership.

Source phaseFull planPhased summary

End-user reproduction first

  1. Seed an existing halted Conductor run.
  2. Dispatch a managed Pipeline task whose intent reserves a different slug.
  3. Observe that the Engineer host has no Pipeline affordance while the worker appears separately.
  4. Process the existing run and observe that the mismatched task does not settle.
  5. Write the failing built Playwright journey before production changes.

Implementation sequence

1. Project task ownership

Add nullable TaskSummary.pipelineRun from the durable task row. Add no top-level Session field and no new comparator.

2. Define the MCP protocol

The agent supplies only slug. The bridge adds session evidence, cwd, and daemon-issued launch task identity.

3. Bind the host launch

Inject scoped task identity, verify the running MCP bundle publishes the tool, and append hidden adoption instructions while preserving visible intent.

4. Guard the transition

Validate caller, task, target projection, repository/provider, reservation absence, and ownership uniqueness. Persist through the lifecycle owner.

5. Surface the link

Add separate task-owned Console chip, Board flag, and rail mark. Keep the existing provider-worker chip unchanged.

6. Test and document

Pin success and refusals in unit and route tests, then prove the built browser journey at desktop and narrow widths.

Non-negotiable boundaries

  • No Session.pipeline on the host.
  • No composer regression.
  • No title, prompt, transcript, PR, or singleton inference.
  • No caller-selected task, repository, or provider.
  • No reassignment of an observed live reservation.
  • No duplicate active owner.
  • No completion from the MCP request.
  • No AI Conductor change or Terminal fallback.
  • No data-testid.
