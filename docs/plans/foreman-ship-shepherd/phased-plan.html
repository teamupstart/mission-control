Approved phased implementation

Foreman ship shepherd

Two merge units first correct the trusted completion boundary and persist its decision, then add a guarded pre-PR recovery loop with operator controls, audit, and escalation.

2 PHASES · 1,250–1,750 ESTIMATED PRODUCTION LINES

Approved product decisions

Coverage

Every invited task-owned ship session before its first task-owned pull request, for both Workflow and Straight-to-PR paths.

Reasoning

Structural recovery where durable state identifies the next step; one tool-less model call only for an ambiguous non-empty implementation.

Timing

A 20-minute initial quiet threshold, then three attempts at 20, 40, and 80 minute delays before human escalation.

Recorded by Mission Control review 2535938c-6519-4bfc-9051-3080328e1f7e. There are no unresolved product choices.

Why two phases

The timer is not the foundation. The current verifier can reject implementation as incomplete because the durable objective still asks for a pull request that Mission Control explicitly deferred. Recovery built on that verdict would repeat the contradiction. Completion truth and its durable reason must land first.

The estimated non-test change is 1,250 to 1,750 lines across shared contracts, SQLite, Workflow claim transactions, Foreman policy and worker orchestration, configuration, and React. One phase would combine two high-risk state machines. Three phases would split the UI from the live automation it controls or leave the targeted-model branch incomplete.

Cross-phase contracts

Phase 1 alone defines completion truth and outcome ids.
Phase 2 adds recovery state without rewriting the decision.
The daemon is the only SQLite writer and final claim authority.
The existing GitHub observer is the only PR reader.
Unknown injection outcomes remain claimed.
One Foreman instruction may reach a pane per worker pass.
Queue, Workflow, pending-turn, and human owners take precedence.
Any observed task-owned PR ends pre-PR shepherding.

Verification bar

Phase 1 proves the exact false-hold regression, atomic disposition storage, Workflow claim consistency, migration, and unchanged personal-session behavior. Phase 2 proves every eligibility gate and reason, exact 20/40/80 timing, model isolation, restart and delivery semantics, multi-repository PR suppression, UI configuration, and one-send coordination.

Both phases run focused tests, the full unit suite, typecheck, lint, build, and smoke. Phase 2 additionally runs the built Playwright Foreman flow with fake agents and no model spend.
