Mission Control · four layout mockups

Same fleet, same theme, same functionality - four different answers to "how should eight agent sessions be arranged on a screen". Each is clickable: select rows, open drawers, sort columns, walk the triage stack. All eight sessions are the same fixture data in every mockup, so the layouts are directly comparable.

Today: one responsive grid of session cards, sorted by tone (needs-you → working → idle → unconfirmed → gone). Click selects, a second click expands one card in place to reveal the Foreman note, work queue and transcript. Everything else - the goal, meta, runtime pills, review workflow strip, action bar - is always on the card.

01

Console

Split-pane master/detail. A dense rail of every session on the left, one always-open detail pane on the right. Nothing expands - selecting is expanding, and the conversation gets half the screen permanently. Detail splits into tabs: Conversation / Work queue / Gate / Diff.

+Transcript is first-class, not a click away +Whole fleet stays visible while you work one session −Only one session's detail at a time
closest to today's modelOpen → 02

Board

Kanban by state. The sort order that's invisible today becomes the layout: one column per state, so "how many need me" is answered by column height instead of by reading badges. Cards shrink to glanceable tiles; the full body moves to a slide-over drawer, so opening one never reflows the board.

+Fleet state readable from across the room +Opening a session never moves the others −Tiles cut goal to two lines; drawer hides the board
best for ambient monitoringOpen → 03

Ops table

Dense sortable grid. Every fact a card carries becomes a column, so you compare across sessions down a line rather than hunting the same chip in eight card positions. Sort by context pressure, gate state, or last-seen; a row expands in place into the full detail without leaving the table.

+Scales past 20 sessions without scrolling forever +Sorting answers questions the grid can't ("who's near context limit?") −Least glanceable; reads as a spreadsheet, not a fleet
best at scaleOpen → 04

Triage

Inbox-zero focus stack. The other three answer "what is the fleet doing". This one answers the only question you act on: what do I have to decide right now. One session fills the screen with its ask pulled out as the headline; answering advances to the next. Everything not asking for you drops to an ambient strip along the bottom.

+The decision is the interface - no hunting for it +Keyboard-only loop: read, answer, ↵, next −Poor for browsing; the fleet is peripheral by design
best for clearing a backlogOpen →

All existing functionality is present in each. Topbar: filter, session/need-you/working/reviews stats, Alerts, Foreman mode, Settings, Roundup + backlog badge, Dispatch, live indicator. Per session: agent dot, rename, name source, PR chip + CI-failure alert, state badge, pending reviews, Foreman decision/draft flag, goal line, path + branch, model / thinking / context meter, task chip, work queue, activity ticker, review workflow + gate buttons + findings, fix log with diff links, gated chip, permission-mode picker, pid, uninstrumented hint, last-seen, and the send / focus / diff / reset / kill actions with their shortcuts.
