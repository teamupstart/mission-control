The promise

Draw the transcript Mission Control already holds as a terminal stream, and say only what it recorded. No fabricated tool status, no exit codes, and no duration beyond a labelled span between two real timestamps.

Problem

A chat log is the wrong metaphor twice over.

An agent session is a process. The operator is watching a program work, and the facts they need while watching it - is it running, on which pid, on which branch, how much context is left - live on the card behind the panel, in a different visual language, and not in the reader's eye while they read. Meanwhile a long stretch of tool work renders as a column of chat rows that say nothing a shell would not have said in one line.

ALREADY HELD

TranscriptPanel receives the whole session, so pid, branch, state and context need no new prop.

ALREADY FOLDED

transcriptRows() folds runs of tool-only turns - the exact fold the mockup's disclosure record draws.

NOT RECORDED

ToolCall carries a name and a capped input. No status, no exit code, no duration.

Intended experience

One list of rows, two renderings of it.

Human turn

A prompt line: you@mission ~/repo ❯ text. The host part is the turn's real author, so a turn Foreman typed reads foreman@mission.

Agent turn

A stdout block under a <agent> / stdout speaker header with its timestamp. Markdown and find highlighting behave exactly as they do today.

Tool run

A closed disclosure - codex executed 3 commands · 1.8s - listing the full command or path per call when opened.

Frame

Window lights, mission-control: conversation · agent · shell, and an attach indicator driven by the transcript stream's own state.

Composer

A mission ❯ label and an enter sends hint around the same uncontrolled box, with the same draft, attachments and Enter behaviour.

Status line

Run state, pid, branch, context percentage, and a legend of the operator's own chords for terminal / diff / complete / kill.

Foreman episodes and answered reviews keep their existing cards. They are not transcript stdout and must not be dressed as it. Everything else the panel owns survives untouched in both renderings: the SSE stream and its reconnect, scrollback paging, pending turns, attachments and the drop veil, the find bar and rail, the observed-activity sideband, and the launcher strip.

Constraint

What the honesty contract rules out.

The sideband plan's rule applies here unchanged: the interface may say what the transcript recorded, and must not imply what it did not.

Where the mockup shows codex executed 3 commands · 1.8s, the honest reading is the span between the first and last turn in that folded run - arithmetic over two recorded timestamps. It is shown only when the run holds more than one turn and the span is positive, and it is labelled as the span it is. A one-turn run shows the count alone.

Not rendered

  • The mockup's done marker before each command - there is no result.
  • An exit code, a status, or an output size for any tool call.
  • A duration for a single tool call.
  • A shell name. The titlebar prints the session's tty, or its runtime.
Data and request flow

No server path changes.

The preference rides the existing UI-config route, and the rendering is a second projection of rows the panel already holds. Amber marks what this plan adds.

Choosing a rendering

One global default, one transient override.

SwitchWhere it livesScopeWhy that shape
Global default
conversationView		 UiConfigSchema + UI_CONFIG_DEFAULTS, uiCache.coerce(), a hook in src/web/lib/, a radio group in Settings → Display with a data-anchor, a SETTINGS_CONTROLS entry. Per machine, persisted by the daemon. No new route, no migration. An enum rather than a boolean, because the study produced three concepts and LAYOUT_MODES is the precedent for a named set of renderings validated in one place.
Per-session override A module-level Map keyed by session id, beside the hook, with a toggle in the conversation pane's launcher strip. The tab. Dropped on session_remove, gone on reload. There is no precedent for a persisted per-session UI preference and this plan does not create one. drafts.ts is the precedent for honestly transient per-session state.

Precedence is explicit and stated in one function: session override when set, global preference otherwise. A reload starts over from the global preference.

Both mounts

The frame has to survive the narrow card.

The terminal frame is a flex column inside .transcript, so it inherits the height contract the panel already gives the log and both hosts keep their max-height: none overrides. At the existing @container (max-width: 560px) breakpoint - which the expanded card crosses and the console detail does not - the frame drops the centred title, drops the enter sends hint and the context percentage, and wraps the status line rather than clipping it.

LOAD-BEARING

.transcript → .find-split → .find-logwrap → .transcript-log: min-height: 0 at every link, one scrolling surface.

ONE CONTAINER

.transcript carries container-type. A container query cannot style its own container - the reason #444 had to move it.

NEVER CLIPPED

The status line is flex: none and wraps. If the container pass leaves doubt, the Electron geometry test measures it.

Requirements

What has to be true.

  1. Render the approved mockup's five elements from data the transcript and session already carry: prompt lines, stdout blocks under a speaker header, folded disclosure records, a titlebar with a live attach indicator, and a status line with run state, pid, branch, context and the chord legend.
  2. Derive every rendering from the existing mergeConversation(transcriptRows(messages)) list, so find hits keep addressing the rows the reader can see.
  3. Make no claim the transcript does not carry: no tool status, no exit codes, and no duration beyond a labelled span between two recorded timestamps.
  4. Preserve the chat rendering as the default and preserve every behaviour of the panel in both renderings: stream and reconnect, scrollback paging, pending turns, attachments, find bar and rail, observed-activity sideband, launchers, Foreman and review rows.
  5. Add the global preference through the existing display-preference path only - schema, defaults, cache coercion, hook, settings control with data-anchor, search entry. No new route and no migration.
  6. Add the per-session override as transient tab-scoped state in a module-level keyed Map, collected on session_remove. Do not create a second settings store, and do not persist it.
  7. Resolve precedence in one place: session override when set, global preference otherwise.
  8. Keep both mounts working across the existing @container (max-width: 560px) breakpoint, with the status line visible and unclipped in the expanded card.
  9. Use roles, labels and placeholders for every new control; add no data-testid.
  10. Document the rendering and its two switches where Conversation behaviour is described.
Non-goals

What this is not.

  • Attaching to a real PTY, or streaming real process output. This renders the transcript Mission Control already has; the terminal is a reading, not a connection.
  • Replacing, restyling or retiring the chat rendering.
  • A third rendering. Concept 03 is out of scope, though the enum leaves room for it.
  • Persisting the per-session override, or adding any per-session settings store.
  • New server events, tables, routes, migrations, hook payloads or transcript parsing.
  • New action paths for terminal / diff / complete / kill. Those four already have one home each, and a second control path to kill is exactly what this repository forbids - so the status line teaches the chords rather than duplicating the buttons.
  • Changing the find, sideband, pending-turn, attachment or paging contracts.
Compatibility and privacy

One field, one shipped default.

No wire contract, persisted schema or harness protocol changes. UiConfigSchema gains one field with a shipped default, so an existing app_config.ui blob parses unchanged and an older blob reads as chat. A cache written by a newer build and read by an older one is already handled by coerce()'s field-by-field rule.

The terminal rendering shows nothing the chat rendering does not already show, with one deliberate difference: a folded run lists toolChip().title, the uncapped command or path, where the chat chip shows it in a tooltip. That string is already on screen today on hover and already governed by the same TOOL_INPUT_CAP, so this exposes no new input - it moves a hover into a disclosure the reader opens.

Verification strategy

Proven in a browser, not in a diff.

Unit

Row projection and the folded-run span; the config field in the store and cache tests; the settings control in the search and sidebar-render tests; override precedence in its own test.

Markup

renderToStaticMarkup pins the honest status line: no pid row when the session reports none, no context when unknown, attach indicator following the stream state.

Browser

A Playwright spec against fake agents: switch the global preference by PUT /api/ui/config and reload, assert the prompt line, the folded run and the status line, then assert the override wins. No model tokens.

Geometry

The Electron test, only if the container-query pass leaves doubt that the status line survives the narrow breakpoint unclipped.

Gates

typecheck, lint, unit tests, build, bundle smoke tests, and the Playwright suite.

Eyes

Both renderings compared against the mockup at console-detail and expanded-card widths, captured and attached to the pull request.

Acceptance criteria

Done means this.

With the preference set to Terminal, the Conversation reads as one terminal stream: a prompt line for what the operator typed, a stdout block for what the agent said, a folded record for a run of tool calls, a titlebar above and a status line below.
The status line carries this session's real run state, pid, branch and context, and says nothing when a fact is absent.
One session can be read as a terminal while the rest stay on the current view, and that choice disappears with the tab.
The default is unchanged, and every existing Conversation behaviour works identically in both renderings.
Both mounts render the frame without clipping the status line at their own widths.
Automated browser coverage proves the switch, the precedence and the rendering through the built dashboard.
