Mission Control · design options

ai-conductor pipeline stages on a session card

A correlated session card says one word about a 22-step feature today: ↸ add-widgets · Build. The step it names is the only one visible, so the card cannot answer how far along the run is, what already failed, or what got skipped - the three reads an operator scanning a board actually wants. Three compact treatments follow. Each replaces the chip's step half with a stage indicator, each fits the tile's existing rhythm, and in each one hovering a stage opens a popover with that stage's live status.

All three cost nothing on the wire. useEventStream already holds every run on the fleet as pipelineRuns, and PipelineRun.steps already carries all 22 step states. A card joins session.pipeline to that map on (provider, repoRoot, slug) and folds it with the existing pipelineStrip / pipelinePhaseStatus derivation. No SSE widening, no fetch, no new server work, and SessionPipelineLink stays exactly as it is.

Option A · Phase meter

one bar · +11px

A single hairline bar cut into five segments, one per phase. Segment width is proportional to how many steps that phase holds - so DECIDE's nine steps really are half the bar - and segment fill is how many of them are finished. The phase the run is in carries a ring. It reads like a progress bar that knows where its milestones are, which is the read a board scan wants: how far, and is anything red.

What hovering a stage opens

The honest cost. SETUP and UNDERSTAND hold one step each, so at proportional width they are 9px slivers - readable, but a small hover target, which is why min-width: 9px is set rather than left to flex. Proportional width is also what makes DECIDE dominate the bar; that is accurate, and it means the four steps after BUILD get less room than their importance suggests.

Option B · Step barcode

every step · +17px

One 4px tick per step - all twenty-two - with a wider gutter where a phase ends. Nothing is aggregated away: a single skipped step, a single stale one, and the exact position of the failure are all on the card. State is carried by colour and height, so the running tick and the failed tick are the two tall ones and the eye lands on them without reading a legend. Hover resolves to one step, not a phase.

What hovering a step opens

The honest cost. 22 ticks at 4px plus gutters is about 148px, which fits the 250px column but leaves the strip nowhere to go if a conductor release adds steps - unknown steps would have to append and the ticks narrow. A 4px hover target is also the smallest of the three, and it is the only option where the popover has 22 distinct contents to get right rather than 5.

Option C · Phase pips

no new height · +0px

Five 8px pips live on the chip the card already draws, between the slug and a single word naming where the run is. The card gets no taller than it is today - this replaces · Build with ●●◖○○ BUILD. State is a shape first: solid is done, half is partial, a ring with a core is running, hollow is untouched, dashed means this build does not know some of those steps. Hover a pip for that phase's status.

What hovering a pip opens

The honest cost. Five pips is the coarsest of the three: DECIDE's nine steps and SETUP's one get the same 8px circle, so the pips say which phase and not how far. A run that is two steps into DECIDE and one that is eight steps in both draw a running ring, and only the popover separates them. In exchange it is the only option that adds no height at all, and the only one that survives a repository whose config inserts custom steps without changing its own geometry.

What is common to all three, and is the real work. The app has exactly one hover primitive, Tooltip, and it takes label: string - no rich content. title= is banned outright and test/tooltip-coverage.test.ts scans for it. So the per-stage popover drawn above does not exist yet in any form, and every option needs the same decision made about it: teach Tooltip to take a node, or add a second hover primitive beside it. The plan puts that question up for decision rather than assuming it.
