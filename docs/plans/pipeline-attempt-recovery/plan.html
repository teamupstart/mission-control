  • Preserves immutable attempt history and requires explicit successor adoption.
  • Places failure classification and worktree retirement with the provider that owns them.
  • Requires a fresh host and a fenced daemon transaction for every retry.

Main gap: it misses current implementation facts and several concrete UI, Git fallback, credential, and delivery details.

Architecture

One identity spine, one workspace resolver, two evidence modes

The plan separates process location from task workspace authority. A provider worktree is interactive only while the daemon can revalidate it. After retirement, the same task remains inspectable through an immutable Git commit, but every mutating or host-opening action is disabled.

Recovery semantics

Failure, retry, and divergence become one guarded system

Two readiness gates

Mission Control performs a non-mutating provider probe before reservation. Authoring requires a current ready result or an explicitly permitted inconclusive result. Push authorization is checked again at handoff.

Atomic retry

A commission, attempt, provider run, revision, and host are fenced together. Existing idempotent create and inspect behavior handles response loss. The predecessor host exits only through Registry.beginEviction.

Explicit adoption

A direct unreserved successor is review-only until lineage, owner, replay, durable commit and provenance, repository, branch, PR, and competing-retry checks all pass. Adoption appends a distinct provider_reconciled attempt.

Acceptance

The plan is done when contradictions become impossible or explicit

  • Path and branch always describe the same provider attempt.
  • Retirement preserves pinned read-only Diff and Files evidence.
  • Concurrent validation cannot advance evidence after handoff freeze.
  • No missing workspace silently falls back to host cwd.
  • Known readiness blockers stop before model-backed authoring.
  • Commission failure raises needs you even when the host is idle.
  • Engineer progress reaches 100 percent at Engineer handoff.
  • Concurrent retries create at most one attempt and one new host.
  • Response loss recovers exact identity or remains durably unknown.
  • Attempt 1 remains immutable after retry or adoption.
  • External work cannot affect the active attempt before explicit adoption.
  • Adoption matches durable commit and provenance across candidate, replay, and adapter.
  • Task and commission contradictions become named status drift.
  • No caller credential appears in process arguments.
