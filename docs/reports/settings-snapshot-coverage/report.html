Mission Control investigation

Trust is backed up, but its coverage contract named the wrong source

The runtime snapshot already serializes and restores every supported Trust value. The gap was in the control-level inventory: Trust declared the unrelated Pipelines domain and omitted the UI domain that owns ungranted staged rows. That made the coverage check incomplete and left the user-visible restore behavior untested.

Verified and fixed

No supported persisted setting is missing from format v1.

The typed registry automatically includes every field classified as a setting and refuses unregistered config ownership.

Why the bug escaped

The runtime path was complete. The separate searchable-control declaration incorrectly mapped Trust to pipelines and omitted ui. The old generic coverage test could prove that every named domain existed, but not that this composite control named the right domains. The corrected declaration is at src/web/lib/settings-search.ts:802-810.

Full settings inventory

Verified configuration domains are ui, harnesses, worktrees, skills, cost, foreman, foreman-instructions, workflow-policy, task-sources, models, standing-instructions, inspector, shipping, pipelines, repo-index, and runtime domain away. Reusable Library domains are personas, session-actions, workflow-commands, workflow-definitions, and workflow-versions.

The stable domain registry is the source of this inventory: src/shared/settings-backup-domains.ts:7-30. The config registry is exhaustive by field and drives capture directly: src/shared/app-config-entries.ts:258-309.

Intentionally not restored

  • Operational: current away state and timestamp, Foreman lease, setup-banner dismissal, and cost telemetry last-seen watermark.
  • Derived: Skills reload generations, generated backlog plan, and cost telemetry enablement watermark.
  • Work state: tasks, sessions, queues, schedules, worktrees, bindings, runs, reviews, usage, archives, leases, projections, and ledgers.
  • Machine authority: credentials, tokens, environment secrets, and built-in catalogs supplied by the installed build.
  • Navigation state: last-open repository and workflow selection remain browser navigation context, not Settings controls.

These boundaries match the documented snapshot contract at docs/configuration.md:191-218.

Implemented safeguards

  • Corrected Trust backup metadata from pipelines to ui.
  • Added a focused contract test that pins all five persisted Trust sources: test/settings-backup-coverage.test.ts:198-207.
  • Extended the built-dashboard restore scenario to capture distinct Trust values, mutate them, restore the snapshot, assert all five daemon values, and inspect the rendered matrix: e2e/specs/settings-backup-restore.spec.ts:102-321.

Evidence and limits

Verified on 2026-08-29 from repository source, the focused unit contract, TypeScript, lint, a production build, and the focused Chromium restore scenario. The browser scenario passed with all four grant cells on and the staged repository row present with all cells off. This audit covers supported application persistence paths. A future developer could still bypass the typed registry with raw SQLite code, but that would be outside the documented settings ownership contract and existing code style.
