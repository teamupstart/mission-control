Mission Control product plan

Foreman ship shepherd

Keep managed ship sessions moving from implementation through the first pull request, with a correct completion boundary, durable recovery reason, bounded retries, and visible escalation.

APPROVED · 21 AUGUST 2026

Goal

Keep task-owned ship sessions moving from implementation through the first task-owned pull request without relying on a human to notice that an idle session has stopped progressing.

Foreman distinguishes a healthy pause from a stranded handoff, explains what it believes is missing, and re-engages the session with one bounded next action. It never interrupts active work, races a Workflow, creates duplicate pull requests, or turns an uninvited personal session into managed work.

Why a timer alone is insufficient

The known incident would loop. The implementation agent was correctly told to stop before commit and PR, but the generic completion verifier judged an objective that still required the PR. A generic nudge would create another work cycle and let the same contradiction reject it again.

The feature therefore has two inseparable parts: define implementation-complete independently from Mission Control's deferred shipping work, then add a durable watchdog for genuine pre-PR stalls.

Foundation to reuse

LifecycleWork-cycle generations

Durable active and completed state across terminal and SDK runtimes.

DetectionIdle + work open

The existing stall policy already treats 20 minutes as unfinished-work silence.

ExecutionFleet-level Foreman passes

PR follow-through already proves fresh rechecks, pane claims, and one send per pass.

Proposed behavior

1. Trusted task completion contract

For a dispatched ship task, the initial boundary requires the implementation, required documentation, focused tests, and evidence registration. Commit, push, pull request, review, and CI are deferred. The verifier receives this as trusted policy beside the durable objective. The Workflow binding decides the next owner, not the meaning of implementation-complete.

2. Durable completion and recovery projection

The prompted queue projection stores the current generation's outcome, bounded verifier summary and gaps, decision time, recovery marker, attempt count, and next eligible time. The daemon remains the only writer. Foreman episodes remain the historical audit.

3. Fleet-level pre-PR pass

A new pass considers only invited, trusted, hook-instrumented task sessions of kind ship that are settled idle beyond the selected threshold, still have open work, have no task-owned open PR, and are not owned by a queue, pending turn, human ask, or non-terminal Workflow run.

4. State-specific action

StateShepherd action
Held with gapsSend the bounded verifier gaps as the next implementation turn.
Idle, non-empty diff, no decisionUse one tool-less recovery review to draft a bounded next implementation step or escalate.
Idle, empty diffTell the session to re-read the durable objective and begin or resume implementation.
Direct handoff, no PRRe-send an idempotent same-branch shipping continuation that first checks for an existing PR.
Retryable claim or captureDo not type. Existing completion and Workflow retry machinery owns it.
Active or parked WorkflowDo not type. Workflow resumption and parked-run handling own it.
Human decision pendingPreserve or escalate the ask. Never answer it as recovery.

5. Bounded repetition

Claims are compare-and-set against task id, logical key, work-cycle generation, reason, and attempt. New activity cancels the quiet period. Unknown injection outcomes remain claimed. Exhaustion becomes a visible human escalation with the last verdict and recovery history.

Data and request flow

Configuration and visibility

  • keepShipTasksMoving grants pre-PR recovery.
  • shipRecoveryMinutes controls silence before the first attempt.
  • A topbar checkbox says “Keep pre-PR ship tasks moving.” The threshold lives in Settings > Foreman.
  • Recovery decisions use the existing session drawer and fleet ledger. There is no second dashboard.

Safety invariants

  • Invited task sessions only, in Live mode and trusted repositories.
  • No interruption of active, starting, awaiting-input, queue-owned, Workflow-owned, or human-owned work.
  • No second PR poller and no database access from the Foreman worker.
  • No retry after an unknown injection outcome.
  • No recovery-model authority to commit, push, merge, delete, or cross repository boundaries.
  • At most one Foreman instruction per session per pass.

Verification and documentation

Unit tests pin every gate, reason precedence, timing boundary, attempt transition, and multi-repository PR check. Persistence and route tests cover migration, compare-and-set claims, restarts, rebinding, terminal tasks, and uncertain delivery. Worker integration reproduces the exact PR-deferred completion incident and every recovery arm. UI changes extend an existing Foreman configuration Playwright spec.

Update Foreman, work-queue, attention, architecture, and change-contract documentation in the same change.

Non-goals

  • General supervision of scout, plan, pipeline, or chat sessions.
  • Uninvited personal sessions.
  • Replacing Workflow resumption, parked-run alerts, PR follow-through, or backlog autopilot.
  • Automatic merge.
  • Inferring missing secondary PRs after the first task-owned PR exists.
  • Transcript polling as a replacement for normalized work-cycle state.

Approved decisions

Scope

Every invited task-owned ship session before its first task-owned PR, for both Workflow and Straight-to-PR completion. Other task kinds remain outside v1.

Recovery reasoning

Structural recovery when the state explains the stall; one tool-less model call only for ambiguous idle implementation.

Timing

A dedicated 20-minute Foreman threshold, independent from Away settings.

Retry budget

Three attempts at 20, 40, and 80 minute delays, then human escalation.

Implementation follow-up

Create a merge-aware phased implementation plan and dependency-linked Mission Control tasks.
