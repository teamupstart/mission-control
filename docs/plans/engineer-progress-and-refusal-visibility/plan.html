Engineer Progress and Refusal Visibility

Status: Approved for phased implementation · Requested: 2026-08-31 · Repositories: Mission Control and AI Conductor

Make approved DECIDE work advance the Pipeline meter live, prevent the reproduced feature-stem refusal when the canonical workflow is followed, and show any remaining recoverable refusal as blocked instead of ordinary authoring.

Outcome

When a managed Codex Pipeline Engineer authors and the operator approves DECIDE artifacts, the Pipeline meter advances during the work instead of remaining on an earlier stage. If Engineer later refuses to land the artifact set, every Mission Control surface that shows the commission makes that blocked state and its exact reason visible.

Reproduced failure

  1. AI Conductor recorded run creation, start, repository routing, and worktree creation. The host then authored an approved PRD, stories, and plan, but the provider journal received no step start, completion, or skip events. Mission Control had no provider-owned progress to project.
  2. land refused because the PRD, stories, and plan used hello-endpoint rather than the exact worktree-reserved stem. Mission Control retained the refusal reason, but the Board meter still said Engineer authoring.

This was not an approval-ingest delay. The approved files existed on disk while the lifecycle journal remained unchanged.

Ownership decisions

AI Conductor owns truth

Engineer step events, accepted completion evidence, feature artifact identity, land reconciliation, and refusal reasons remain provider-owned.

Mission Control owns projection

Mission Control consumes provider events and presents commission state. It does not inspect artifacts, infer approval from transcript text, or emit lifecycle events.

One authoritative identity

The slug and engineerRunId returned by engineer worktree govern the rest of the authoring run.

Evidence-backed completion

Tool return is insufficient. Completion comes from an accepted workflow result, deterministic artifact validation, or land reconciliation.

Target flow

AI Conductor changes

  • Capture exact engineerRunId, slug, branch, and worktreePath from worktree creation.
  • Use validated run-record transitions around applicable authoring steps for Codex and other no-hook hosts.
  • Use accepted-result or artifact-validation completion evidence, with explicit skips, failures, and retries.
  • Name feature-scoped artifacts from the returned slug and audit names before land.
  • Keep the authoring worktree on refusal and repair the same run in place.
  • Pin the contract in provider skill tests and maintained lifecycle documentation.

Mission Control changes

Keep the provider integration and persisted schema unchanged. Harden the shared commission view so a failed current step or land refusal visibly halts the synthetic meter, carries the exact reason through the existing accessible control, stays nonterminal, and returns to running after a provider retry or later successful event.

Do not add run-record commands to the Mission Control launch prompt. That would duplicate the provider skill's workflow contract.

Acceptance criteria

  1. Codex-hosted authoring emits live evidence-backed start, completion, skip, failure, and retry transitions.
  2. An approved PRD advances the meter before land.
  3. Feature artifacts use the exact returned slug, preventing the reproduced naming refusal.
  4. Land keeps its independent deterministic validation.
  5. A land refusal or failed current step is visibly blocked on Board, Console, and Runs with an accessible exact reason.
  6. A retry remains running and later provider progress clears stale refusal presentation.
  7. Mission Control never infers step completion or writes provider state.
  8. Existing Claude, direct Engineer, BUILD/SHIP, replay, and uncommissioned flows remain compatible.

Non-goals

  • No wire-schema redesign or approval inference from files and conversation text.
  • No automatic repair of an existing artifact set.
  • No automatic spec merge or implementation-run change.
  • No reopening of completed continuity phases.

Verification strategy

AI Conductor

Mutation-resistant skill contract checks, existing lifecycle and land tests, then required typecheck, lint, test, and build gates.

Mission Control

Reducer and view-model tests plus a built-dashboard Playwright reproduction with fake agents, keyboard assertions, geometry review, screenshots, and focused transcript evidence.
