Investigated findings

  1. One normalized contract: Claude, Codex, and Pi all produce TranscriptMessage; provider-native file mutation is unnecessary.
  2. Two launch facts: the dispatcher holds both the full composed prompt and original Task.intent. Pi fingerprints its final memory-pointer-prefixed text.
  3. Different timing: terminal launch can stage before injection; SDK marker state must be durable before registration and its event pump.
  4. Existing identity lifecycle: noteKeyFor moves from provisional to native identity. Launch state moves only on that initial bind, never across /clear.
  5. Existing overlay: transcript attribution already adds non-destructive metadata after native parsing.
  6. Several browser consumers: Chat, Native, find, and Yours must share one projected message array.
  7. Byte-based paging: browser history and SSE offsets remain based on unprojected native transcript bytes.
  8. Existing E2E seam: dispatch-and-converse.spec.ts covers the real dashboard-to-fake-agent round trip without model spend.
  9. Pipeline split: the SDK arm launches a streamable agent conversation and is covered. The terminal arm launches the Conductor host with no agent conversation or transcript turn to mark.

Design reconciliation

Store a fingerprint of the complete normalized launch text plus its human display projection. Preserve the native message id, role, timestamp, and tools when substituting visible text.

Do not use origin: "harness". Origin is authorship; launch presentation is a display projection of one accepted human request plus platform context.

Sizing and phase count

Estimated non-test production change: 190-270 lines, excluding documentation and tests.

Create one phase and one one-shot implementation task. The estimate straddles 200 lines, but splitting the vertical slice would merge dead metadata or a wire consumer with no producer. One pull request is the smallest operable and reviewable unit.

Concurrency and merge order

There is one phase, so there are no concurrent groups or inter-phase edges. Its task depends directly on this planning session and stays backlogged until the artifact pull request merges.

Cross-phase contracts

  • Native transcripts and agent delivery remain unchanged.
  • Only fresh Mission Control-managed launches receive presentation metadata.
  • The marker survives restart and initial binding, but not /clear.
  • All server evidence readers retain the complete prompt.
  • Chat, Native, find, and Yours share one identity-preserving projection.
  • Unmarked messages retain current behavior.
  • Transcript paging and reconnect remain byte-based on native text.

Final verification strategy

  • Failing-first Playwright reproduction through real dashboard dispatch and the fake SDK agent.
  • Persistence, identity movement, dispatcher, supervisor, attribution, projection, find, and Yours tests.
  • Manual, assigned, resumed, cleared, and historical compatibility cases.
  • Provider-boundary evidence proving the full composed prompt was accepted.
  • Typecheck, lint, focused tests, build, smoke, focused Playwright, and repository-required broader suites.
