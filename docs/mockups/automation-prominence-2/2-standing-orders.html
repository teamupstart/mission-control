2/3Standing Orders: the rules you have delegated

The reframe: automation is not a set of pages, it is a set of promises the operator has made to the machinery. One surface lists every rule Mission Control may act on without you, written as a full sentence - trigger, procedure, outcome. Workflows, Personas and Actions become the vocabulary inside the sentences; runs and ensemble decisions become each order's execution ledger, attached to the rule that caused them. Nothing is hidden, because everything the app will ever do on its own is on this one page, in plain language, with a pause switch.

The vocabulary the sentences use ⌁ Workflows 2 · edit ❝ Personas 6 · edit ▤ Actions 3 · edit ⧉ Strategies 3 Authoring lives one click behind the words themselves.
01The sentence IS the purpose. Nobody needs a tooltip explaining what a workflow is for when it only ever appears mid-sentence between its trigger and its outcome. The noun survives as a chip; the meaning is the grammar around it.
02Runs re-homed as ledgers. A run is the receipt of a promise kept. Attaching execution history to the order that caused it answers "why did this run happen" for free - the global Runs tab becomes a per-order filter.
03Trust is the organizing axis. The page doubles as the app's consent surface: every order has a pause switch, and the paused state is as legible as the active one. Prominence and blast-radius control become the same feature.
04Cost: the biggest conceptual lift of the three. Orders must unify four existing mechanisms (schedules, task sources, binding trigger modes, dispatch defaults) behind one abstraction, and manual one-off launches still need a home outside it. An order model that is only a view over those systems risks lying; one that replaces them is a real migration.
