Lifecycle consumption and unified presentation

Mission Control | Direct prerequisite: Phase 3

Run non-mutating provider preflight before database CAS reservation, then add restart-safe recovery, Registry-owned old-host eviction, fresh-host retry, and exact adoption with owner, replay, durable-commit, and provenance validation before explicit task settlement.

Why four

Every boundary reduces a different implementation risk

BoundaryReason not to combine
Phase 1 vs 2They are independently operable in different repositories. Combining them would widen review and remove safe parallelism.
Phase 2 vs 3Current Mission Control safely retains unknown provider events, so provider-first delivery is a clean compatibility gate.
Phase 3 vs 4Projection and UI migration are broad; retry and adoption are concurrency-sensitive. Separate state-machine reviews are safer.
Inside Phase 1Splitting schema, Diff, Files, workflow, or credentials would leave contradictory or dead intermediate surfaces.

Cross-phase contracts

Authority stays in one place at every layer

Workspace

  • Session.cwd remains process identity.
  • Only revalidated live worktrees authorize mutation.
  • Evidence initializes by null-and-unfrozen CAS, later advances by predecessor-and-freeze CAS, and freezes atomically with handoff.
  • Retired or missing worktrees use a durable attempt commit and never follow a moved branch.
  • No consumer falls back to host cwd.

Provider

  • One additive Engineer event spine.
  • Authoring requires current ready or explicitly permitted inconclusive readiness.
  • Logical retirement is the sole metadata-only post-terminal event and never changes terminal outcome.
  • Current attempt ordering and replay remain intact.
  • Owned correlations reject accidental owner loss.

Recovery

  • Retries and adoptions append immutable attempts.
  • Database CAS fences identity before external calls.
  • Adoption requires exact owner continuity or recorded transfer plus matching commit and provenance across candidate, replay, and adapter.
  • Response loss uses exact inspect before another create.
  • Old hosts leave through Registry eviction.

Settlement

  • Provider lifecycle governs commission state.
  • Branch and PR facts validate but never rewrite it.
  • SDK idle is secondary evidence.
  • Spec handoff does not mean implementation complete.

Compatibility audit

The graph is merge-safe

  • Phases 1 and 2 touch different repositories and may merge in either order.
  • Current Mission Control retains unknown v1 provider kinds and preserves raw error on extended known failures.
  • Phase 3 distinguishes provider-confirmed retirement from filesystem-observed missing state and reconciles the provider commit without changing authorization.
  • Phase 4 inserts an attempt before replay, so existing ingest identity checks stay authoritative and partial replay can resume.
  • No phase depends on later cleanup to restore an operable repository.
