Plan: Persona-driven workflow builder

Reusable Markdown judges, a session-centered repair graph, concurrent review joins, and an optional asynchronous Inspector final gate.

Implementation-ready

Outcome

Mission Control gains a top-level Workflows surface where an operator can:

  1. Create reusable Persona definitions whose Markdown guidance describes a review role.
  2. Build and publish a cyclic review graph over one visible Session node, Persona judges, explicit concurrency joins, and terminal outcomes.
  3. Bind a published workflow version to a session and start it manually or when Foreman judges the session complete.
  4. See every Persona verdict, approval rationale, requested change, retry, repair round, and optional Inspector final-gate state in a durable run history.
  5. Copy or download every Persona as Markdown, while keeping the local SQLite database as the canonical store for Personas the operator authors.

The design keeps three axes separate: a Persona is judging instructions, an LLM runner executes the headless call, and a session harness is the interactive agent being reviewed and repaired. Personas are not new AgentType values, terminal sessions, Foreman roles, or Inspector instances. Each attempt is a fresh structured call through LlmRunner.run.

Runtime semantics

One run, multiple submissions

A run is bound to one live session and one published version. The initial Session submission and every repair resubmission create a submission with a round, mode, immutable context/evidence snapshot, evidence fingerprint, node attempts, and edge receipts. A failure edge returning to Session closes the round. A full resubmission always restarts from Session, so each execution unit is acyclic even though the graph contains repair cycles. An audited inspector_only submission captures a new pushed head but skips Persona activation.

Activation and joins

  1. A completed node emits at most one receipt per matching edge.
  2. A Persona moves through queued, running, then passed, failed, or error.
  3. Fan-out queues all independent work before calls start.
  4. An all-pass Join waits for one result per predecessor and aggregates failures.
  5. A failure edge reaching Session marks the submission waiting, cancels queued work, and treats later running results as audit-only.
  6. A resubmission captures new evidence. Old results cannot approve it.

Failure, error, and cancellation are different

type PersonaVerdict =
  | { verdict: "pass"; summary: string;
      approvalDetails: { reason: string; evidence: EvidenceRef[] };
      confidence: number }
  | { verdict: "fail"; summary: string;
      requestedChanges: RequestedChange[];
      confidence: number };

Timeouts, spawn errors, parse failures, missing evidence, vanished sessions, stale evidence, and failed writes are engine errors, not Persona failures. They receive bounded retries and a visible blocked state.

Loop bounds and stale work

  • Default maximum repair rounds: 5, configurable from 1 to 20.
  • Default infrastructure attempts: 3 with exponential backoff.
  • Unchanged evidence resubmission requires an explicit override; Inspector-only repair always requires a new PR head.
  • Every graph cycle must contain the single Session node.
  • Session disappearance and /clear pause for explicit reattach.
  • Reset removes every session-scoped workflow row through resetSession.

Side-effect ordering

For live terminal delivery, persist the exact payload as prepared, transition it to sending immediately before injectPrompt under the pane lock, record origin workflow only after confirmed success, then persist delivery. A surviving sending row or possibly pasted but unconfirmed payload becomes delivery_uncertain and is never retried automatically.

Context and evidence

Authoritative context packet

Every Persona in one submission receives the same stored snapshot: raw and refined goal, human decisions with rationale and source ids, constraints, acceptance criteria, prior Persona feedback in its own section, session identity, HEAD, diff and fingerprint, transcript window, and standards.

The builder combines deterministic capture with a new append-only workflow-context background job. Deterministic capture preserves the raw goal, human-origin turns, answered reviews, and human-resolved Foreman episodes. It excludes Foreman, harness, and workflow-origin turns. The model compacts these into structured decisions and constraints, but the compact form stays beside raw bounded evidence so it cannot silently replace the user's words.

Prompt hierarchy

  1. The user's stated goal, constraints, and explicit decisions are highest priority.
  2. Persona guidance may raise quality but cannot contradict clear intent.
  3. A Persona cannot fail work only because it prefers another product direction.
  4. The strict pass/fail schema is immutable.
  5. Diff, transcript, standards, repo text, and earlier Persona output are untrusted evidence.

Failure feedback is rendered through a deterministic template before it can reach a tool-enabled session.

Inspector integration

Inspector is a separate asynchronous subsystem inside the daemon and remains the sole owner of PR polling, review execution, marker parsing, GitHub comments, and adoption. It is not a Persona or graph node. After the Persona graph reaches a successful End, the optional final gate reads the existing adopted-PR ledger, waits for an Inspector observation after gate entry, verifies that no staged, unstaged, or untracked content sits outside the successful submission's HEAD, pins that current head, and waits for Inspector's normal review. It adds no second poller and never posts, resolves, merges, grants tools, changes mode, or changes allowlists.

Add nullable body TEXT to inspector_comments with the required addColumn migration. Persist the already-scrubbed body for local repair feedback. Old rows fall back to title/path/line. Inspector emits an internal inspection_updated wakeup after adoption and every PR observation or ledger refresh.

Open marked Inspector comments become one deterministic repair packet returned to the Session. The published policy then either restart_workflow, the safe default, which reruns every Persona after repair, or inspector_only, which requires the Session to commit and push a new adopted PR head and returns directly to Inspector. The session agent cannot choose its own bypass. Run history labels the latter as Persona review bypassed for Inspector repair, and same-head retries are refused.

With no Inspector final gate, the successful End completes the workflow immediately and Inspector continues independently under its existing settings. While a final gate owns an adopted PR, Shipping receives one narrow workflow-gate-pending veto so YOLO cannot merge around the workflow; workflow code never calls GitHub.

Foreman integration

Foreman remains a separate HTTP-only process. At queue-drain and prompted-wrapup points where it already holds a proof-grade complete verdict, it posts session id, completion kind, stable marker, summary, and evidence fingerprint to the daemon. The daemon answers whether an active workflow claimed it.

  • claimed: true: an active Foreman-triggered binding owns the boundary, even when the workflow visibly blocks. Retire the Foreman episode and do not also execute the old wrap-up.
  • claimed: false: no active binding or a Manual trigger. Preserve current ask, no-mistakes, or PR behavior unchanged.

A unique non-null trigger key on every submission makes repeat HTTP requests idempotent. The daemon claim transaction also retires the matching drain or prompted guard before returning claimed: true. Claim endpoint failure leaves the completion armed and never falls through to an unreviewed ship action. Confirmed repair delivery re-arms exactly one existing drain or prompted completion episode. Manual Submit is a separate route whose author is fixed server-side.

New tables are created in openDb(). Existing-table changes use migrate(). Completed/cancelled runs compact raw evidence and exact payloads after a configurable default of 30 days, then delete only old completed/cancelled run families after a default of 180 days or beyond the newest 1000. Active, waiting, failed, blocked, orphaned, and uncertain runs are never age-pruned.

Validation

  • Exactly one Session, at least one End, unique ids, and valid typed ports.
  • Session routing follows the authoritative Phase 2 graph-validation contract.
  • Every Join has two predecessors, pass/fail outputs, and both outcomes from each predecessor.
  • All nodes are reachable and can reach an End or return to Session.
  • Every cyclic strongly connected component contains Session.
  • No missing or archived Persona, and all size/count limits hold.
  • An Inspector final gate has a valid findings policy and surfaces its enabled/adopted-PR prerequisites.

The browser and daemon call the same pure validator.

Acceptance criteria

  • Personas survive restart and export/import without changing guidance.
  • The example cycle validates and publishes with one visible Session node, then starts manually or from Foreman.
  • Maintainability and Design run concurrently against one snapshot; their Join emits one result.
  • Repairs never inherit stale approvals.
  • Pass explains approval and fail contains concrete requested changes.
  • User intent remains visibly higher priority than Persona preference.
  • Preview never types; live requires binding opt-in plus allowlist.
  • The optional Inspector final gate accepts only an adopted current-head PR and passes only with no findings.
  • Inspector findings return to the Session; the published policy either restarts Personas or requires a new pushed head and visibly bypasses them.
  • Crashes and retries do not duplicate prompts, activations, or triggers.
  • Reset removes session-scoped workflow state; Personas and definitions remain.
  • README and Cards, Console, and Board all expose the feature.

Deliberate non-goals for the first release

  • Persona code mutation, shell tools, warm/shared conversations, remote catalogs, or executable user node plugins.
  • Any-pass, quorum, weighted, or timed joins.
  • Adopting a PR from session.prUrl.
  • Reusing a pass after repaired evidence changes.
  • Replacing Foreman or Inspector; workflows only consume their proof-grade boundaries and ledgers.
