# Voice addressing on Linux

On a Linux desktop, the operator can address an agent while another app has focus, see confirmation in the browser, and hear a reply when a local voice is ready. The daemon owns the listener. Closing or opening a dashboard tab neither starts a second listener nor changes which process holds the microphone.

## Decisions and entry gate

- **Distribution.** The operator selected “Ship the daemon and browser experience”. The daemon and browser run on the same machine, in the operator’s graphical user session. Linux desktop app packaging, tray and floating windows are outside this fast follow.
- **Wayland.** “Ship where the portal proves both press and release”. The operator subsequently chose “Retain the event-based support bar”. Named desktops qualify with tested press and release events, physical event-time mapping, a bounded hold and release-time clipping. Delayed activation can briefly open the microphone after physical release while deactivation is queued. The operator accepted that limitation, including on portals without an independent current-down query. An absent, denied or insufficient portal leaves the hotkey unavailable there. Other verified capabilities remain usable.
- **Microphone.** “Choose after a real-desktop capture spike”. Keep the capture package undecided until it passes the physical tests below.
- **Timing.** “Secure a desktop before implementation begins”. This gates all implementation, including supervision and the spike.
- **Owner.** “I’ll arrange the desktop and tester”. Obtain the operator’s explicit confirmation of access, a working physical microphone and audible output, a willing tester, the session types and available test times. Record distribution, architecture, audio server and desktop versions with results. Planning approval or a backlog dependency clearing does not confirm access.

The operator selected “Create phased implementation plan” and approved the root plan in revision 1. The implementation graph is in `phased-plan.md`.

## Runtime and capture

**Flow.** Desktop key and microphone-activity adapters feed the daemon’s shell-report state. The daemon starts one sherpa listener and issues capture or speech directives. The listener exchanges audio with the local desktop, posts utterances and speech events to the daemon, and the daemon publishes voice state and cards to browser tabs.

Bind the Linux supervisor to daemon startup, feature/config/model changes and shutdown, using the existing voice preview and required flags. Acquire daemon state ownership before reconciliation. Use the actual bound local endpoint and protected token file. Reuse the verified backend selection, including explicit overrides. A missing model, unsupported selection, missing graphical session or inaccessible audio service gets a specific Setup reading. Avoid launching a file fixture or repeatedly launching a known-broken child. Keep the daemon and keyboard-only dashboard operable. Start at most one live child for the selected model, serialize reconciles and teardown, bound crash retries with backoff, cancel pending launches when settings change, and release device/session resources on flag-off, logout and shutdown. Speech holds survive those transitions. A user service without the desktop’s session bus, display or audio endpoint reports which connection is missing.

Compare an installed PipeWire or PulseAudio client against a directly integrated audio library on the operator’s desktop. Measure dependency availability, device enumeration and stable IDs, default and selected input, format conversion to mono 16 kHz, capture timestamps, startup/stop latency, reliable device release, hotplug and recovery. Include CPU/backpressure under recognition. Select the smallest candidate that can prove all required boundaries. Document required packages and diagnostics for the tested stack. If none qualifies, record the failed measurements and return the choice to the operator before adoption.

Keep device probes separate from recording. Report actual permission and device readings, including unknown, denied and selected input lost. Establish readiness without recording while muted. With an authorized current directive, stream bounded in-memory PCM through VAD, roster hotwords, decoding and word timings. Close the input and invalidate stale PCM and decoder work on mute, mode/revision changes, poll failure or lease loss. A wedged decoder must not delay closing the microphone. Apply the existing explicit held-release exception only to audio proven inside that physical key interval. Preserve the deployed protocol major, lease ID, revision, heartbeat and monotonic capture/start/onset/end headers as required by the merged routes. The file helper’s JSON-only directive reader needs access to release/draining headers for live input. Clip and decode again at key-up when required. Discard uncertain audio. Pass only utterances and timing metadata to the daemon. Keep raw samples, recognized text and tokens out of listener logs.

## Mute and microphone activity

Use one Linux producer of complete contract B snapshots so an idle hotkey heartbeat cannot overwrite call detection. Send transitions promptly and refresh within the 15-second report lifetime. When auto-mute is enabled, an expired audio observation gates capture while a fresh baseline is collected, including when the transport and hotkey heartbeats remain live. Use the existing config, mute operation, voiceMode precedence, registeredHotkey, hotkeyError, callActive and pushToTalk. Order observation and physical key edges on the Linux CLOCK_MONOTONIC microsecond timebase. Retain the last release stamp across heartbeats. A missing release, disconnect, session lock, rebind or stale report clears a held state and discards an unprovable tail. Keep explicit mute authoritative.

On X11, passively grab only the configured chord in the user’s X session. Handle press/release, modifier variants, auto-repeat, layout changes and conflicting grabs. Release old registrations on disable or exit. Apply the shared tap/hold behavior: tap within 350 ms toggles mute once, a longer hold talks through call auto-mute only while held. Preserve the old chord on failed replacement where it remains registered, otherwise report no chord in force. Reflect the actual binding. When speech is active, honor the Speech 1 hotkey stop behavior.

On Wayland, exercise GlobalShortcuts CreateSession, BindShortcuts, consent, returned bindings, Activated, Deactivated, changes, revocation and session loss from the unpackaged daemon. Verify desktop identity and consent presentation without a native parent window. The portal may choose a different trigger and specifies milliseconds with an undefined base. Establish a defensible mapping of physical event time to the audio clock, including delayed delivery, or withhold the capability. Verify equivalent time conversion and wraparound for X11 event times. A callback receipt timestamp cannot establish an earlier physical release. Offer the keycap only for a current confirmed matching chord. Never use an XWayland grab as proof of global Wayland support. Use one authoritative observer per session with a baseline snapshot, change subscription and rescan on reconnection. ## Spoken replies and crash recovery

Any implementation phase adding Linux playback has two **direct merge prerequisites**: “Spoken Responses for Voice - Speech 1: The speech job and ask aloud” and “Spoken Responses for Voice - Speech 2: Mission Control voices”. It also requires proven Linux capture stop/restart and the supervised-instance lifecycle. Contract L supersedes the addressing plan’s shell-owned speech capability and macOS-only ask path. Reuse M’s daemon-started synthesizer, on-request Supertonic 3 download (about 150 MB), Automatic F4, existing picker, and daemon-computed speech-output. Linux lists no system voices. The on-screen card is the fallback. The only Linux speech work is playback, supervision/recovery and truthful Setup reporting.

**Show that the listener is silent.** Announce a supervised instance first. A live hello advertises speech.audio only when a working, qualified player is available. For each holder-specific audio directive, stop and await physical capture closure, discard pending acoustic input, fetch the in-memory WAV from the existing token route, then play on the default output. Name the holder in x-mission-voice-instance on directive polls, audio fetches and event reports. Keep the existing listener lease header separately. Send started at actual playback start and ended after output drains or a stop really silences the device. Keep polling during fetch/playback. Serialize cancellation, stale callbacks, duplicate directives and event retries. Every stop silences whatever is playing, cancels pending starts and returns ended/stopped for the named job, including unknown or already-ended IDs. Output loss ends as failed after silence is certain. While playing, stopping or awaiting resolution keep local capture closed even if a directive is stale. Resume only under a fresh capture directive and an otherwise eligible mode. An external player must have a provable lifetime tied to the listener; qualify an in-process player preferentially so its audio cannot outlive process-exit proof.

**Start and replace one process.** Give the Linux supervisor its own owner-only record under the existing supervised directory, e.g. `voice/supervised/linux.json`. Extend Speech 1’s recovery enumeration to recognize it alongside shell and dev, keeping the same record semantics. In its supervisor role the daemon alone writes this record. Generate a fresh secret instance (at least 128 random bits), atomically persist intent before launch, announce started through the same authenticated supervised-instance operation, pass the instance in MISSION_VOICE_LISTENER_INSTANCE, then atomically complete the record with OS PID and start identity. Use 0700 directory, 0600 file, durable write/rename and directory sync for each ownership transition. No secret in argv, URL, dashboard or logs. Preserve the record until exited has been accepted. Re-announce a still-running child and replay unaccepted exit reports idempotently. On an unconfirmed stop, retain capture suppression through the existing five-second confirmation limit, request termination and escalate against the identified process if necessary. Await OS-observed exit and proof of device silence before reporting exited and launching any successor. Timers, signals sent, an expired hello or a new hello never prove silence.

**Recover after daemon death.** Before the first directive poll or any replacement, load Speech 1’s owner-only `voice/speech-holds.json` and reconcile the Linux supervisor record under single-writer ownership. The job manager persists each holder before exposing a ready job. Restore each unfinished holder as stopping, suppress capture globally and give only that holder its stop. A matching ended confirming silence, or a supervisor exit report backed by OS-proven exit and output silence, finalizes the recovered job as failed. On Linux the supervisor withholds its exit report and any replacement until queued output is proven discarded or drained, including after its own restart. A verified backend guarantee may establish silence at exit; otherwise the supervisor must observe it separately. An inconclusive observation keeps every capture directive off. Hold new jobs until recovery is complete. Preserve the contract’s guards on captured utterances, flag cycles, mute and delayed confirmations.

For a recorded child, bind its identity to boot ID, OS process start ticks, uid and the launched listener program (Node executable plus exact sherpa entrypoint). Open a pidfd for the candidate, validate identity against the saved run, signal only the verified process through that handle, then poll the handle for exit. A fresh daemon cannot use the former parent’s child exit callback. A verified different boot, absent process or reused PID with a different start identity proves the *recorded* process has exited; never signal its successor. Treat access errors, unsupported identity probes or inconsistent evidence as unresolved. Keep the gate closed and show a recovery diagnostic. Validate this design on the target kernel. [Linux pidfd semantics](https://man7.org/linux/man-pages/man2/pidfd_open.2.html)

Exercise crashes between intent, announcement, spawn, PID write, accepted exit and record deletion. For a PID-less record, reconcile with a complete OS scan of the listener launch signature, scoped to the correct user/namespace and covering any helper still starting. Tie the pre-audio launch barrier to the fresh instance already persisted in the owner-only intent record. Establish a restart-verifiable per-launch identity before spawn, for example a dedicated user service scope with atomic child placement and a stable per-launch handle. Its public handle must not disclose the secret speech instance. An exact lookup must cover a still-pending launch and every capture descendant. The child cannot touch audio before placement and PID/start identity are committed, and aborts on parent loss before release. A manually launched listener with the same entrypoint, UID and namespace is outside this launch. Preserve it. A full process listing alone cannot attribute a live candidate to an instance. Stop positively identified remnants and wait for OS exit; report absence only with complete coverage. Ambiguity or inaccessible process state keeps capture off. For unreadable holds, follow L’s replacement entries for every outstanding supervisor, including unknown-instance entries for unreadable records. Treat an unreadable supervisor record as potentially playback-capable. Before removing or replacing it, require both proven absence of the launch and its descendants and independent evidence that every possibly affected output is silent. Recover the complete route set from surviving durable evidence or a qualified audio-server lookup, and prove discard or drain on each route. If the route set or silence cannot be established, retain the record and recovery hold, suppress capture and replacement, and report the missing proof in Setup. Re-evaluate on new evidence; recheck through the supervised operation. A readable hold with missing proof stays held. Test with an unrelated Node process, PID reuse, reboot, replacement hello, unreadable files and a restarted daemon while the original holder still plays.

## Proof required to ship

1. Confirm the operator’s desktop and tester before beginning. Capture the environment and results for each supported session and audio path. A result on one compositor or server qualifies only that combination.
2. Speak an actual roster name and message, verify delivery to the intended conversation and the corner toast, mute from another app and prove the device closes. Test input removal/reselection, permission denial, audio-server restart and browser reload. Record the capture backend decision and failed candidates.
3. On real X11 and each claimed Wayland combination test a tap, long hold during another app’s capture, key-up with active speech, delayed/repeated events, denied/conflicting bind and lost session. Verify no words outside the held interval are delivered. Exercise unavailable desktop capabilities through the browser.
4. Run S9 on real speakers and microphone with a tester listening: three isolated capture-open control trials and three with capture closed until real playback completion. Check acoustic pickup and routed utterances in a disposable fixture. Try the upstream 250 ms post-completion delay if needed and rerun. Persistent leakage keeps audio unavailable. Test natural finish, immediate/late stop, output removal, crash during playback and successful listening afterward. Record audible results separately from file recognition or synthesis CI.
5. Add focused node:test cases for protocol, report freshness, stable identity, crash windows, durable recovery, missing confirmation, replacement ordering and capability computation. Run isolated Linux subprocess tests with real OS exit observation plus device-independent fakes. Keep the existing Linux recognizer test required. Every changed dashboard behavior gets a Playwright spec using fake sessions and role/label selectors; compare rendered screenshots and interactions to the references. Run repository typecheck, lint, build, smoke and applicable unit/E2E suites with the required test preload.
