Investigated findings

Everything below was read in this repository, and two of them contradict what the plan or a first reading assumed.

  1. CorrectedAll six conductor/* anchors already render. ConductorPanel has one unconditional return (ConductorPanel.tsx:385), .sc-controls (:438) is not behind a config guard, and ConsoleCard always emits data-anchor={anchor} (settings-console.tsx:77). The five new search entries can point at anchors that already exist. An initial reading claimed only two anchors render; it was checked against the source and rejected.
  2. renderToStaticMarkup runs no effects. test/settings-search.test.ts:124-132 renders every category statically and fails any indexed anchor that no panel renders, so new anchors stay unconditional.
  3. DiscrepancyA repo-scoped pipelines deep link does not exist. The grammar has exactly two pipeline forms - #/runs/pipeline and #/runs/pipeline/:repoKey/:slug (useWorkflowRoute.ts:352-362, :468-478). There is no :repoKey-only form, and the panel holds no run slug. This disagreed with the approved mockup's pipelines button; it is settled in the phase file and carried back into the mockup, which now labels the action Open Pipelines tab.
  4. settingsRailDot already accepts "conductor" (settings-dots.ts:59-61). A case is enough, with no type widening.
  5. dotLabel switches on tone before category (SettingsPage.tsx:81-108). Reusing armed or live without a category === "conductor" arm makes a screen reader announce "YOLO mode is armed" on the Conductor row.
  6. risky search entries are pinned by a deep-equal literal (test/settings-search.test.ts:296-302). The new entries are kind: "jump" and non-risky, so that literal is untouched.
  7. .sc-seg has no CSS of its own - layout comes from .sc-field and .sc-seg-row. InspectorSettingsPanel.tsx:307-326 is already a two-option instance and is the closest model.
  8. ConsoleSwitch replaces the borrowed skill-switch (settings-console.tsx:96). Its track is 38x22px against the old 15x15px checkbox, so the row alignment needs a look.
  9. Selection is not addressable. Task sources holds it as local state keyed by id, and the settings route grammar is category-only by design. Key by pipelineRepoKey(provider, repoRoot), and a hash form for the selection would be a change to that grammar rather than a detail of this work.
  10. Test churn is smaller than the file sizes suggest. 9 of 23 tests in conductor-panel.test.ts touch row markup, and 5 of 12 in the e2e spec. settings-sidebar-render.test.ts fingerprints the panel by "Conductor commissioning progress", which survives only because trimming the ladder was deferred.

Phase count: one

Above the 200-line one-shot threshold, the rubric still defaults to one phase, and nothing here overturns that. The work is a single panel plus the two registries that describe it - a vertical slice that produces working behaviour, not a stack of layers.

Three splits were considered and rejected:

Ride-alongs as a second phase (~75 lines: the search entries and the rail dot). Strictly serial - the search entries must point at anchors this change finalizes, and settings-search.test.ts fails an anchor that renders nowhere - so it buys no parallelism, only a second pull request. A sub-100-line trailing phase is the balance-making cleanup phase the rubric forbids.
A layer split (shared registries, then the component). An application-layer boundary is not by itself a phase boundary, and both skill-switch and the Engineer host radios sit inside the exact regions the restructure rewrites - splitting them out puts two agents in one file.
A behavioural split ("bound the list" first, "add the detail pane" second). A real vertical boundary, but it restyles the repository list twice and, because every UI change here requires a Playwright spec, pays for two full e2e rewrites to ship one approved design.

Cross-phase contracts

With one phase there is nothing to hand downstream, but three contracts are recorded because later work will meet them:

  • The row switch keeps aria-label="Observe pipelines in <name>". e2e/specs/settings-conductor.spec.ts:253-254 reaches rows through it.
  • Anchors stay unconditional and keep their current six names. The search index points at them and the render test requires each to appear inside the Conductor panel and nowhere else.
  • The selected repository is keyed by pipelineRepoKey(provider, repoRoot), never by list index, because the view is polled every four seconds.
