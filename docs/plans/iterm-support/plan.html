Outcome

Mission Control will treat iTerm2 as a first-class terminal emulator under the existing terminal registry. An operator using iTerm2 will be able to discover and name sessions, send prompts and key input, capture visible terminal content, focus an existing pane, open a worktree in a new iTerm2 window, rename the containing tab, and compose those behaviors with tmux.

Compatibility promise: setup and launch surfaces consume the shared registry. Existing WezTerm, Ghostty, and tmux preference and behavior remain unchanged.

Evidence and Constraints

  • The existing emulator contract already models list, write, capture, focus, spawn, and retitle. Routes, actions, and UI derive from the registry.
  • The installed iTerm2 3.6.11 scripting dictionary exposes windows, tabs, sessions, session unique IDs, TTYs, visible contents, writable tab titles, selection, text input, and new-window commands.
  • Official scripting documentation confirms the object hierarchy. AppleScript is in maintenance mode, but unlike the Python API it needs no helper package, WebSocket connection, or separate API service.
  • AppleScript can launch an application, so the adapter must use the existing host-process gate before passive enumeration.
  • iTerm2 exports ITERM_SESSION_ID. Mission Control must capture that additive hook field and scrub it from daemon-owned agent children.
  • Terminal and setup IDs are append-only persisted contracts. iterm is appended; UI grouping must not reorder the source tuple.
  • The daemon keeps ownership of fixed installation commands and terminal actions. The browser sends only dependency and backend IDs.

Additional references: session titles and the Homebrew iTerm2 cask.

Adopted Design

Registry and availability

Append iterm, register one emulator implementation, resolve ITERM_BIN, and declare the iTerm2 host process. Existing fallback order remains WezTerm, Ghostty, then iTerm2.

Adapter and targeting

Address every mutation by session unique ID, correlate by TTY, use the tab title for naming, and treat working directory as best effort. Send scripts and prompt payloads through osascript standard input.

Hook identity

Add itermSession to the optional terminal environment schema, bind it after existing tmux and WezTerm precedence, and scrub inherited identity from SDK, one-shot, and headless launches.

Setup and user surfaces

Append the setup record, add the fixed remedy brew install --cask iterm2, and let existing registry-driven settings and launch controls render the new backend.

Runtime flow

Capability implementation

  1. Enumerate all windows, tabs, and sessions in one delimiter-safe AppleScript response.
  2. Implement literal text, the shared key vocabulary, and bracketed paste wrappers.
  3. Capture visible contents and isolate capture failure from discovery.
  4. Select the exact session, containing tab, and window before activating iTerm2.
  5. Create a new window with safely quoted working directory and argv, then return its target.
  6. Retitle the tab containing the selected session and confirm it through enumeration.

Implementation Work

  1. Extend stable contracts and registries. Append IDs, register setup and terminal implementations, widen host-gate documentation, and update exhaustive fakes and tests.
  2. Implement and harden the adapter. Add binary resolution, AppleScript helpers, safe parsing, stable targeting, complete capabilities, timeouts, and local failure behavior.
  3. Complete session binding. Capture and normalize ITERM_SESSION_ID, preserve tmux precedence, scrub daemon-owned child environments, and cover fixtures.
  4. Expose setup and launch behavior. Add the optional check and remedy, retain registry-derived UI, and cover setup and launch with Playwright.
  5. Document support and permissions. Add ITERM_BIN, support details, Automation permission recovery, and passive-versus-explicit launch behavior.

Verification

Automated

  1. Adapter tests cover parsing, quoting, target traversal, keys, bracketed paste, capture, focus, spawn, retitle, timeouts, stale targets, and nonzero exits.
  2. Enumeration and correlation tests cover the non-running host gate, exact TTY joins, active selection, and failure isolation.
  3. Hook and environment tests cover identity capture, tmux precedence, normalization, and SDK/headless scrubbing.
  4. Setup, probe, registry, target, and route tests cover the new append-only entries.
  5. Playwright covers the visible setup row and an iTerm2 launch selection, including route payload and feedback.
  6. Run focused tests, typecheck, lint, full unit tests, build, smoke, and the browser suite.

Live macOS acceptance

  1. Confirm passive discovery does not launch a closed iTerm2.
  2. Exercise Automation approval, denial, retry, and revoked permission.
  3. Enumerate multiple windows, tabs, and splits, then verify identity, titles, TTYs, active state, and working directories.
  4. Verify keys, long and multi-line paste, exact PTY bytes, capture, precise focus, retitle, and worktree spawn.
  5. Verify tmux raise and fallback attach inside iTerm2.
  6. Repeat critical flows from the packaged Electron app. Expand entitlements or release scope only if this proves a concrete requirement.

Scope Boundaries

Included

  • Discovery, input, capture, naming, launch, and focus
  • Hook binding and environment hygiene
  • Setup, documentation, browser coverage, and packaged validation
  • Small shared refactors needed to keep quoting and grouping single-sourced

Excluded

  • Profile management, badges, triggers, or Python API plugins
  • Default-terminal changes, migrations, flags, or helper services
  • A new browser-side vendor branch
  • Release, signing, deployment, or CI changes without separately reviewed evidence

Decisions Recorded

  • Use backend ID iterm and display label iTerm2.
  • Use built-in AppleScript behind the existing adapter contract, not the Python API.
  • Implement all iTerm2-supported capabilities, including capture and retitle.
  • Address sessions by unique ID, correlate by TTY, and keep working directory best effort.
  • Use a new iTerm2 window for the existing emulator spawn contract.
  • Append iTerm2 after WezTerm and Ghostty to preserve automatic priority.
  • Include hook identity propagation and environment scrubbing in full support.
  • Land one compatible feature change with no persisted-data migration.
