Approved engineering plan

Durable work-cycle completion

Make prompted automatic completion react once to each genuine completed agent work cycle, including background continuations under unchanged human intent, without replacing the verifier or the surrounding safety system.

Approved for phased implementation

Decision

Replace the prompted intent-revision re-arm with one daemon-owned, durable work-cycle generation. This is not a permanent fallback layered beside the existing mechanism.

Intent remains the objective and staleness guard. Evidence remains proof and idempotency material. A completed work cycle is the missing lifecycle identity.

Problem

Mission Control durably models intent episodes, task and pull-request work episodes, and review evidence. Prompted completion currently borrows the intent episode to mean that another agent turn finished. After an incomplete verdict it assumes nothing relevant changes until another human prompt is reconciled.

Claude background-task notifications correctly drive the working lifecycle without becoming human intent. A later Stop can therefore be a new completion opportunity while the intent revision stays unchanged. The current guard suppresses it. The worker also rechecks intent after verification but does not prove that the same completed turn remains current and idle.

Approved design

Normalize

Harness adapters translate terminal activity and turn-end hooks, plus SDK working and turn_done, into one generic work-cycle contract. Consumers never branch on agent names or raw events.

Persist

The daemon stores the latest generation and completion time per logical session key. It keeps current state, not an unbounded event backlog, and survives daemon and worker restarts.

Consume once

Prompted completion checks only an unconsumed, settled generation. Empty diff, hold, Ask, workflow claim, and direct wrap-up each consume it exactly once.

Recheck currency

After verification, Foreman requires the same note key, completion generation, resolved intent, and settled idle state before any action.

Flow

  1. A terminal hook adapter or SDK driver reports work activity to Registry.
  2. The adapter normalizes a completed turn without exposing raw event vocabulary.
  3. The daemon advances and persists the logical session's work-cycle generation.
  4. Foreman observes a new settled generation and gathers current evidence and intent.
  5. The existing verifier decides completion.
  6. Foreman rechecks work-cycle, intent, and idle currency.
  7. The daemon atomically consumes the generation with the resulting action or hold.

Compatibility

  • Use additive migrations and keep historical databases opening safely.
  • Keep lifecycle state separate from session_events and task-level session_work_episodes.
  • Preserve prompted_goal for schema compatibility but stop using it as the active completion key.
  • Translate a matching legacy prompted guard into an initially consumed current generation to prevent upgrade replay.
  • Fail closed on missing or inconsistent work-cycle state instead of retaining a permanent legacy trigger.
  • Keep the direct-wrap-up payload loop guard until injection authorship is durable.

Scope boundaries

In scope

  • Terminal and SDK normalization
  • Durable current work-cycle state
  • Prompted selection and consumption
  • Post-verifier currency checks
  • Workflow claim integration
  • Regression and migration coverage

Out of scope

  • Replacing queue drain
  • Forcing tasks into queues
  • Merging policy state machines
  • Agent-required done calls
  • Reviewer or workflow graph changes
  • New dashboard UI

Delivery decision

The running tactical task 5439ebd4-e346-4d57-b778-ecb2ebec8e67 may land first. The durable implementation rebases on it, keeps valid regression coverage, and replaces any evidence- or intent-based re-arm as the final mechanism.

Implementation tasks are intentionally disabled, low priority, and pinned to Codex gpt-5.6-sol at xhigh effort. A human must explicitly enable them.
