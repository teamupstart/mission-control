Investigated findings that shaped the phases

  1. markWorkEpisodeMerged already stamps merged_at on the current binding table but not the historical one - a merge observed after rollover is lost.
  2. mergedPrFor reads only the current binding - the single line that makes agentWentAway mark shipped work failed.
  3. Merge observation has two sources: the live-session branch poller (refuses rolled sessions) and a by-URL poller fed only by dependency URLs. A standalone task whose session died has no observer at all.
  4. The retained historical bindings + DependencyPrPollState cadence mean all three phases are wiring, not new infrastructure.
  5. PR #224 reorders settle/close (complete-then-close). It landed on main as b4503f2 while this plan was being phased; every phase starts from a base including it (now simply: current main).

Dependency graph

Strictly serial - no concurrency group. All three phases edit src/server/tasks.ts / src/server/registry.ts, and each consumes the previous phase's contract.

Cross-phase contracts

  • mergedPrFor(taskId) (Phase 1): newest merged PR across ALL of the task's bindings, or null. The only durable completion lookup.
  • markWorkEpisodeMerged (Phase 1): stamps current AND historical binding rows in one transaction.
  • reconcileMergedTasks() (Phase 2): single owner of PR-driven completion including failed/cancelled upgrades; stamps dependency edges; keeps resources; never registers in autoCompleted.
  • One by-URL poll pipeline (Phase 2): dependency and task-completion URLs share DependencyPrPollState.
  • Task.sessionId = "currently executing on" (Phase 3): provenance reads bindings; serial invariant enforced at agentIsFree + TaskManager.assign.

Final verification

Each phase runs npm run typecheck && npm test && npm run build and ships through the no-mistakes gate with CI green on Node 24 + 26. The end state is pinned by Phase 2's headline tests (killed-session completion, cancelled upgrade, dependent unblocked, agent freed) plus Phase 3's multi-task flow test. task-merge-settles.test.ts and task-session-orphan.test.ts stay green in every phase.
