Approved Direction

The operator approved the root plan as written on 2026-09-03 and selected phased implementation planning.

Fixed decisions: backend ID iterm, display label iTerm2, built-in AppleScript transport, full supported capabilities, stable session identity, TTY correlation, new-window spawn, current terminal priority, hook identity hygiene, and no persisted-data migration.

Why One Phase

Estimated non-test implementation size is 420 to 650 lines: 280 to 420 for the adapter and AppleScript boundary, 80 to 130 for shared registry and hook contracts, and 60 to 100 for setup and fixture integration. No database or new React component is expected.

These changes form one vertical capability slice. Registering early exposes partial support; setup or hook changes without the adapter expose an unusable backend; leaving the adapter unregistered creates dead production code. A single phase is the fewest coherent, operable merge units.

Contracts Preserved

  • Stable terminal and setup IDs are append-only; existing emulator priority does not move.
  • Browser code stays declarative while the daemon owns commands, targeting, quoting, and timeouts.
  • Session unique ID is durable; TTY is the strong correlation key; working directory is best effort.
  • Passive discovery never launches iTerm2.
  • The hook field is optional and daemon-owned child processes cannot inherit it.
  • Backend failure is isolated from WezTerm, Ghostty, and tmux.
  • No database, generated artifact, release, signing, deployment, or CI change is planned.

Release Gate

  1. Focused adapter, registry, correlation, hook, environment, setup, and route contracts pass.
  2. Playwright proves setup and launch behavior through accessible selectors and fake agents.
  3. Typecheck, lint, full unit tests, build, smoke, focused browser tests, and the full browser suite pass.
  4. Live iTerm2 acceptance proves no-auto-launch behavior, exact input bytes, capture, focus, retitle, spawn, tmux composition, and permission recovery.
  5. Packaged Electron acceptance finds no unplanned macOS Automation or entitlement difference.
  6. Documentation matches the shipped capability and configuration surface.

Compatibility Audit

The final audit maps every root-plan requirement to Phase 1 exactly once. The only wire change is optional, the only stable-ID changes are append-only, and the implementation remains operable in one merge without a later cleanup or migration phase.

The implementation task is created only after these artifacts are committed and pushed. It depends on the current planning session and stays backlogged until the planning pull request merges.
