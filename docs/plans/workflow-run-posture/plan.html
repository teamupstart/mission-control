Shared underpinnings

The posture model all three render. runPosture(detail) in run-model.ts returns auto (workflow executing, a session action on a machine-side wait reason, or a parked round that resumes itself; a run with a derived move demotes it to a labelled override, and a run that is actively moving shows no resubmission control at all), yours (session idle, nothing running, an operator decision is the only way forward - including a session action whose wait reason only a person can end), or none (terminal). Sources: run.status, summary.actionWait through the shared sessionActionWaitsOnOperator predicate, the resumption observer's withheld ledger (session_busy, session_needs_you, policy_manual, resumesItself), and summary.resumptionPolicy plus the binding's deliveryMode through workflowRunResumesItself. No new server state.

Whichever option is selected: unit cases beside runNextMove's in test/workflow-run-next-move.test.ts, and a Playwright spec in e2e/ driving reviewers-running, parked-with-session-working, and session-idle states, plus the override path.
