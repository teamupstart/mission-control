Criterion-mapped evidence preflight

Make every material acceptance criterion point to the proof intended to satisfy it, then catch structural omissions before Test Evidence Auditor spends an attempt.

Clarified model boundary

Existing configurable job

Reuse workflow-context and its existing Settings, environment, and provider-default resolution. No new model or Settings row.

Bounded new context

Add changed code paths, a clipped diff summary, evidence captions, and claim metadata to the current goal-and-decisions prompt. Never include evidence locators, local artifact paths, or artifact bodies.

Advisory classification

The author's proof class selects hard evidence roles. A model-only visual suggestion warns, so a non-UI change is never forced to provide a screenshot by classifier opinion alone.

What changes

The boundary: preflight checks whether the expected proof shapes are present. Test Evidence Auditor still decides whether the proof actually demonstrates the claim.

Safe by construction

  • Coverage links resolve only inside the same frozen submission.
  • Repository scope is checked deterministically.
  • Canonical IDs are daemon-derived, never model-supplied.
  • Model-only proof-class disagreements warn rather than hard-block.
  • Compaction failure proceeds as unavailable and cannot deadlock a run.
  • Overrides require a durable reason and leave every gap visible.
  • Historical and custom workflows stay off until an immutable version opts in.

Intentionally excluded

  • No automated command execution.
  • No semantic pass from the preflight.
  • No PR or CI evidence import.
  • No arbitrary file attachment.
  • No evidence artifacts committed.
  • No repair-round charge for preflight corrections.

Versioning and persistence

Add immutable evidenceReadinessPolicy to workflow definitions and versions, with off as the compatibility default and criterion_mapped_v1 enabled only by a new No-Mistakes Review version.

Mutable authoring

workflow_evidence_coverage_staging holds bounded claims, proof classes, repository scopes, evidence links, and staging generations.

Immutable review packet

Submission coverage and readiness records freeze canonical criteria, mappings, deterministic gaps, and policy version. Existing parent_submission_id carries refinement lineage with a new reason.

Audited exception

An append-only override record stores actor, reason, request ID, and timestamp without rewriting the immutable evidence packet.

Incomplete packets enter waiting_for_evidence_readiness and prepare one idempotent evidence_readiness delivery. Agent repair creates a same-round evidence-refinement segment; operator override activates the same immutable submission.

Implementation sequence

  1. Add versioned contracts and migrations. Define policy, proof roles, lifecycle values, mutable coverage staging, immutable coverage, readiness results, overrides, and explicit segment lineage.
  2. Stage and freeze coverage atomically. Extend the dashboard and MCP contract while preserving legacy evidence-only calls.
  3. Derive and reconcile canonical criteria. Extend the existing configurable Workflow context call with bounded changed-path, clipped diff-summary, and evidence metadata, then apply deterministic matching, scope, and author-declared role checks.
  4. Gate before Persona activation. Pause incomplete submissions, create no Persona attempt, and deliver an exact repository-specific repair packet.
  5. Resume without spending repair budget. Freeze same-round refinement segments and support idempotent operator override on the same packet.
  6. Expose and verify the state. Build criterion mapping and history UI, add Playwright coverage, publish a new built-in workflow version, and add honest telemetry.

Acceptance bar

Before review

Missing structural proof pauses the run before any Persona model call and identifies the exact criterion and role.

During repair

New evidence creates an immutable child segment in the same round, with restart-safe and inspectable lineage.

After readiness

The existing workflow continues normally and Test Evidence Auditor remains the semantic acceptance authority.

Measurement

The primary metric becomes first Test Evidence Auditor attempt acceptance, not round 1 segment 0. Preflight interceptions are reported separately, along with missing proof classes, same-round refinements, overrides, readiness failures, and Auditor rejections after a ready result.

Success is not hiding rejections. A packet held by preflight has not passed the Auditor. The design preserves that distinction in storage, UI, and telemetry.
