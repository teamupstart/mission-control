Resume permission loss

Why did a resumed agent lose repository permissions?

Resume rebuilds a session from its stored configuration but never replays the repository grant, so the relaunched session starts with an empty allowlist. Every resumed session loses repository writes at its first tool call.

Evidence

StepGrant presentSource
Initial launchyesdispatcher.ts:214
Stored configyesharness.db tasks.grants
Resumenoregistry.ts:412

What we ruled out

  • The grant is not lost in storage - it is still readable in tasks.grants after the resume.
  • The harness adapter is not filtering it; both Claude and Codex resumes reproduce identically.
  • It is not a race with the first tool call - a resumed session idle for a minute behaves the same.

Limits

Only repository grants were traced. Whether MCP server grants and permission-mode selections take the same path through resume was not measured, and the same omission is plausible there.
