Syntax-highlighted editor

Use CodeMirror 6. Existing rehype-highlight is a static Markdown rendering pipeline; it has no editable selection, undo history, IME handling, or accessible editor behavior. CodeMirror provides those contracts without Monaco's worker-heavy IDE surface.

  • Line numbers, active line, brackets, folding, find, undo/redo, indentation, and horizontal scrolling.
  • Language by basename/extension with plain-text fallback. Unknown UTF-8 text stays editable.
  • Mission Control light/dark palette; no foreign theme.
  • Preserve newline style and final newline; V1 writes UTF-8 only.
  • Spellcheck off. Editor focus stands down global shortcuts.
  • HTML Preview renders the local buffer after a short debounce, independently of disk save.

Autosave and concurrent edits

Saved→Modified→Saving…→Saved

Save after roughly 750 ms of inactivity and flush on blur, file switch, extract/restore, and overlay close. Only one save per file is in flight. New keystrokes during a save schedule the next save against the returned revision.

Every read returns a SHA-256 revision of exact bytes. Every save sends that expectedRevision. The daemon compares current disk bytes immediately before an atomic write.

Conflict pauses autosave. Keep the local buffer and offer Compare, confirmed Reload disk, confirmed Overwrite disk, and Copy local text. V1 deliberately does not auto-merge.

Server boundary

Discovery and reads

  • Add session-files.ts with one canonical resolver shared by list, read, preview, and write.
  • Root operations in live session cwd; canonical separator-aware containment rejects traversal and symlink escape.
  • Discover bounded, sorted files with git ls-files --cached --others --exclude-standard; a manual repo-relative path reaches known ignored output.
  • Classify on open using fatal UTF-8 decoding plus NUL detection, not extension alone.
  • Proposed caps: 2,000 entries, 5 MiB read-only HTML, 2 MiB editable text.
  • Return relative path, text, bytes, mtime, language, kind, and revision—never absolute path.

Routes: GET /api/sessions/:id/files and GET /api/sessions/:id/file?path=….

Revisioned atomic writes

Add PUT /api/sessions/:id/file with { path, text, expectedRevision }. Define SaveSessionFileSchema in shared protocol and go through parseBody.

  1. Repeat every path/type/UTF-8/size check and reject non-regular/symlink/disappeared targets.
  2. Create an exclusive temporary file in the same directory.
  3. Write full UTF-8, fsync, and preserve original mode.
  4. Re-hash the target immediately before rename; return 409 if it moved.
  5. Rename atomically and return the new revision/mtime.
  6. Clean the temporary file on every failure.

V1 edits existing files only: no create, rename, delete, chmod, or symlink following.

A session-scoped useSessionFiles controller owns list, selection, buffers, revisions, save state, conflicts, and refresh. Integrated and extracted presentations consume the same controller.

Lifecycle contracts

  • Add Files to ConsoleDetail.
  • Route onOpenFiles through SessionViewProps/cardProps.
  • Register Files in OVERLAY_IDS.
  • App owns session binding and disappearance reconciliation.
  • Reset drops editor workspace; conflicts prompt before destructive reset.
  • No rail/tile/card state badge and no V1 shortcut.

HTML preview security

The preview renders the current local buffer through srcDoc in iframe sandbox="". Never add scripts, forms, same-origin, popups, navigation, or download capabilities.

CSP blocks by default and explicitly blocks connections, forms, and navigation; only inline styles and data/blob images/fonts are allowed. V1 therefore supports self-contained HTML. Relative assets and application preview require a separate isolated origin/process later.

Editing does not weaken preview isolation. The editor may contain executable markup; the preview still treats it as untrusted checkout content.

Failure and lifecycle behavior

  • Disconnected: retain local buffer, show Offline, retry only after the existing connection state returns.
  • Save failed: retain buffer/revision, show error, offer Retry.
  • Session disappeared: drop session-scoped buffers when checkout authority is gone; offer copy recovery when possible.
  • File deleted externally: deleted-on-disk conflict. V1 cannot recreate it.
  • External change while reading: manual refresh or next save detects it; no watcher/polling in V1.
  • Navigate while dirty: flush; retain failed/conflicted buffers and mark their files.
