# Phase 2 - Pipeline editor

## 1. Outcome

Authoring a workflow becomes "stages of reviewers": operators add, remove and reorder reviewers and
stages; joins, fail routes, return edges and reachability are generated by `compileStages`. The
freeform canvas remains a co-equal fallback editor (adopted decision 2). This is the phase where the
review's headline complaint dies: parallel first-wave review is two clicks, not a validation error.

## 2. Entry criteria and dependencies

- Direct prerequisite: Phase 1 merged (`workflow-stages.ts` API frozen, validator relaxed).

## 3. Scope

1. `PipelineEditor.tsx` and shared presentational leaves (`pipeline-bits.tsx`).
2. Pipeline | Graph view toggle in `WorkflowLibrary` with the blockers banner.
3. Overlay-hosted confirm replacing `window.confirm` on the builder surfaces.
4. Right-rail rebuild: settings copy fixes, sentence-first validation, version history, and a
   "Bind to a session..." call to action.
5. Vocabulary adoption (`nodeLabel`) in the Graph view's panels and announcements.
6. Styles, README, keyboard docs, tests.

Non-goals: the runs monitor (phase 3); moving Workflow settings (phase 4); re-theming React Flow
chrome; Persona library changes; any server change.

## 5. Implementation steps

1. **`src/web/workflows/pipeline-bits.tsx`** - presentational leaves used by this phase and phase 3
   (the same role `session-bits.tsx` plays for session surfaces): `StageCard`, `ReviewerRow`
   (persona name + `runner · model` meta + optional status chip slot), `StageSeam` (gate mark +
   insert affordance), `TerminusCard` (Session / End), `PipelineFrame` (horizontal scroll container
   + repair rail). Props take data, never fetch. Status chip vocabulary maps the tones used by
   `workflow-chip` (`running/waiting/passed/failed`).
2. **`src/web/workflows/PipelineEditor.tsx`** - renders `projectStages(draft)` through the leaves;
   edits build a new `StagePipeline` and call `onChange(compileStages(next, workflow.draft))`. The
   editor holds no pipeline state of its own: after every edit its state IS
   `projectStages(draft)`, so a reviewer being added is constructed with `nodeId: null` and its
   compiler-minted id comes back on the next projection (phase 1's identity contract).
   - Add reviewer: inline persona picker inside the stage (active personas; archived excluded),
     replacing the sidebar palette's select-then-click for pipeline mode.
   - Remove reviewer / remove stage: overlay confirm (step 4), then compile.
   - Insert stage at any seam; reorder reviewers within a stage and stages within the chain by
     drag and by keyboard (Alt+Arrow while a reviewer or stage header is focused).
   - Roving tab focus across termini, stages and reviewers; `aria-live` announcements phrased with
     persona and stage names.
3. **`WorkflowLibrary.tsx`** - view state `"pipeline" | "graph"`, defaulting per
   `stageExpressible(workflow.draft)`; a Pipeline | Graph toggle in the toolbar; in graph mode with
   blockers, a banner listing `stageBlockers(graph)` sentences ("Pipeline view unavailable: ...").
   The node palette section renders only in graph mode. Toolbar order regrouped: edit actions
   together, Archive separated from Publish (danger-ghost, not filled red).
4. **Overlay confirm.** Add `workflowConfirm` to `OVERLAY_IDS` and the host; a small
   `WorkflowConfirmModal` (title, body naming what is removed with `nodeLabel`/stage names, confirm
   + cancel) replaces every `window.confirm` in `WorkflowLibrary.tsx` and `WorkflowProperties.tsx`.
   `overlay-registry.test.ts` updated. Not session-bound; no disappearance reconciliation needed.
5. **Right rail.** Keep `WorkflowProperties` as the graph-mode panel but fix its copy (drop the
   phase labels; message-first diagnostics with the code demoted to a `title`/detail affordance;
   connections list and selected-edge text through `nodeLabel`). In pipeline mode render a slimmer
   rail: workflow settings fields, validation ("Ready to publish." or persona-level sentences),
   `WorkflowVersionHistory`, and a "Bind to a session..." button. The button reaches App through a
   new optional `onBindWorkflow?: () => void` prop threaded `App -> AppPageShell(workflows) ->
   WorkflowPage -> WorkflowLibrary`, opening the existing dialog with `{}` (no session pinned).
6. **Vocabulary in the canvas surfaces.** Graph-view connect-dialog options, edge/node aria labels
   and announcements switch to `nodeLabel`. `WorkflowCanvas` gains a `labelFor(node)` prop rather
   than importing personas itself, keeping it presentational.
7. **Styles.** New `wf-pipeline-*` rules in the existing workflows section; grep removed class
   names out of `styles.css` in the same change.
8. **Docs and keys.** README Workflows section rewritten around stages (parallel reviewers, the
   generated repair loop, the Graph fallback); in-surface keys (Alt+Arrow reorder, Delete with
   confirm) added to the README keyboard table. No new global chords, so `ACTIONS` in
   `lib/keybindings.ts` is unchanged.

## 6. Data/API/migration

None. All edits compile to ordinary draft graphs; the server sees PATCH bodies identical in shape to
today's.

## 7. Tests and verification

- `workflow-pipeline-render.test.ts`: renders a 2-stage pipeline via `renderToStaticMarkup`; asserts
  persona names, stage names, gate marks, and that no UUID substring appears in the markup.
- `workflow-pipeline-editor.test.ts`: edit operations produce compiled graphs that
  `validateWorkflowGraph` accepts and that preserve untouched ids (drives `compileStages` through
  the editor's handlers).
- `workflow-builder-a11y.test.ts` extended (or a sibling): roving focus order and announcement
  strings use names.
- `overlay-registry.test.ts` updated for `workflowConfirm`.
- Manual: `make start`, verify against the operator's own vite port (`:5173` serves the main
  checkout - house rule); author the 2-parallel-reviewer workflow end to end and publish it.

## 8. Merge and exit criteria

- A brand-new workflow opens in pipeline mode with Session -> (empty stage affordance) -> End
  (phase 1's zero-stage projection; opening never edits the graph). Its draft diagnostics render as
  one guidance sentence ("Add a reviewer to route the submission"), not error codes; the first edit
  compiles the canonical graph. Adding two reviewers to stage 1 and publishing succeeds.
- Graph mode still edits arbitrary graphs; non-expressible drafts open in graph mode with the
  blockers banner.
- No `window.confirm` remains under `src/web/workflows/` except in `WorkflowRuns.tsx` and
  `WorkflowConfigPanel.tsx` (phases 3 and 4 own those).
- Suites green; README updated in the same change.

## 9. Downstream handoff

Phase 3 may rely on: `pipeline-bits.tsx` component props as merged here; the `wf-pipeline-*` CSS
vocabulary; the `workflowConfirm` overlay; the `onBindWorkflow` threading through `WorkflowPage`.
Phase 3 must not fork a second stage-rendering dialect.
