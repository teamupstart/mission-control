Commands

Commands is the odd one out and its screen has never admitted it. There is no Markdown and nothing to write - a slot holds one repository-neutral default argv plus a list of exceptions, and the longest matching path wins. There are exactly four slots, forever, so the rail that Personas and Actions need is here a fixed list of four that can never grow, with no New, no search and no state filter to justify its width. And the one question a person actually arrives with - "what will test run in this repository?" - is never answered on screen; you are given the ingredients and a sentence about precedence and left to resolve it in your head.

A

Rail

evolve the workbench · smallest diff

The rail stays for consistency with the other two screens, and gains the same ← Library row carrying esc. The body is where the work is: the default and its exceptions become one table with a header row, default pinned at the top as the rule it actually is, and the add row visibly an add row rather than a third entry indistinguishable from the two saved ones. Each row carries its parsed argv underneath, so the "Runs as: 1. make 2. test" readout that today applies only to the default now applies to every rule. The rail sub-labels carry override counts, so you can see which of the four slots has exceptions without opening each one.

smallest change to ship add row is finally distinguishable from a saved one argv preview on every rule, not just the default 268px of rail for a list that can never exceed four still does not answer "what runs in repo X"

B

Focus

answer the question first

There is no document here to focus on, so Focus becomes something better: the screen leads with the question people arrive with. Pick a repository and the header tells you what test will run in it; the rules below reorder by specificity with the winner marked and the losers dimmed, so "the longest matching path wins" is demonstrated rather than asserted. The rail is gone - four slots do not need 268px - and becomes a strip of four chips across the top, each showing what it resolves to for the repository you picked. That strip is the whole gate set at a glance, which is the thing you are really configuring.

C

Sheet

all four gates, one grid

Same sheet mechanics as the other two screens - the card wall stays behind the app's own backdrop, Escape and Close both dismiss. What is specific to Commands is that the sheet holds all four slots at once as a matrix: repositories down the side, the four gates across the top, each cell the command that will actually run there. Because there are exactly four slots and they never change, the whole configuration fits one grid - and the mental model this matches is the real one, which is not "configure the test slot" but "make this repository's gates work". A cell showing default is inheriting; click it to override just that one.

the entire gate configuration on one screen matches how you actually work - per repository, not per slot Escape is self-evident wide rows once a command is long four independent CAS saves behind one surface
