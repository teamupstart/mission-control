Workflow evidence plan

Native image evidence for workflow reviewers

Let every Persona inspect and cite screenshots from the exact immutable submission it reviews, without moving the pull-request stage or committing proof-of-work images.

Approved for implementation

Objective

Success means a Test Evidence Auditor receives pixels, caption, provenance, and a stable image id in round 1 or a repair round, and a human can inspect the same retained image from run history.

Scope correction

The transcript is already review evidence. readWorkflowContextRaw captures a bounded window and clips each turn to 3,000 UTF-8 bytes while setting transcriptTruncated. Text results should continue to be concise counts and verdicts.

The missing channel is binary image evidence. The context contract has no image metadata, submit and resubmit accept no attachments, and LlmRunner.run accepts one prompt string for a tool-less Persona. A path in the transcript reaches the reviewer only as characters.

This plan does not move the pull-request stage, make PR comments a prerequisite, or bless docs/images/ as a proof-of-work destination.

Product decisions

Intake surface. Decision: ship dashboard upload and session-attributed agent registration together in the first complete feature.

Supported artifact type

V1 accepts PNG, JPEG, GIF, and WebP. PDFs, video, arbitrary binary attachments, OCR, and image generation are out of scope.

Lifetime

Image bytes follow raw workflow evidence retention. Metadata, digest, caption, id, citations, counts, and pruning time remain after bytes are pruned. Full run-family deletion removes the rest.

Repository scope

Every image targets one issued repository slot or all repositories in a multi-repository submission. Dashboard submission defaults to the selected binding's repository. The daemon resolves scope from its own records.

Implementation scheduling

Any implementation tasks created from this plan use gpt-5.6-sol with xhigh reasoning, per the operator's instruction.

Proposed flow

The copy is complete before any Persona attempt can be claimed. Reviewers never read a mutable checkout path and receive no filesystem grant.

Contract and limit changes

Shared workflow evidence

  • Add WorkflowEvidenceImage with stable id, ordinal, display name, required caption, repository scope, sniffed MIME type, bytes, SHA-256, and retained/pruned availability.
  • Add images to the context schema with an empty default for older snapshots. Extend retention counts with image count and bytes.
  • Append image to EVIDENCE_REF_KINDS. Its path is the stable image id and its quote is the observed visual fact.

Intake schemas

Use one bounded locator shape for upload reference or checkout-relative path, caption, repository scope, and a client item id. Mirror agent-tool validation in src/mcp/server.ts. Centralize per-image, count, caption, and aggregate-byte limits, with final count and aggregate limits set by a live compatibility check against both providers.

Provider-neutral runner input

Add optional immutable local images to LlmRunOptions. Codex adds repeatable --image arguments. Claude SDK uses one user message with base64 image blocks. Claude print uses one fresh stream-json message. Every text-only caller remains unchanged, and image-bearing calls fail before provider invocation if a retained file cannot be opened.

Durable intake and capture

Dashboard uploads

Reuse the existing upload endpoint and image-drop components, adding evidence caption and scope. The browser sends opaque upload references. The daemon re-sniffs and copies them into submission-owned storage before upload expiry.

Agent registration

Add submit_workflow_evidence as a session-attributed Mission MCP tool. Resolve issued repository roots server-side. Accept relative ordinary files inside those roots, including gitignored evidence. Reject absolute paths, traversal, control characters, symlinked components, unsupported types, and limit violations. Stage valid items for the next eligible submission and expose them for human removal before capture.

Submission ownership

Add workflow_submission_images beside workflow_submissions. Reserve staged items when the submission is created. Inside the existing capture lock, open without following links, read once, sniff, hash, atomically copy, persist rows and context, compute the final fingerprint, then activate the graph. A failure blocks before Persona tokens are spent.

Fresh-evidence semantics

A new digest or caption is fresh evidence. Extend the cheap probe with staged-image generation so an automatic repair can resume on a new screenshot even when code is unchanged. Transcript growth alone remains insufficient. Normal repair rounds do not silently carry old screenshots forward.

Persona execution and citations

The prompt gains an untrusted image manifest with id, caption, display name, repository scope, MIME type, bytes, and digest. Runner images use the same order. Every Persona receives the same immutable set. The Test Evidence Auditor may cite kind: "image"; an unavailable image is infrastructure failure, not a verdict against the work. Context compaction remains text-only.

Dashboard and audit history

Add the evidence composer to Bind and submit, Preview, Ship it, Resume review, Preview fresh evidence, and Run this review again. Block capture while upload is in flight or a caption is missing. Confirmations state image count and aggregate size.

Run detail shows thumbnail, caption, scope, digest prefix, size, and retained/pruned state per submission. An authenticated id-based route opens retained files with O_NOFOLLOW; the browser renders a blob URL. Run JSON exports metadata and digests, not base64.

Retention, reset, and deletion

Extend raw-evidence compaction to prune image bodies and record count and bytes. Use retryable cleanup or atomic trash rename so database and filesystem state cannot disagree. Session reset and full run deletion remove rows and files through existing owners. Startup reconciliation repairs interrupted cleanup. Active and otherwise ineligible runs retain images under the current retention rules.

Security and privacy invariants

  • No arbitrary browser or MCP absolute path is read.
  • Relative evidence cannot escape by traversal or symlink.
  • MIME comes from bytes, never names or headers.
  • Reviewers stay tool-less.
  • Bytes never enter prompt text, transcript, SSE, events, or context JSON.
  • Logs contain ids and bounded diagnostics, not base64 or private paths.
  • Every image collection and byte surface is bounded.
  • Proof-of-work images are never committed automatically.

Tests and acceptance evidence

Focused tests

  • Old snapshots default to no images; new metadata survives capture, export, and retention.
  • Old-database upgrade creates image storage safely.
  • Containment, symlink, MIME, regular-file, duplicate, count, and byte-limit refusals are pinned.
  • Dashboard and agent intake converge on identical metadata.
  • Digest or caption moves the fingerprint; transcript-only growth does not move the automatic probe.
  • Initial, repair, continuation, unchanged, external, multi-repo, reset, restart, prune, and delete paths preserve ownership and cleanup.
  • Codex gets image arguments. Claude SDK and print get image blocks. Text-only calls stay unchanged.
  • Manifest order matches runner order and image citations parse durably.

Browser end-to-end

  1. Drop and caption a real PNG, submit, and prove the fake reviewer received metadata and native image input.
  2. Open run detail and reach the retained thumbnail and caption by role and label.
  3. Fail a round, stage a new screenshot without changing code, resume, and prove its digest opens a fresh round.
  4. Capture reviewer-visible frames under e2e/.artifacts/workflow-image-evidence/ and do not commit them.

Validation gates

npm run typecheck, npm run lint, npm test, npm run build, npm run smoke, the focused Playwright spec, and npm run test:e2e.

Documentation and memory follow-up

Update workflow documentation and correct the repository memory whose headline says review rounds cannot see replies. Transcript text is visible but bounded; images require native evidence transport. Keep the private-PR attachment memory for the later publishing stage.

Definition of done

  • A dashboard user and automated session can submit a screenshot without committing it or opening a PR.
  • The screenshot is copied, hashed, stored, fingerprinted, and delivered to each Persona before review.
  • Claude and Codex see actual image content with tools disabled and can cite it.
  • A new screenshot advances an otherwise code-unchanged repair; incidental transcript growth does not.
  • Run detail renders retained evidence and clearly reports pruning.
  • Security, migration, recovery, retention, unit, build, smoke, and browser gates pass.
  • Product docs and repository memory state the corrected model.
