Approved goal

An agent in repository A can create a backlog task whose primary is B, or whose repository set spans A and B. Mission Control validates local checkout identity and harness capability; Git and the repository host enforce the eventual write. Omitting selectors preserves current-repository behavior.

Repository findings

  1. The model is ready. Task storage, dependencies, worktrees, PR tracking, and completion already understand a primary plus secondaries.
  2. The restriction is the MCP edge. The public tool has no selector and sends process.cwd().
  3. Canonicalization has one owner. resolveTaskRepoSet already handles owner walk-back, collisions, duplicates, and order.
  4. Harness policy belongs before storage. Dashboard and MCP creation must share effective-agent and multiRepoDispatch preparation.
  5. The Board already renders the result. Existing cards and report rows need browser proof, not new React UI.
  6. Foreman is separate. Its allowlist is consulted after creation and stays unchanged.
  7. Mixed-version correction. The old Zod object strips unknown selector fields. Explicit targeting therefore needs a capability preflight before creation.
  8. The phased-plan skill is the consumer. Its dashboard-only stop becomes explicit target-set scheduling with safe failure reporting.
Design correction: a new child cannot rely on an older daemon rejecting unknown fields. A token-authenticated capability check prevents a wrong or incomplete repository set from being created.

Sizing and phase count

Estimate: 170–240 gross non-test implementation lines. This includes shared schema and capability shape, selector and repository preparation, route convergence, bundled MCP changes, and shipped-skill changes. Tests and docs are additional.

Exactly one phase is appropriate. Schema, advertised capability, tool preflight, route handling, and skill guidance form one compatibility contract. Splitting them would leave either a dead daemon surface or operational guidance that the running tool cannot safely follow.

Dependency graph

Concurrency: none. Merge order: planning PR, then Phase 1. The task depends directly on the active planning session so its file pointers resolve only after this plan reaches the default branch.

Fixed contracts

  • Public repository and additionalRepositories are optional; omission uses the caller checkout.
  • Selectors are absolute paths or unique workspace basenames. Ambiguity lists candidates and never chooses first.
  • resolveTaskRepoSet remains the canonical identity boundary.
  • Explicit selectors verify daemon support before creation; default calls add no preflight.
  • The effective ship harness is resolved before storage and attachments require multiRepoDispatch.
  • Calling-session identity remains env, sessionId, and cwd, independent of the target.
  • Foreman's all-repository allowlist and all durable task mechanisms remain unchanged.
