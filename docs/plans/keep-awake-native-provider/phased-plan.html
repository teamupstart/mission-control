Source plan and human decision

Source: docs/plans/keep-awake-native-provider/plan.md.

The user selected recommendation 1 from the archived alternatives report and asked to schedule it through the phased-plan workflow. The fixed goal is in-process IOKit owned by the daemon, with normal screen dimming and locking. Electron ownership, synthetic activity, display-sleep inhibition, persistence, and automatic command fallback are out of scope.

Investigated repository findings

  1. KeepAwakeManager currently combines transition truth and child mechanics. Extract the provider without creating a second owner.
  2. provider is live wire state, not persisted, and React does not branch on it. Appending iokit is compatible.
  3. src/server/index.ts already constructs and stops exactly one manager.
  4. The bundle runs under standalone Node 24+ and Electron 43's Node 24 utility process. Stable Node-API serves both.
  5. esbuild cannot inline `.node`; packaging includes dist/**/*, so the build must copy a deterministic native artifact.
  6. Vite clears only dist/web, leaving dist/native intact.
  7. node-gyp is transitive only and must become a direct development dependency.
  8. Linux CI and Playwright require MISSION_KEEP_AWAKE_BIN to exercise the full UI without touching real power state.
  9. Ordinary tests must not call IOKit. Real assertion behavior remains a controlled macOS receipt.
  10. No UI, route, SSE event name, database, saved config, or restore path needs to move.

Sizing estimate

Estimated non-test implementation is 320-480 lines: 90-150 native addon and binding, 60-100 conditional build/copy/loading, 130-190 provider and manager adaptation, and 40-60 shared-type, smoke, package, and runtime-comment work. Tests and product docs are excluded.

Phase-count decision

Create exactly one phase. Splitting the addon would land an unused binary and packaging contract. Splitting the manager first would retain the failing provider or create temporary duplicate ownership. The addon, provider switch, package path, proof, docs, and real receipt are one reviewable rollback boundary.

Merge order and release gate

The Phase 1 Mission Control task depends directly on this planning session. It remains backlogged until the planning PR merges these files to the default branch. Phase 1 then lands the complete provider replacement in one implementation PR. No preparation or cleanup phase follows.

Cross-phase contracts

  • The daemon stays the sole owner in packaged, browser, adopted, standalone, and LaunchAgent modes.
  • Production Darwin defaults to IOKit. The explicit command override is test-only and never an automatic fallback.
  • Only user-idle system sleep is inhibited; display sleep and user activity are never asserted.
  • on follows successful create, off follows successful release, and failures stay visible and bounded.
  • Every daemon starts off. The native module is side-effect free on load and uses stable Node-API.
  • Linux does not compile or call IOKit. No database, saved config, route, event name, or UI ownership changes.
  • A denied assertion stops rollout and records evidence instead of invoking evasive alternatives.

Final verification strategy

  • Provider and manager unit tests with injected native and command fakes.
  • Existing HTTP, Registry/SSE, reducer, render, and Electron lifecycle tests.
  • Existing Keep Awake Playwright vertical slice through the Linux-safe command fixture.
  • npm run typecheck, npm run lint, npm test, npm run build, and npm run smoke.
  • npm run package on macOS arm64 and a packaged utility-process load check.
  • A real managed-Mac receipt proving normal lock, continuing work, disable release, crash release, restart off, and no caffeinate child.

Final compatibility audit

  • Every approved source-plan requirement is owned by Phase 1.
  • The provider boundary, native implementation, and package path land together.
  • The explicit command override preserves Linux browser proof without real power changes.
  • iokit extends live vocabulary only; no historical row or archive is rewritten.
  • The phase ends operable and has no undocumented cleanup dependency.
  • All task paths will be checked against the pushed planning commit before scheduling.
