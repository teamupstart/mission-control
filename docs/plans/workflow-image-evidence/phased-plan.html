Phased implementation plan

Native image evidence for workflow reviewers

Three serial merge units turn explicit screenshots into immutable, citable Persona evidence without moving the pull-request stage or committing proof artifacts.

Approved scope · scheduling after publication

Approved decisions

Complete V1 intake: dashboard upload and session-attributed agent registration.

Formats and lifetime: PNG, JPEG, GIF, and WebP, retained and pruned with raw workflow evidence.

Execution: every phase task uses Codex gpt-5.6-sol with xhigh reasoning.

Why three phases

The feature crosses provider protocols, secure local files, additive SQLite migrations, workflow state, retention, four dashboard entry points, and browser proof. Three phases isolate the riskiest contracts while keeping the agent path and dashboard path operable at their merge boundaries.

Cross-phase contracts

Runner to workflow

  • Omitting images leaves existing provider input byte-compatible.
  • Image-bearing calls validate every file and never downgrade to text-only.
  • Provider order, digest, MIME, byte limits, and stable ids are fixed before workflow intake ships.

Backend to dashboard

  • The browser sends opaque upload ids, captions, client ids, and issued repository slots, never paths.
  • Run detail exposes metadata and an authenticated body route; export remains metadata-only.
  • Normal repair does not inherit old screenshots. Historical reuse is an explicit new staged item.
  • A changed digest or caption is fresh evidence even when Git bytes are unchanged.

Fixed safety invariants

  • Personas stay tool-less and receive images only as native model inputs.
  • Evidence cannot escape an issued repository root and is never committed automatically.
  • Persona review stays before the authored pull-request action.

Verification and publication

  1. Each phase runs focused Node tests with the mandatory state preload plus typecheck and lint.
  2. Provider and runtime changes run build and smoke. Backend lifecycle changes also run the full unit suite.
  3. The dashboard phase runs focused and full Playwright against the built daemon and fake agents.
  4. The browser test must fail if only metadata arrives and pass only when actual PNG bytes reach both fake provider boundaries.
  5. Generated proof screenshots stay in e2e/.artifacts/workflow-image-evidence/ and remain uncommitted.

Final phase audit

Every approved requirement has one owner. Phase 1 owns transport, Phase 2 owns durable evidence and the complete agent path, and Phase 3 owns human intake, audit presentation, E2E proof, docs, and stale-memory correction. Dependencies are strictly planning session → Phase 1 → Phase 2 → Phase 3.
