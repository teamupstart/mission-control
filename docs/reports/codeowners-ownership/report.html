Ownership assessment · 25 August 2026

One default ownership rule, with one access gap

Use @teamupstart/delivery-squad and @mancej for every path. The team slug and individual are confirmed against the live repository. GitHub currently recognizes @mancej as an effective owner, but the Delivery Squad has only pull access and needs an explicit write grant before GitHub can treat the team as a code owner.

Implemented rule

# Default owners for every path in the repository.
* @teamupstart/delivery-squad @mancej

The file lives at .github/CODEOWNERS, GitHub's highest-priority supported location. Both owners are on the same pattern so they both apply to every changed file, including the CODEOWNERS file itself.

Operational gap

Delivery Squad needs write access

The live repository team list reports Delivery Squad with pull permission. GitHub's CODEOWNERS documentation requires users and teams to have explicit write access, even when individual team members have stronger access through another route. Until that grant is made, the team mention remains in the rule but GitHub will not assign it as a code owner.

The active enterprise ruleset currently requires one approving review, but its require_code_owner_review setting is false. CODEOWNERS will therefore drive automatic ownership and review requests for valid owners, not create a code-owner approval gate. No repository access or ruleset setting was changed in this task.

Limits

GitHub access, team membership, pull requests, and rulesets are live observations and can change. This assessment did not establish an internal policy requiring specialized path owners, and it did not change GitHub permissions. A repository administrator should grant Delivery Squad write access if the team is expected to receive code-owner requests. Enabling required code-owner approval is a separate governance decision.
