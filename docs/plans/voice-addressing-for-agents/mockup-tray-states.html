Tray icon states and tray menu

macOS shows its orange microphone dot whenever the mic is open, so it cannot say whether Mission Control is acting on what it hears. The tray icon must make four states obvious even while the window is minimized: listening, muted, auto-muted for a call and push-to-talk active. Voice adds them to the existing icon (src/main/tray.ts) rather than adding a second one, and a click on the icon mutes.

Fixed in every variant: one tray item, the need-you count still beside it, the existing menu rows untouched, and with the voice flag off the icon is exactly today's. What varies is how the state is drawn (shape, colour, words, motion) and how click-to-mute coexists with the menu, because today every click opens the menu. Template images are monochrome and macOS recolours them for dark, light and tinted menu bars; a coloured icon is a non-template image that the app must supply per appearance. Voice rows added to the menu carry a green edge in these mock-ups only.

  • Template images throughout: macOS recolours them for dark, light and tinted menu bars, so there is no appearance code and nothing to keep in step with nativeTheme.
  • Mission Control's own mark leaves the menu bar while voice is on, and the operator has to learn four 16px glyphs. Listening and push-to-talk differ by two small arcs.
  • State is carried by shape alone, so it survives colour blindness, the Reduce Transparency setting and a tinted bar.
  • Left-click-to-mute means dropping tray.setContextMenu, which on macOS makes every click open the menu, for separate click and right-click handlers. Operators used to clicking for the menu will mute by accident at first.
