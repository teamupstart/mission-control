Mission Control · phased implementation

Keep Awake mode

One merge-safe vertical slice from the daemon-owned power assertion to the live indicator, with the approved restart-to-off lifecycle.

Source of truth

The approved product behavior lives in the Keep Awake plan. The implementation may adapt where repository evidence requires it, but it must preserve the user-visible goal and this lifecycle decision.

Decision recorded: Keep Awake applies only to the current daemon run. A daemon restart, crash, or quit resets the mode to off. Mission Control neither persists nor reacquires the assertion.

Repository findings

  1. The inert leading segment of FleetPulse is already the connection indicator and is the correct trigger and dropdown anchor.
  2. Registry.snapshot(), Registry events, and useEventStream are the existing convergence path for daemon-owned live state. Keep Awake must use that path and clear to unknown on disconnect.
  3. The daemon owns long-lived services and ordered signal shutdown. It can stop the child gracefully, while caffeinate -w <daemon PID> covers abrupt exits.
  4. buildApp() appends optional injected managers for compatibility with focused route tests. The new manager follows that pattern.
  5. The topbar's rung-3 selectors currently preserve only the trailing review button. They must preserve both interactive pulse controls after the live segment becomes a button.
  6. The anchored panel must join the Electron title-bar no-drag selectors.
  7. CI and Playwright run on Linux, so tests need injected process seams and a MISSION_KEEP_AWAKE_BIN fixture override.
  8. No database, config write, startup restore, or automatic child restart belongs in the approved transient design.

Inside the phase

  1. Define append-only runtime status, event, snapshot, and request contracts. Add no persisted config.
  2. Implement KeepAwakeManager with direct spawn, exact -i -w arguments, serialized transitions, truthful failures, and bounded shutdown.
  3. Wire GET/PUT routes, Registry publication, SSE convergence, daemon startup seeding, and ordered cleanup.
  4. Replace the leading live segment with an accessible trigger and anchored switch dialog driven only by daemon state.
  5. Preserve both pulse controls through responsive compaction and add the panel to Electron no-drag coverage.
  6. Add unit, HTTP, SSE, render, Playwright, screenshot, README, runbook, and real macOS verification evidence.

Hard boundaries

  • Use ['-i', '-w', String(daemonPid)] with shell: false. Never add -d, -u, or -s.
  • Unexpected child exit becomes a visible error and is not silently restarted.
  • Every daemon starts off. No SQLite, app_config, startup restoration, or saved preference is introduced.
  • Unsupported production platforms refuse visibly. The environment override exists for the built Linux test fixture.
  • Away mode, Recurring Missions, Electron IPC, and future platform providers remain unchanged.

Request and status flow

The write response waits for the completed transition. Registry plus SSE remains the only browser state source and makes every open dashboard converge. If SSE disconnects, status becomes unknown and reconnecting takes precedence over any stale awake label.
