Investigation report · 21 August 2026

Codex interrupts were invisible in the conversation

Finding: the interrupt worked, but Codex recorded it only as a rollout lifecycle event. Mission Control's transcript parser discarded that event, while Claude supplied its own visible user message. The parser now projects Codex's measured interrupt record into the same [Request interrupted by user] message.

Cause and correction

A real Codex rollout contains an event_msg whose payload is turn_aborted, with reason: "interrupted" and a stable turn_id. The Codex transcript adapter previously admitted only user_message and agent_message records. Its only use of turn_aborted was to clear activity narration, so the dashboard had no conversation row to render.

The correction is in src/server/harness/codex/transcript.ts. It creates a user-role transcript message only for the measured reason: "interrupted", keys it as interrupt:<turn_id> for stable window de-duplication, and resets assistant grouping at that boundary. Other future abort reasons are not attributed to the operator.
