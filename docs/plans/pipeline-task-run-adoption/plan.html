Pipeline Task Run Adoption and Card Visibility

Show the Pipeline run owned by a task on its interactive Engineer host card, and repair a prompt-slug mismatch only through an authenticated, launch-bound adoption handshake.

The host remains interactive. The provider worker remains the only process-owned Pipeline session. Provider projection remains the only completion authority.

Answer and boundaries

What changes

  • TaskSummary.pipelineRun carries task ownership to the host.
  • A new adopt_pipeline_run tool accepts only the observed slug.
  • The daemon derives and validates task, session, repository, and provider.
  • Board, rail, and Console show a task-owned link with copy distinct from the worker chip.

What stays fixed

  • Session.pipeline stays null on the SDK host.
  • The host composer stays available.
  • Workers retain external-driver semantics.
  • Only provider projection settles the task.

Target flow

Guarded adoption contract

Authority

  1. Caller is the task's live SDK host.
  2. Task is active and kind pipeline.
  3. Target is observed under the task's repository and provider.

Compare-and-swap

  1. Same target is an idempotent success.
  2. A different current reservation must not exist in projection.
  3. No other active task may own the target.

Failure behavior

Refuse without mutation

  • Unknown target
  • Target owned by another task
  • Current reservation already observed
  • Stale or wrong host
  • Cross-repository or provider mismatch

Safe retries

  • Same-run replay succeeds idempotently.
  • Persistence failure keeps the old durable binding.
  • An already-processed target enters the ordinary settlement path immediately.

Verification and acceptance

  • Reproduce in the built dashboard before code changes.
  • Host card shows the task run on Board, rail, and Console.
  • Host remains messageable and outside the provider cluster.
  • Worker retains Session.pipeline and worker chip copy.
  • Adopted processed run settles the task.
  • Every refusal leaves the old binding unchanged.
  • Desktop and 420-pixel layouts are visually inspected.
  • Typecheck, lint, unit, build, smoke, and focused Playwright pass.

Out of scope

No AI Conductor change, manual run picker, multi-repository Pipeline task, downstream model or effort change, managed-to-Terminal fallback, or dashboard reassignment of a live reservation.
