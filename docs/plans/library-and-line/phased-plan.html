The Library and the Line - phased implementation

Source plan: plan.md (rendered: plan.html). The operator's submitted decisions are recorded there as requirements; the follow-up decision was "create phased implementation plan, schedule the phases, PR the artifacts, merge on green CI".

Incorporated decisions

  1. One product: Library (authoring home) + Line (execution surface on the Fleet).
  2. Runs and Ensembles re-home to #/runs and #/ensembles; never Library shelves. Strategy launchers shelve in the Library.
  3. Session cards unchanged in data, layout, and size, in every state.
  4. UsageBar row retired for a cost chip + spend popover; FleetCost unchanged.
  5. Drawers: toggle semantics, hard cap of three rows (~38vh), internal scroll, board pushes down and returns.
  6. The everything-palette is the final phase.

Investigated findings

  • MissionRoute is the single router union (useWorkflowRoute.ts); workflowsToggleRoute implements the page-toggle chord with guards. New pages extend this union.
  • App.tsx renders the UsageBar second row delegating to FleetStrip.tsx; fold state persists via usageBar.ts.
  • useEventStream.ts handles every ServerEvent exhaustively; cost_fleet is the precedent for a server-computed, change-gated line_summary event (registry folds ~registry.ts:3779).
  • Drawer building blocks exist: runs (run-model.ts, pipeline-bits.tsx, WorkflowLadder.tsx) and ensembles (ENSEMBLE_RESULT_RENDERERS, DecisionPanel.tsx).
  • ⌘K today searches settings only (settings-search.ts).
  • e2e specs select by role/label/placeholder with fake agents; Electron geometry tests measure fleet height on macOS.
  • Discrepancy noted: mockup topbar filter and sample counts are illustrative; phases bind to contracts, not sample data.

Dependency graph and concurrency

P1 gates nothing. P1, P2, P3 run concurrently; P4 after P2 and P3; P5 after P4.
  • Group A (P1, P2, P3): mutually independent. P1 owns the topbar's right side, P2 the topbar's left segment and the router union, P3 the fleet content area and the new SSE event. The only shared file is App.tsx, in disjoint regions; merge in any order.
  • P4 needs P2 (a destination for the retiring authoring tabs) and P3 (a strip to hang drawers from).
  • P5 needs P4 directly; P2 and P3 arrive transitively.

Cross-phase contracts

  • Routes: P2 owns #/library; P4 owns #/runs, #/ensembles, and permanent #/workflows/* redirects; P5 navigates only to published routes.
  • Event: P3 owns line_summary / LineSummary in src/shared/ (append-only); P4 consumes for drawers; P5 reads the store.
  • Cost: P1 owns the chip + popover; P3 reuses FleetCost.prsToday on the Shipped stage without new wire contracts.
  • Interim state: after P2 and before P4, the Workflows page is a valid two-tab execution page (runs, ensembles).
  • Keyboard: P2 retargets the page toggle; P4 adds fleet-scoped drawer esc; P5 owns ⌘K.

Final verification

After P5: npm run typecheck && npm run lint && npm test, npm run build && npm run smoke, npm run test:e2e (all phase specs), npm run test:electron on macOS. Manual pass against the mockups: two homes, drawer semantics (cap, scroll, close paths), every legacy deep-link redirect, cost chip parity with the retired FleetStrip, README matching every shipped surface.
