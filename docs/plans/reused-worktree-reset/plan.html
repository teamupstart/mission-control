Implementation plan

Reset reused worktrees before dispatch

Approved for phased implementation and scheduling

Dashboard decision recorded 2026-08-20: create the phased implementation plan and schedule its dependency-linked task.

Decision: ordinary unpinned tasks start from a freshly fetched, frozen remote-default SHA, and native pool slots must be clean and detached before their lease is finalized. Explicit pinned bases remain exact and bypass remote-default selection.

What the investigation established

The affected task was not scheduled over another live task or session. It held the slot's only active lease. The reused checkout reached the requested commit but retained the previous occupant's branch and upstream because native reset does not detach HEAD.

When the agent renamed that inherited feature branch, the registry's valid branch-takeover guard started a new work episode and invalidated the task binding. The prevention boundary belongs in dispatch and allocator verification, not in weaker ownership rules.

Contract mismatch: docs/worktrees-and-checks.md describes native slots as exact-commit, detached worktrees. New slots satisfy that contract; warm-slot reset and verification do not.

Dispatch flow after the change

  1. Verify an explicit pin or fetch and freeze each repository's remote-default SHA.
  2. Reserve an exclusive slot for that exact commit.
  3. Create the slot detached, or force-detach and reset a warm slot.
  4. Verify identity, exact HEAD, cleanliness, empty occupancy, and detached HEAD.
  5. Persist all task resources and spawn the agent only after every repository passes.

Any failed fetch, reset, or proof stops before launch. An explicit pinned dispatch enters at slot reservation with its supplied SHA.

Required behavior

Resolve bases before provisioning

  • Run a bounded git remote listing. Only a successful listing that omits the exact name origin establishes no origin; a timeout, spawn failure, overflow, signal, or nonzero result fails dispatch.
  • With a configured origin, fetch it, resolve origin/HEAD with the existing main/master fallbacks, and freeze a full SHA.
  • A configured-origin fetch or resolution failure is a dispatch failure, not permission to use stale local state.
  • A repository that genuinely has no origin keeps local-repository support by freezing its current local HEAD.
  • Resolve all primary and attached repository bases before taking the first tree.
  • Keep an explicit pinned SHA unchanged, including ensemble and check paths.

Detach as part of native reset

  • Force-detach the checkout at the exact requested SHA before the destructive reset and clean.
  • Preserve the old local branch ref. Pool reuse should release a branch name from the checkout, not move or delete it.
  • Keep git clean -fd, never -fdx, so ignored dependencies and build caches remain warm.
  • Contain this behavior in NativeWorktreeGit.reset; do not change ensemble snapshot restoration semantics.

Fail closed on verification

  • Add detached state to native inspection.
  • Require detached state before both finalizeLease and completeRelease.
  • Quarantine an attached or unprovable slot. Do not persist it to the task or spawn the agent.

Regression and validation bar

  1. Reused attached slot becomes detached and reports branch: null.
  2. Old branch ref is preserved at its prior commit.
  3. Return reaches fresh remote default, removes nonignored residue, preserves ignored caches, and detaches.
  4. Attached or unprovable detached state quarantines and cannot finalize a lease.
  5. Stale local main does not beat newly fetched remote default.
  6. Configured-origin fetch failure leaves no worktree or agent.
  7. No-origin repositories still use frozen local HEAD, but a failed or unknown origin probe fails closed.
  8. Explicit pins remain exact after remote advancement.
  9. Multi-repository base resolution is per repo and all-or-nothing.
  10. The first agent-created feature branch stays in the bound work episode.

The exported low-level provisionWorktree() helper keeps its current local-HEAD default when no exact base is passed. Production TaskDispatcher owns the new remote-default policy and passes the resolved SHA into that helper.

Delivery shape

Ship this as one atomic implementation task. Base resolution, native reset, detached verification, tests, and documentation form one invariant. Splitting them would permit an intermediate merge where a task can still launch from a Git state the dispatcher or registry interprets incorrectly.

The task must not alter current live task/session records, delete branch refs, remove worktrees, or retroactively repair cancelled tasks.

Established and not established

Established: exclusive ownership, inherited branch state, the rename-to-invalidation sequence, missing detached reset and verification, and the difference between Return's remote-default target and acquisition's local-HEAD target.

Not established: the fix has not yet been implemented or reproduced in a test, fetch latency was not benchmarked, and no live cancelled-task or session record was repaired.
