Phased implementation index

Reset reused worktrees before dispatch

One phase, one scheduled task
An ordinary scheduled task freezes a fresh remote-default base before provisioning, and no native slot can be leased or returned as available unless it is clean, exact, and detached. Explicit pinned bases remain exact.

Source and incorporated decision

  • Approved source: docs/plans/reused-worktree-reset/plan.md
  • Human decision submitted 2026-08-20: create the phased implementation plan and schedule its dependency-linked task.
  • Investigation: docs/reports/stale-worktree-session-close/report.html

Sizing and phase count

Estimated production change: 90 to 150 materially changed or added non-test lines. This covers dispatch base resolution, native detached inspection/reset, and manager verification. It excludes tests and documentation.

The estimate is below 200 lines and all changes form one lifecycle invariant. The phase-sizing rule therefore requires exactly one implementation phase and one one-shot task.

Why not split: separating base resolution from detachment would create an intermediate merge where a task can still launch from a Git state the registry interprets incorrectly.

Dependency graph and merge order

There are no concurrency groups or inter-phase merge choices. The implementation task stays backlogged until the planning PR merges.

Repository findings incorporated

  1. Remote-default policy belongs in TaskDispatcher; the low-level provisionWorktree() helper keeps its local-HEAD default for direct callers.
  2. Only a successful remote listing can establish that origin is absent; probe failure or uncertainty aborts dispatch.
  3. All attached-repository bases must resolve before the first lease.
  4. Pool reset detaches before invoking the existing hard-reset and clean -fd helper, preserving the old branch ref and ignored caches.
  5. Detached state becomes an independently observed manager gate on acquisition and Return.
  6. The registry's branch ownership rotation and ensemble snapshot restore semantics remain unchanged.

Cross-phase contracts and final verification

  • TaskDispatcher owns scheduled-task base policy.
  • WorktreeManager owns lease transitions and quarantine.
  • NativeWorktreeGit owns pool reset and detached observation.
  • Explicit pins, old branch refs, local-only provisioning, and ignored caches remain compatible.
  • Focused regression tests, typecheck, lint, full unit suite, build, and smoke must pass.

No Playwright run is required unless implementation introduces a visible UI change.

Final compatibility audit

  • Every approved requirement is owned by Phase 1.
  • The scheduling decision is incorporated with no unresolved alternative.
  • Inspector feedback is incorporated in the fail-closed origin-probe contract.
  • No schema, generated output, other repository, or unpublished API is required.
  • No later cleanup phase is needed to leave the repository operable.
