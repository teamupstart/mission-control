Backlog bulk edit: three mockups

Select several backlog cards, then change their fixed-choice fields together: priority, labels, kind, agent, model, effort, After work, autopilot, and dependencies. Freeform fields (title, intent) and repositories stay one task at a time. All three options share the selection model below and differ only in how the bulk edit is presented.

Shared by all three: how you select

  • Click on a card still opens it for editing, exactly as it does today. ⌘/Ctrl-click adds a card to the selection or removes it. Shift-click selects every card between the last one you clicked and this one, in the column's order.
  • Drag to select starts on empty column space (the gaps between cards, or below the last card) and draws a marquee. Every card it touches joins the selection. A drag that starts on a card still moves or assigns that card, so today's drag-to-reorder and drag-to-agent keep working.
  • Selected cards show a green edge and a check in the corner. The checkbox also appears on hover and on focus, so selecting works by pointer alone, and Space on the focused checkbox toggles its card for keyboard users.
  • Esc or clicking empty board space clears the selection. ⌘A while the backlog has focus selects every card.
  • Only backlog tasks can be selected, so every edit falls under the rules the single-task editor already enforces: kinds that can wait in the backlog, effort levels the chosen agent supports, and dependencies that can't point at the task itself.

A. Selection bar and a bulk-edit dialog

recommendedstaged, apply once

When a selection exists, a bar docks at the bottom of the backlog column. Edit 3 tasks… opens a dialog that lists every bulk-editable field. Each field starts as leave as is and shows Mixed when the selected tasks disagree. Changing a field ticks its row, and only ticked rows are sent. Labels and dependencies are add / remove edits, not replacements, so a task's other labels survive. The daemon applies everything in one request, so either every task changes or none does.

Strengths

  • Nothing is written until you press Apply, and the edit is all or nothing. A slip of the mouse can't recolour twelve cards.
  • Every field is on one screen, so edits that depend on each other (agent then model then effort) can be made together and checked together.
  • Built from existing parts: the dispatch modal's pickers and the Overlay shell.

Costs

  • Changing one field on many tasks takes three steps (select, open, apply).
  • The dialog covers the board while it is open.

B. The column header becomes a command strip

instant, with undo

While cards are selected, the backlog header turns into a strip of field chips. Each chip opens a small popover that shows how many selected tasks have each value. Picking a value applies it immediately to the whole selection, and a toast offers Undo. Labels use tri-state checkboxes: filled if every selected task has the label, partial if some do. Nothing covers the board, and the selection persists so you can make several edits in a row.

2. Labels use tri-state boxes, so adding "q4" never strips "docs" from the one task that has it. Agent, Model and Effort work the same way, and a choice the new agent can't run is shown disabled with the reason.

Strengths

  • Fastest for the common case: select, chip, value. Two clicks.
  • The board stays visible, so you see the cards recolour as you go.
  • Keyboard friendly: number keys in each popover.

Costs

  • Edits that depend on each other (agent → model → effort) are separate writes, so an intermediate state can be refused and you fix it in steps.
  • Nine chips crowd a 292px column. The strip wraps to two rows, or the column has to widen.
  • Needs a real undo (a snapshot of each task's previous values), which is new server work.

C. Side inspector with a change preview

staged, per-task preview

Selecting two or more cards opens an inspector on the right edge of the board, like a design tool's multi-select panel. The form mirrors the dispatch modal's sections. Mixed values show as Mixed with a breakdown underneath. Changed fields get a dot, and a preview table lists each task's before and after values, including tasks a change would skip (for example, an effort level their agent can't run) so you decide knowingly. Apply writes it all in one request.

Strengths

Costs

  • On a narrow window it has to fall back to an overlay, which makes it a variant of A.
  • Heavy for the most common edit (one priority change).
