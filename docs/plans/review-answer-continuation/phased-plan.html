Durable review answer continuation

One vertical phase, released only after its planning artifacts are published.

Approved source

The approved solution uses the existing pending-turn outbox after an MCP review wait detaches. The recorded follow-up requires this phased plan and a dependency-linked Mission Control task.

The planning checkout already contains candidate implementation. The phase agent preserves conforming inherited work and changes only gaps found on the default branch.

Repository findings

Review persistence, lifecycle, HTTP transport, MCP cancellation, and pending-turn delivery are owned by existing modules. SQLite must record the handoff, while the pending-turn manager remains the only later-turn delivery owner. A separate terminal writer or a timeout-only fix would violate the approved design.

Sizing and phase count

The expected implementation is 350 to 450 gross non-test lines. It stays in one phase because persistence, session ownership, cancellation races, result parity, restart recovery, and outbox delivery form one transaction-sensitive vertical slice. Splitting them would merge a dead marker or an untrustworthy consumer.
