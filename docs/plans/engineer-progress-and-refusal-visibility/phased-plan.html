Phased Plan: Engineer Progress and Refusal Visibility

Source: Engineer Progress and Refusal Visibility · Status: Ready to schedule

Two independent repository-owned phases restore provider progress and make recoverable refusal visible. Both release after this planning PR merges and may run concurrently.

Implementation outcome

Restore live DECIDE progress for managed Codex Engineer runs at the provider source, prevent the reproduced artifact-stem refusal when the canonical workflow is followed, and make any remaining recoverable refusal unmistakable on Mission Control's shared Pipeline surfaces.

Incorporated decisions

  • The operator explicitly asked to plan and schedule both repository fixes.
  • AI Conductor owns lifecycle emission, completion evidence, artifact identity, and land behavior.
  • Mission Control owns commission projection and visible presentation only.
  • No AI Conductor planning skill is used.
  • A duplicated launch-prompt workaround is rejected in favor of one durable provider contract.

Repository findings

  1. The validated lifecycle CLI already exists. The canonical Engineer skill omits its no-hook use.
  2. The worktree command already returns and persists the exact Engineer run id and feature slug.
  3. Land intentionally enforces the reserved feature stem, while the skill lets artifacts choose a shorter stem.
  4. Mission Control preserves the provider refusal as a generic error and clears it on the next event, but does not retain the error's event-kind provenance.
  5. The shared commission view only halts terminal failures, so recoverable refusal still looks like authoring. Generic error shape is not a safe substitute for provenance.
  6. No provider event, route, ingest, migration, or replay change is required. Mission Control adds one optional consumer projection field.

Size and phase rationale

Estimated non-test implementation and maintained documentation: 220-350 lines. AI Conductor accounts for roughly 130-210 lines; Mission Control accounts for 90-140. Tests are excluded and expected to add 180-300 lines.

Two phases keep provider ownership and browser presentation separately reviewable. Each repository remains operable alone, and the fixed existing interface allows parallel implementation and either merge order.
