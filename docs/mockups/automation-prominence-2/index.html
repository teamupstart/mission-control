Mission Control - UI exploration - 2026-08-01 - round 2

Building vs. watching: one product from the Library and the Line

Round 1 asked how to make workflows, Personas and ensembles visible. Round 2 starts from the split the operator named since: Workflows, Personas and Actions are how you build automation; Runs and Ensembles are the work actually being done. The current UI files all five under one page as sibling tabs. The flagship concept merges round 1's Library and Line into a single product shaped by that split, and two new concepts attack the same problem from different axes - rules and stories. The cost bar's second topbar row is in scope everywhere; session cards are untouched everywhere.

01What changed since round 1

Actions exist now. A workflow stage can type a reusable instruction into its session - the built-in Pull Request action ships in No-Mistakes v8 - so a run acts, waits on the session, and resumes. "Waiting for action" is a first-class run state no mockup accounted for. SessionActionLibrary.tsx · workflow.ts
Five tabs, two natures. The Workflows page now holds workflows / personas / actions / runs / ensembles as equals. Three are authoring surfaces, two are execution monitors; the tab strip says nothing about which is which. WorkflowPage.tsx · useWorkflowRoute.ts
Ensembles hand off into runs. A decided ensemble can open a workflow run on the winner (trigger source "ensemble"), so the two execution systems already flow into each other - across two tabs that never point at one another. ensemble.ts workflow_handoff · ExternalProvenance
The cost bar earns its complaint. A foldable second topbar row (UsageBar → FleetStrip) spends permanent chrome on stats, runway meters and an automation line that are consulted occasionally, not every glance. App.tsx UsageBar · FleetStrip.tsx

04Recommendation

Ship concept 1. It is the only one that resolves the stated problem with the machinery the app already has: every phase reuses an existing editor, renderer or route, the five-tab page dissolves into homes that match the build/watch split, and phases 1-3 each leave the app whole. Round 1's palette (concept 4 there) survives intact as phase 5; round 1's rail is subsumed by the Library segment.

Steal from 2 and 3 later, without adopting them. Standing Orders' pause switch and sentence framing would make a strong Library shelf header for missions and sources ("what runs without me"), and Threads' per-work cost accounting ("this fix cost $4.10") is the honest number the spend popover should eventually show per PR. Both graft onto concept 1; neither blocks it.
