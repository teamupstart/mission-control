What the current repository changed

  1. The current tour is still singular: a 756-line controller plus roughly 330 App lines and hardcoded Settings, palette, overlay, route, API, target, and CSS entries.
  2. The tour HTTP routes moved to src/server/routes.ts:5657-5770, but their fixed-input and strict-cleanup safety contracts remain.
  3. MissionRoute already preserves Library shelf and asset selection, so no parallel snapshot field is needed.
  4. App already owns complete SSE-backed workflow-run summaries. The second tour selects in memory and adds no history fetch.
  5. Almost all target nodes already exist. Shared renderers need optional ref seams; the Action chips and contract sentence need one labelled semantic region because they are currently siblings.
  6. The existing router remains the only dirty-draft gate. Tour start preflights navigation and stays inactive when that gate refuses.
  7. Run detail and session Workflows navigation already have App owners. The tour invokes them directly instead of driving clicks.
  8. No persistence, migration, or ServerEvent change is required.
  9. Coachmark geometry is proven in Playwright, alongside the required UI behavior spec.
  10. docs/workflow-system.md still says v9 while No-Mistakes Review v10 is current.

Size and split rationale

Estimated production implementation: 2,300 to 3,100 materially added or changed non-test lines. About half is engine, App, registry, route, entry-point, target, and skin extraction. The rest is the Library definition, navigation/runtime adapter, nineteen target registrations, run fallback behavior, and feature styling.

One combined pull request would mix the fragile Driver.js lifecycle refactor with six newly instrumented UI surfaces and twenty tour screens. The two-phase boundary lets the unchanged See-work tour prove the engine first. A third phase would be harmful because target plumbing without the Library definition is dead code, while a definition without its targets exposes an incomplete feature.
