Workflow image evidence has no transport

Question: why can workflow Personas read a session's written evidence but still reject visual work for lack of screenshots, and where should the fix live?

Finding. The transcript reaches every Persona, with each turn clipped to 3,000 UTF-8 bytes. Images do not. A submission persists a text-only evidence snapshot and the Persona runner accepts one string, so no screenshot path, MIME type, bytes, or image content reaches the reviewing model. The correct fix is native, explicit, per-submission multimodal evidence. PR attachments and committed documentation images are later publishing choices, not the review transport.

Recommended product boundary

Make visual evidence an explicit submission input. Each image needs a human-readable caption, a repository scope, bounded MIME and byte metadata, and an immutable digest. The daemon copies and owns the bytes for the life of raw workflow evidence. Persona prompts name the image and caption while the runner sends the corresponding pixels through the provider's native multimodal input.

  • Offer dashboard upload at every initial submission, resubmission, and run-again entry point.
  • Offer a session-attributed Mission MCP tool for an agent to register checkout-relative, gitignored screenshots before an automatic Foreman completion.
  • Include image digests and captions in the evidence fingerprint. A new screenshot is fresh evidence even when the code bytes did not change.
  • Append image to the persisted evidence-reference vocabulary so verdicts can cite an image id and state the observed visual fact.
  • Show thumbnails, captions, availability, and pruning state in run detail. Keep raw-image deletion aligned with the existing raw-evidence retention sweep.

Rejected shortcuts

ShortcutWhy it fails
Open a pull request before review.No-Mistakes Review v8 intentionally creates and verifies the PR after Persona review. Moving it earlier changes authored workflow semantics and still leaves Preview workflows without image evidence.
Commit screenshots under docs/images/.Proof-of-work images are evidence artifacts and repository rules forbid committing them. A binary Git diff also does not give a tool-less Persona the pixels.
Parse every image-looking path out of transcript prose.It is ambiguous, reads paths the user never explicitly submitted, creates a local-file disclosure risk, and cannot freeze a mutable file reliably.
Grant the reviewer filesystem tools.It widens the security boundary for untrusted transcript content, is unsupported by the Codex headless runner, and makes image availability depend on a checkout that retention or cleanup may remove.
Increase the transcript limit.More text is still not image content. The existing 3 KB per-turn limit is a separate reporting-quality issue.

Limits of this investigation

No live provider call was made, so the strictest count, dimension, and aggregate-byte limits still need a focused compatibility check against the installed Claude and Codex transports during implementation. The installed Codex CLI advertises repeatable codex exec --image <FILE>, and the installed Claude Agent SDK accepts an async user message whose content can contain image blocks, but the print transport still needs its own one-shot stream-json implementation and contract test. This investigation also did not choose whether agent-side evidence registration must ship in the first increment; that is presented as a plan decision.
