Why not split it?

A bootstrap without enforcement leaves nonstandard commands dependent on convention. Enforcement without a bootstrap repeats the authoring hazard. Tests and docs define the same behavior and belong in its merge unit.

Dependency graph and merge order

There is no internal concurrency group or phase-to-phase edge. The implementation task depends directly on this planning session and remains backlogged until the plan PR merges.

Cross-phase contracts

  • envVar("HOME") remains the only alias resolver.
  • MISSION_HOME remains the preferred operator alias; HARNESS_HOME is only the lowest-priority test fallback.
  • Each worker owns one fallback temp root; files may select another fresh fixture before imports.
  • openDb() validates before returning new or cached connections.
  • Production exits test validation immediately and pays no filesystem-validation cost.
  • No phase deletes operator rows or changes state migration.

Final verification strategy

Run focused child-process isolation tests, the provider-column migration canary, typecheck, lint, and the full suite. The full run exercises bootstrap behavior across all 596 tracked test files and configured concurrency. Report wall time without treating one local sample as a stable benchmark.

No build, smoke, or Playwright run is required unless implementation expands into a runtime or UI surface. If it does, stop and revise the plan.
