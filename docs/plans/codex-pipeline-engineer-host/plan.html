Codex Pipeline Engineer Host

Let each Pipeline task choose Claude or Codex as its managed Engineer host. Codex runs through Mission Control's existing SDK session and invokes the Engineer skill directly.

Answer

conduct-ts engineer is not required

The managed route starts a Claude or Codex SDK session, then sends that host's native Engineer skill invocation plus the task intent. The skill uses deterministic conduct-ts primitives internally as needed, but Mission Control does not launch the standalone Engineer command.

Terminal remains an explicit Claude-only compatibility route. A managed SDK failure fails visibly and never falls back to Terminal.

Decisions

  1. task.agent is authoritative for managed Pipeline hosts.
  2. Eligible hosts come from shared SDK and skill capabilities, not a second agent list.
  3. Canonical runtime becomes agent-sdk; legacy claude-sdk input migrates on read.
  4. Model and effort remain host defaults; Conductor owns downstream choices.
  5. Terminal is Claude-only and rejects mismatched task data.

Acceptance

  • Standard and guided Dispatch can select Codex for Pipeline.
  • The dispatcher starts the fake Codex SDK and preserves the intent in turn one.
  • Claude uses the same provider-neutral path.
  • No managed failure invokes Terminal.
  • Provider completion and run reservation remain unchanged.
