Mission Control - UI exploration - 2026-08-01

Opening a diff file in the Files tab

The Diff tab tells you a file changed. The Files tab, one tab over, is where you read and edit it. Right now nothing connects them - you read src/web/components/DiffViewer.tsx in the diff, press f, and hunt for it again in a list of the whole checkout. Three placements for the link that closes that gap, each shown in a full-size frame of the real UI.

01What is already true in the codebase

The jump already exists. onOpenFile does files.select + requestFilesTab and is what a path in a transcript calls today. Nothing new has to be built to make the tab switch happen. App.tsx:541 · openSessionFile
The diff reader has no route to it. InlineDiffViewer takes three props - session, commit, requestNonce. It has never been handed a way to reach the Files tab, so the callback has to be threaded in. DiffViewer.tsx:47
The list row is one big button. Putting a second control inside it is invalid markup and unreachable for a screen reader, so option 2 must split the row in two. Options 1 and 3 leave it alone. DiffViewer.tsx:255
There is already a visual language for this. a.workspace-path - inherited colour, dotted rule, accent on hover - means "a path that opens in Files" everywhere in a transcript. styles.css:3409
The header bar has room. .diff-file-head is a flex row whose path is the only growing child; the list is a fixed 264px where .fp-dir is already truncating. styles.css:6502 · 6378
o is unclaimed. Every other single letter that reads as "open" is spoken for, but o is free if this wants a chord and a keycap. keybindings.ts

04Where I would land

Option 3, and then option 2 if one click matters. Option 3 is the only one that adds no vocabulary: the dashboard already has a single treatment meaning "this path opens in Files", the diff header is the one place printing a path that ignores it, and honouring it there is a smaller change than any new control. It also costs nothing in layout, which the 264px file list cannot say.

The real argument for option 2 is not decoration, it is that it halves the interaction: from the diff you can open any of the five changed files without first making it the one you are reading. If reviewers are jumping between files rather than following one, that is worth the row restructure and the 27px. The two compose - the same onOpenInFiles prop feeds both, and shipping 3 first does not close the door.

Option 1 is the safe pick if the worry is that nobody finds the feature. It is the loudest and the least surprising, at the price of putting a button where the app currently puts none.

05True of all three

Deleted files cannot be opened. The path is gone from the checkout, so the control is disabled with a tooltip rather than offering a jump that only produces an error in the Files pane.
Renames point at the new path. DiffFile.path holds the post-rename name, which is the one that exists on disk.
One shared callback. All three call onOpenInFiles(path), threaded from ConsoleDetail into InlineDiffViewer, landing on the existing files.select + requestFilesTab pair.
Grid layout has no Files tab. Cards open the diff as a modal. openSessionFile already handles that branch by setting filesSessionId instead - so the control works there too, or is omitted from the modal on purpose. App.tsx:557
Needs a Playwright spec. Click the control in the Diff tab, assert the Files tab is selected and showing that path. Selected by role and accessible name - no data-testid.
The keyboard walk stays. ↑/↓ and j/k keep moving the diff selection; whichever control ships must not steal those keys or the focus they depend on.
