Source and approved decisions

Source: Fast installed-app session bootstrap. The operator approved early Board serving with dedicated restoring cards and directly requested this phased plan and task schedule.

  • Use the daemon-served React app, not a separate local loading application.
  • Use a dedicated transient projection, not synthetic real sessions or dispatching tasks.
  • Move HTTP before awaited restore while keeping terminal discovery after it.
  • Keep SDK restore serial.
  • Fix SSE bootstrap ordering in the same merge unit.

Investigated findings

  • src/server/index.ts owns the full startup and shutdown sequence; the state-home lock remains before SQLite and serving.
  • The supervisor's required contract is register-or-evict before first terminal observation, not before HTTP.
  • The Registry and browser snapshot are the only live bootstrap. The new collection must move through shared types, Registry, SSE, and useEventStream together.
  • Background restore makes the existing snapshot-before-subscribe gap load-bearing.
  • The built E2E fixture already supports crash/restart and SDK idle-restore verification.
  • Early serving creates a new shutdown race that the supervisor must own.

Cross-phase contracts

  • State-home ownership and database open precede serving.
  • Real Registry sessions require a live terminal process or adopted SDK driver.
  • The restore projection is transient, bounded, and rebuilt from existing rows.
  • Success or existing register-and-evict failure settles before a provisional row retires.
  • Terminal discovery waits for the restore promise.
  • SSE subscribes before snapshot capture.
  • Restoring rows never participate in fleet automation, counts, selection, or actions.
  • Shutdown prevents later launches and cleans the in-flight restore through the supervisor.
  • Health means serving, not that every driver is ready.
