The approved goal and scope are in [plan.md](plan.md). The operator chose the daemon and browser experience, event-based Wayland qualification with tested press/release timestamps, bounded holds and release-time clipping (the operator accepts brief microphone opening after a delayed release), and capture backend selection by a real-desktop spike. Task pointers use this directory on the default branch.

S2 qualified no Linux capture package. S9 qualified the Mac callback only. The existing Speech 1 and 2 tasks own the speech manager and synthesis. The Linux supervisor must join their recovery contract before the player can advertise audio.

Estimate **2,000–3,650 gross non-test lines** assuming an existing desktop audio client or maintained binding works, and existing state, routes, browser components and speech manager remain reusable. A custom audio stack or an unqualified compositor changes that estimate. Record an unsuccessful spike and surface the decision before expanding scope.

## Merge graph and rationale

1. **Live microphone capture** ([phase-1-live-microphone-capture.md](phase-1-live-microphone-capture.md)). Direct upstream: addressing Phase 16. The standalone live listener introduces the shared daemon-side observation gate for every Linux live capture directive. Before a working observer exists, ordinary live use requires auto-mute explicitly disabled. An isolated Phase 1 test injects observations for renewal and expiry on a real microphone. Phase 3 repeats that test with the production observer. Keep selection and implementation together so a candidate must pass the full capture boundary.
2. **Daemon supervision and restart recovery** ([phase-2-daemon-supervision.md](phase-2-daemon-supervision.md)). Direct: Linux 1 and Speech 1. Distinguish OS identity, exit and durable job recovery from microphone timing. Before the observer lands, the daemon-run listener admits live input only with auto-mute explicitly disabled and all other capture gates satisfied. It can safely supervise a silent child before acoustic output lands.
3. **Global mute and call detection** ([phase-3-global-mute-and-call-detection.md](phase-3-global-mute-and-call-detection.md)). Direct: Linux 2 and addressing Phase 11. One Linux producer combines the two observations. A real call and a held key test the state transition together. Desktop event and audio-clock qualification is independent of output devices.
4. **Spoken playback** ([phase-4-spoken-playback.md](phase-4-spoken-playback.md)). Direct: Linux 2, **Spoken Responses for Voice - Speech 1: The speech job and ask aloud**, and **Spoken Responses for Voice - Speech 2: Mission Control voices**. Both upstream edges are explicit as requested. This phase qualifies the player’s real drain/stop behavior and acoustic isolation separately from crash-safe ownership.
5. **Setup and browser feedback** ([phase-5-setup-and-browser-feedback.md](phase-5-setup-and-browser-feedback.md)). Direct: Linux 3, Linux 4, addressing Phase 6 (card host), and Speech 4 (voice picker). Show results from real capability producers and link the existing remedies. Cross-capability states and mock-up parity can now be checked in a single browser pass.

**Order.** After Linux 1 and 2, Linux 3 and 4 can merge in either order when their other prerequisites have merged. Linux 3 owns the desktop report producer and observes capture metadata through the Phase 1 boundary. Linux 4 owns the listener output adapter and adds its fields through the shared Speech 1 contract. Linux 2 supplies separate registration points for those consumers. Neither parallel phase changes the other’s adapter or report authority. Linux 5 joins both branches. Phase numbering adds no edge between 3 and 4.

Linux 5 verifies browser layout and end-to-end use with the same physical environment plus repeatable Playwright fixtures. State exactly which desktop combinations passed. Fake tests, recording CI, synthesis CI and a physical listening check prove different claims.
- Merging a feature requires the tests and evidence in its phase file, plus proportionate repository gates. Keep evidence out of Git. Preserve earlier green behavior on macOS and headless Linux. All five phases end in an operable repository.
