Investigated repository

Findings that determine the cut

01
Current ownership is one machine-wide config blob. Every command row still requires a repository, and longest-path matching already expresses the exception rule.
02
Slot and node identifiers are durable. The four slot strings and kind: "check" must remain append-only even while product language changes.
03
Resolution and execution are separate. The new default belongs before unconfigured skip; it does not change policy, verdicts, spawning, or recovery.
04
Library collections are live state. Cards consume App-owned snapshot/SSE collections, so Commands must join that path rather than fetch or poll alone.
05
The old editor cannot break between merges. Phase 1 needs a compatibility projection until Phase 2's replacement is complete.
06
Browser-visible changes require Playwright. Phase 2 owns the built-dashboard spec, route coverage, visual inspection, and documentation sweep.

Implementation sequence

Two mergeable units

The chain is serial because both tasks cross workflow config, Registry state, Library routing, and Settings. Phase 1 remains fully operable with today's UI; Phase 2 removes the bridge after its replacement is tested.

Cross-phase contracts

Boundaries the second task must consume, not reopen

C1

Fixed identity. Slot values and order, graph kind: "check", outcome statuses, and stored attempts remain unchanged.

C2

One authority. The catalog is the only persisted command source; legacy config is projection and adapter only.

C3

Resolution. Longest path override wins, then global default, then unconfigured skip. Nested winners own the working subpath.

C4

Policy separation. checksEnabled and Workflows Trust stay outside catalog rows and are checked after resolution.

C5

Live state. Four bounded views ride snapshot plus full-slot upsert. Registry and MissionState remain the only collections.

C6

Atomic edits. One CAS update replaces a slot's nullable default and complete override list.

C7

Migration. Legacy rows become overrides only. No default is inferred, policy is unchanged, and edited catalogs are never overwritten.

C8

Visible model. Commands is a fixed sixth shelf with no New or Archive affordance and durable slot routes.

C9

Terminology. Product surfaces use Command for the executable node; ordinary English “check” actions remain untouched.

C10

Authorization copy. Settings keeps one control and Trust summary, while the catalog table and repeated warning move out.
