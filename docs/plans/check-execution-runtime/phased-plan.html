What the investigation changed

The automatic loop mostly exists already

This was the biggest surprise and it substantially shrank Phase 1. Built-in v6 already ships foreman_complete + live, and confirmDeliverySend already re-arms Foreman's drain guard in the same transaction. The full cycle is implemented and has never run for anybody.

Four things stop it running by default, and Phase 1 owns all four:

  1. liveEnabled is false, so nothing is ever delivered.
  2. Foreman enabled is false, so foreman_complete is refused at bind time.
  3. An unchanged_evidence refusal permanently kills the loop. The guard is retired inside the claim transaction, before capture runs. If capture then refuses, the guard is spent and no further claim ever arrives. PR #323 split retirement across two sites and added a worse variant: on the fallback path the same transaction also inserts a brand-new No-Mistakes binding, so a refusal there strands a binding nobody asked for on a blocked run.
  4. Item-less sessions never re-arm. The drain re-arm requires queue items to exist, and there is no rearmPromptedCompletionForDelivery anywhere.

And no test asserts the cycle end to end - the completion test fakes the re-arm with raw SQL, in two places.

Landed mid-decomposition PR #323 also gave claimCompletion an auto-bind path that reads liveEnabled to choose its own delivery mode. So Phase 1's default flip does more than switch delivery on: it silently upgrades every auto-created No-Mistakes binding from preview to live on an allowlisted repository. Recorded in Phase 1's findings, and it belongs in that PR's description.

The pool reaper will destroy a check lease

Currently reachable the moment leases exist Walk cheapVerdict against an idle check lease held as mission-control: state leased ✓, holder recognised ✓, not busy ✓ (the command has not spawned yet), not a task worktree ✓, not a session cwd ✓, path exists ✓ - verdict null, so it is returned with treehouse return --force, which terminates processes and hard-resets the tree. This is why Phase 2 cannot be split into "table now, pins later".

treehouse return has no holder argument

Verified against the installed binary: return [path] [--force], no --holder; status has no flags and no --json. So the source plan's "holder-verified idempotent return" cannot be obtained by asking treehouse, and its own escape clause applies - supply holder-aware semantics or exclusive coordination, or pooled check execution cannot ship.

Cross-phase contracts

Contract L - lease safety (Phase 2)

  1. Distinct holder token mission-control-check-<attemptId>. Because cheapVerdict gates on LEASE_HOLDERS.includes(holder), the shared reaper structurally cannot return a check lease. Primary protection, no new reaper code.
  2. PoolPins.checkLeasePaths - defence in depth for a token-scheme change or a widened LEASE_HOLDERS.
  3. A per-repository pool lock serialising every get / status / return this process issues.
Stated residual, not a closure Layer 3 binds only this process. A make session in another terminal is outside it. Layer 1 is what makes that survivable: an out-of-process re-lease gets the bare mission-control holder, never the check token, so the identity comparison fails and the return is refused. A refused return is terminal, not a hold: the row survives as lost for audit and the pin is dropped, because holding a pin on a tree we have just proven is not ours would bar the ordinary reaper from that path for the life of the daemon. Because the shared reaper cannot see check leases, Phase 2 also owns collecting its own leaks - that is an obligation, not a nicety.

Contract P - process identity (Phase 2 defines, Phase 3 consumes)

export interface CheckProcessRegistry {
  /** Persist supervisor identity BEFORE branch code is allowed to run. */
  record(attemptId: string, pid: number, startTimeTicks: string): void;
  /** What was recorded, or null when nothing ever was. Sentinel and missing rows both read null. */
  read(attemptId: string): { pid: number; startTimeTicks: string } | null;
  /** Clear after confirmed group emptiness, never merely leader exit. */
  clear(attemptId: string): void;
}

read was added while implementing Phase 3 and is recorded in its audit. The seam below hands Phase 3 nothing but an attempt id, so without a reader it could not find the pid it had persisted except by reaching into workflow_check_leases - the one thing it is forbidden to do. Additive: record and clear are unchanged.

A second, opposite-direction seam joins the same two phases: CheckGroupRecovery(attemptId) => "empty" | "not-empty" | "unknown". Phase 2's startup reconciliation can prove a leased tree is ours but not that its process group is empty, and only emptiness may authorise a return. Phase 2 declares it with a refusing default, Phase 3 implements it, Phase 4 injects it. Phase 2 hands Phase 3 durability; Phase 3 hands Phase 2 proof-of-death.

startTimeTicks is opaque to Phase 2 and, since Inspector round 3, a composite: a start-time field plus the supervisor's command line, which carries the attempt id. No shell-reachable start-time field has the resolution to stand alone (ps -o lstart= is whole-second), so uniqueness comes from the attempt id in the argv rather than from precision.

Contract R - the retry gate (Phase 2 defines, Phase 4 consumes)

unresolvedLeaseForNode(submissionId, nodeId) answers whether a check node still owns a lease. Phase 4 consults it before a retry is created and blocks the run instead of retrying when the answer is yes. A retry is a new attempt id, so it carries a new holder token and would otherwise lease a second tree while the first group may still be writing.

Contract E - the executor signature (shipped; changed by nobody)

CheckExecutor, CheckExecutionRequest, CheckExecutionResult are already published and tested. workingSubpath stays relative, to be joined onto the leased tree; command stays an argv spawned with shell: false.

Contract F - the repair loop (Phase 1)

  • A Persona or Check fail returns a rendered packet and never a patch.
  • A confirmed live delivery re-arms exactly one completion episode, drain or prompted.
  • A claim that cannot produce a round returns the guard rather than spending it.
  • maxRepairRounds still bounds the loop; reaching it is a visible blocked state a human resolves.

Decisions already settled in shipped code

Not re-opened by any phase The check EvidenceRef kind shipped - EVIDENCE_REF_KINDS includes it, with a docstring defending it as a real kind rather than a relaxation of the citation rule. And workflow_node_attempts needs no widening; only the durable lease table is new.

Verification for the completed set

  1. The CI matrix - typecheck, test, build, bundle smoke, on Node 24 and 26.
  2. Phase 1's repair-cycle test still passes after Phase 4, extended so a real failing check is the trigger. Extended, not forked - the point is that the loop is shared.
  3. Manual: a failing typecheck on a real allowlisted repository fails the submission, the packet reaches the session, the session fixes, and round 2 passes.
  4. Manual: kill the daemon mid-check. The lease row survives, the group is reconciled by identity, the tree is returned only once emptiness is confirmed, and the reaper never touched it.
  5. The suite ends with no leaked lease - the cheapest guard against the worst failure mode.
