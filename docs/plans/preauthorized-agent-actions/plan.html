Preauthorized PR and workflow actions

Make Mission Control's existing scope legible to the agent, so creating the requested pull request and registering scoped workflow evidence no longer stop for a duplicate conversational approval.

Approved decisions

  • Apply the authorization as an always-on Mission Control execution contract. Do not add a setting or opt-out UI.
  • Create a phased implementation plan and schedule its implementation task after the plan artifacts are committed and pushed.

Outcome

  1. When the task or workflow calls for a pull request, the agent may commit the scoped work, push its task branch, and create or update that pull request without asking again.
  2. When a Persona workflow exposes submit_workflow_evidence, the agent may register task-produced, checkout-relative evidence under an issued repository scope without asking for approval of the payload or destination. The agent must not ask the human to resubmit the workflow after a repair.

The authorization is conditional, not an instruction to perform either action in every task. Scout no-PR rules, repository boundaries, evidence validation, and the prohibition on merging remain authoritative.

Why this is happening

Codex is stopping on redundant conversational approvals even though Mission Control has already established the operational scope. The same gap appears around pull request creation: the task or workflow asks for a PR, but the delivered prompt does not state plainly enough that this external write is already authorized by the operator's Mission Control action.

Repository findings

  • src/server/task-contract.ts is the central composer used by both fresh dispatch and assignment to a live session.
  • src/server/workflows/agent-contract.ts explains the evidence tool but does not explicitly preauthorize its scoped write or close the resubmission question.
  • Mission MCP launch registration and preapproval already exist. This is a prompt-level authorization gap, not a reason to widen sandbox access.
  • src/server/workflows/feedback.ts renders daemon-authored repair, Inspector, unchanged-evidence, legacy PR, and SessionAction packets. Follow-up turns need the same authorization after context compaction.
  • The workflow engine or Runs UI owns resubmission. The agent should repair, stage evidence, and stop.
  • actions/pull-request.md is frozen into published workflow versions. Runtime delivery must add the platform envelope without rewriting snapshot Markdown.

Adopted policy: always-on contract

Use an always-on Mission Control execution contract.

Authorization does not expand the task. It removes a duplicate confirmation for an action another task or workflow instruction already requires. Making the invariant optional would preserve the stall whenever disabled and add a persistence and UI surface unrelated to the already-bounded action.

Proposed design

1. One prompt policy

Add a server-side renderer for exact authorization language. It receives task/workflow context, evidence availability, and continuation state.

2. Both task seams

Compose the shared authorization through withTaskKindContract. Keep the human intent first and narrower task-kind restrictions later.

3. Every workflow continuation

Keep authorization in the truncation-safe workflow suffix and the runtime SessionAction envelope, outside frozen action Markdown.

4. Existing enforcement

Keep the current sandbox, MCP allowlists, issued repository slots, path checks, bounds, and server-side attribution unchanged.

Exact policy boundaries

  • PR creation or update is authorized only when the current task or workflow asks for it.
  • The task branch and repository named by Mission Control are in scope. Arbitrary repositories are not.
  • Merge is not authorized, and an explicit no-PR instruction wins.
  • An available evidence tool may be called directly for task-produced, checkout-relative files and issued scopes, including all when issued.
  • Workflow resubmission is owned by Mission Control or the Runs UI, not turned into an agent permission request.

Documentation

Update docs/sessions.md and docs/workflows.md. No Settings documentation, schema, route, or UI changes are required.

Prompt flow change

The agent still asks when a genuinely new decision is required. It no longer asks the human to approve an action already selected and bounded by the task or workflow.

Acceptance criteria

  • Requested PR creation or update no longer causes a separate conversational permission request.
  • Eligible evidence can be submitted directly with the issued scope, including repositoryScope: "all".
  • Repair and action packets do not ask the human to resubmit the workflow.
  • Scout, no-merge, repository, sandbox, MCP, and evidence-validation boundaries remain intact.
  • Published workflow versions and frozen SessionAction Markdown remain unchanged.
  • The authorization survives workflow feedback truncation.
