In-window voice state (optional, not in the spec)

The spec puts the listening state in one place: the menu-bar tray icon, so it is visible while Mission Control is minimized. It does not ask for anything inside the dashboard. This page offers an optional mirror of that state in the window, so the operator who is looking at the dashboard can see it and mute with a click, and so a Playwright spec has something to assert (the tray is outside the browser).

"Tray only, no in-window indicator" is a valid choice, and it is the spec as written. If one of these is chosen it only mirrors the tray: the same four states (listening, muted, auto-muted for a call, push-to-talk active), one click to mute, and the hotkey shown as a keycap. With the voice flag off none of it renders. The state colours here borrow the session tones (--idle, --attention, --working) for the mock-up only; the stylesheet's own rule is that a new meaning gets its own token, so an implementation would mint voice tokens. What varies is where the mirror lives and how much room it takes.

The state word is the mute button. The right end always says what the hotkey does next: Mute, Unmute, or Hold to talk during a call.
  • Room for words, so the call state can say what to do about it ("hold ⌃⌥M to talk") instead of only changing colour.

  • The bottom edge is the least looked-at part of the window, and the residents dock and the background-agents tray already live near it.

  • The words are behind a hover, which is the opposite of the feature's own rule for hints ("always visible, no hover"). At rest it is glyph and colour only.

Click the tab to mute ⌃⌥M The line is decoration; the tab is the control and the accessible name. Muted has no glow at all.
  • Readable from the corner of the eye, and it costs the layout nothing: the line overlays the window's top pixel rows.
  • Colour is doing most of the work, and it has to keep working in every skin (Daylight, Paper, Blueprint, Neon Dusk), each of which would need four state colours that read on its own chrome.
  • The tab is small and fixed, so it never collides with the top bar's ladder.
  • The tab sits in the title bar, which is the window's drag region in the desktop shell, so it needs a no-drag hole there and a different home in the browser build.

Composer mic

Listening for names. Click to mute ⌃⌥M The button mutes Mission Control everywhere, not just for this session. It does not dictate into the box: speech is routed by name, as anywhere else.
  • Teaches the feature at the moment of typing, with the right name already filled in, which is the spec's "teach in place" goal.
  • Only present where a message box is open. On the Board with nothing selected, in Settings or in the inbox there is no indicator, so it cannot be the only in-window mirror.
  • No change to the top bar, the window edges or any page's height.
  • A microphone inside a text box reads as "dictate into this box" in every other app. Operators will expect the words to land in the field, and a session with no call sign has no name to put in the placeholder.
