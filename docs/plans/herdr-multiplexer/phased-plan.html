Source of truth and approved decisions

  • Source: docs/plans/herdr-multiplexer/plan.md and its rendered page.
  • Use a socket-backed Herdr adapter behind the existing Multiplexer registry.
  • Make terminal socket failures settle pending requests once, clear resources, destroy the socket, and ignore late events.
  • Classify every mutation protocol failure after request write as outcome-unknown; pre-write failures and parsed refusals remain confirmed.
  • Support only Herdr's default local server session in the first release.
  • Select inside Herdr, declare clients: null, and use the existing new-client fallback without direct-attach takeover.
  • Scope initial support to POSIX Unix sockets and env -u; Windows named-pipe support is future work.
  • Create merge-aware phases and dependency-linked tasks.
Requirements, not questions. Agents may adapt the proposed route where repository evidence demands it, but the selected behavior remains fixed and deviations must be explained in the implementation pull request.

Repository findings that shape the split

  1. src/shared/terminal.ts is the sole backend vocabulary. Its ordered multiplexer tuple drives wire enums, naming priority, target ordering, setup choices, and exhaustive records.
  2. The current interface already separates stable session address from display name and carries nullable panePid, capture, paste, pane mode, clients, selection, and lifecycle capabilities.
  3. correlate.ts indexes multiplexer panes only by tty. Its host-process and cwd uniqueness fallback is emulator-only and must remain separate from exact PID ancestry.
  4. DetachedSessionSpec lacks selection intent. Background home creation and explicit operator launch are the two owners that must state it.
  5. Browser and setup surfaces are registry-driven. Registration should activate them without a Herdr branch in React.
  6. The E2E daemon explicitly installs fake cmux and suppresses other terminal binaries. Herdr must be equally controlled to keep the suite machine-independent.
  7. Adding herdr widens shared Zod request enums and NameSource, but requires no SQLite migration.
  8. Stable Herdr exposes the workspace, pane, shell PID, I/O, focus, and lifecycle primitives needed here, but no attached-client tty list.

Design clarifications

  • All Herdr protocol mechanism stays in src/server/terminal/herdr*.ts.
  • PID ancestry uses the same process snapshot as discovery, never shells out, never guesses from proximity or cwd, and never competes with a reported tty.
  • Only workspace creation may start a stopped server. Reads and existing-target mutations do not create background state.
  • Status JSON and narrow response schemas gate compatibility. Mission Control never replaces an incompatible server.
  • The full client is launched through an argv wrapper that removes every Herdr namespace selector before executing the resolved binary.
  • Workspace creation and any optional side split receive the exact requested worktree cwd rather than inheriting Herdr's default directory.
  • Named servers, client-tty inference, unpublished pane focus, direct takeover, persistence, and a second registry remain out of scope.

Resolved discrepancies from the root draft

  1. Attach environment. Current attachArgv carries no environment, so a bare Herdr binary could inherit a named-session selector from the daemon. Phase 2 returns an env -u ... wrapper for the default-session guarantee.
  2. Server start scope. The draft allowed startup before any mutation. Existing-target operations cannot act on live state when the server is stopped, and auto-start could restore state the operator did not request. Startup is limited to workspace creation.

Sizing and phase-count rationale

Expected non-test production change: 700 to 950 lines.

  • 100 to 170 lines for ancestry correlation, selection intent, current adapter changes, and contract comments.
  • 350 to 500 lines for socket framing, schemas, compatibility, error classification, and server readiness.
  • 230 to 300 lines for the Herdr adapter, registration, environment isolation, lifecycle mapping, and small generic-surface adjustments.

Combining these would mix shipped tmux/cmux behavior, process-correlation safety, socket protocol work, daemon-start races, a new backend, and all UI/E2E coverage in one large review. A third phase would split the Herdr vertical slice and leave dead code or a visible partial backend, so two is the smallest safe graph.

Merge order and operable states

  1. Merge the planning PR so all task paths exist on the default branch.
  2. Merge Phase 1. Current tmux and cmux remain fully operable, exact tty-less correlation is available, operator cmux launch requests focus, and no Herdr ID is exposed.
  3. Rebase and merge Phase 2. Herdr enters the registry only with discovery, I/O, lifecycle, focus, launch, tests, and documentation complete together.

Cross-phase contracts

Process correlation

  • TTY remains strongest. PID fallback is limited to null-tty multiplexer panes with an actual shell PID on the representative agent's current parent chain.
  • The closest same-backend ancestor wins only when unique. Registry order still names across backends.

Session creation intent

  • DetachedSessionSpec.select selects internally and never promises to raise an operating-system window.
  • Background dispatch passes false; operator launch passes true; tmux may ignore it; cmux and Herdr map it natively.

Herdr boundary

  • Default namespace only, with CLI, server-start, and attach environment isolation.
  • One bounded newline-delimited JSON connection per operation or batch, narrow Zod schemas, explicit size and time limits, and exact unknown-outcome behavior.
  • clients: null and paneMode: null are honest capabilities. Full-client attach never uses takeover.

Compatibility and ownership

  • No SQLite migration and no React vendor branch.
  • No real Herdr server or agent process in automated tests.
  • No generated file or CHANGELOG.md edit.

Final verification strategy

Each phase runs focused tests plus typecheck, lint, the full unit suite, a production build, smoke where runtime surfaces change, and Playwright because terminal behavior is visible. Phase 2 also performs disposable live verification with stable Herdr.

  • No vendor branch exists outside the adapter and every widened enum parses and renders consistently.
  • Missing Herdr costs no subprocess; discovery and existing-target operations never start a stopped server.
  • Background dispatch preserves focus, operator launch requests it, and workspace creation carries the exact requested worktree cwd.
  • Repeated Focus may open another normal client but never evicts an attachment.
  • Named Herdr sessions remain out of scope and automated tests launch no real agent or server.

Complete cross-phase audit

  • Phase 1 uniquely owns correlation and selection intent. Phase 2 uniquely owns Herdr transport, adapter, registration, lifecycle, UI/E2E surface, and docs.
  • Phase 2 consumes Phase 1's exact contracts without redefining them.
  • No concurrent phase, duplicate file owner, temporary registry, migration, generated output, or cleanup-only follow-up exists.
  • Both intermediate and final repository states are buildable, testable, and honest to the operator.
