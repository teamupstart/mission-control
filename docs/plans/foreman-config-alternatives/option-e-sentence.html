Option E · every underlined value is clickable

The configuration as a sentence - the value you read is the control you click

Fourteen controls, each with a label, a widget and a blurb, spend about 140px of panel to state one word. This option deletes the form. The configuration is written out as one paragraph, and every value in it is its own control: click Codex, or On, or a model name, and a picker opens under the word carrying that field's blurb. Nothing is behind a disclosure because there is no disclosure - and the paragraph states the one thing four labelled dropdowns never could, which is the order the roles actually run in.

Click any dashed value - the provider, the tier, a model name, leaves alone. The picker opens under the word, Escape or a click outside closes it, and the sentence rewrites itself around whatever you chose. Two things in it are not pickers: Live is a reading the topbar owns, and the repository count is a link that leaves for Trust.

Configuration

Change the provider, then read the three model names again. The real panel clears every role override when the provider changes; the sentence has no way to know that, so it keeps naming Codex models until something reloads it - the mockup flags them amber, and the shipped version would have to do the same. The cheap-tier clause is the same fault from the other side: set the tier to Off and the words between Triage and Review have to be rewritten, because the paragraph asserts a relationship that the settings store does not hold. A form can be wrong about one field. A sentence can be wrong about the connection between two, and that is a harder class of bug to notice.

Why this one

  • The reading and the control are the same word. "What is Foreman set to" and "change it" stop being two different surfaces, so there is no digest to keep in sync with an editor.
  • It states the pipeline. Triage answers first, the rest reach Review, Verify checks finished work. Four dropdowns in a column never say which order they run in; this cannot avoid saying it.
  • The blurbs survive, unspent. Every field's prose is still there, verbatim, in the popover for that field - it just is not printed 14 times at rest, which is what made the column 1988px.
  • No labels at all. A label is a word that names a value you are already looking at; in a sentence the grammar does that job for free.

What it costs

  • Prose does not scale. A 15th setting cannot be appended - somebody has to write it into a clause, get the clause reviewed as copy, and re-read the whole paragraph to check it still flows. The other five options take a new row.
  • Hardest of the six to keep true. The sentence encodes relationships between settings that nothing in the code enforces. Two are live in this mockup: the provider clearing role overrides, and the tier verb between Triage and Review.
  • Translation becomes structural. A form translates as a bag of strings. A sentence translates as word order, so every locale needs its own arrangement of tokens, and a translator can silently break a clause's meaning.
  • Screen readers need real work. Ten buttons inside one running paragraph is ten interruptions in browse mode, and a dialog anchored to a word has no natural reading position. aria-haspopup and moving focus are the floor, not the answer.
  • Nowhere to put a setting with no narrative role. The Backlog role model is already outside the paragraph, in the dashed box, because no clause wanted it.
  • Compression drops axes. The launch clause names three models and never says which harness gets which; the form said it in three labels. Deep links have the same problem - foreman/skip-scout-wrapup has to land on a word inside a paragraph and open its popover.
