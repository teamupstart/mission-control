Mission Control · mockups · task-kind-visibility

Task type, always visible

Before this change, the conversation header named a task's kind only when it was not ship: taskPillParts (src/shared/task.ts) treated ship as the silent default, and the kind that did print was a small blue chip in the PATH and BRANCH band. Board cards never showed a kind at all. So a ship task, the most common kind, showed nothing anywhere. The behaviour that shipped is described in docs/ui.md.

These mockups make the kind always shown, ship included, give each of the six kinds its own icon and colour, and move it out of the PATH and BRANCH band. There are four options for the conversation header (A to D) and four for the board card (1 to 4). Every option prints the kind's word or, for option 4, shows it on hover, so colour is never the only cue. Both surfaces get a setting under Settings › Display.

shipdeliver a changebugfixfix a bugscoutinvestigate and reportplanproduce a reviewed planpipelinerun a conductor pipelinechathave an open-ended conversation

When these mock-ups were prepared, the kind colours were only proposals. They were then selected and are the colours that shipped. Each kind gets its own hue, chosen to stay clear of the state tones that already colour a card's left edge and the header's status pill. The backlog card's .bl-kind-* colours are left as they are.
