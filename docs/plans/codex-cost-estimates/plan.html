Decisions

1Provenance is data chosen

Add reported | api-equivalent | unpriced to session and ledger summaries. The first two identify the calculator—not different economics—and components branch on basis, never on agent id.

2Price requests, not cumulative snapshots chosen

Persist every last_token_usage event with the active turn_context.model. This is required for model switches, long-context rules, cache tiers, and midnight boundaries.

3Rollouts remain the source chosen

No Codex OTel installation. Rollouts already reach operator-started sessions and carry the necessary token categories without adding /v1/logs or editing ~/.codex/config.toml.

4Combine like estimates; keep quota separate chosen

Claude Code's token-price estimate and Mission Control's Codex token-price estimate share one completeness-aware SQL sum. Subscription quota remains a separate provider signal.

5No new opt-in chosen

The app already reads Codex rollouts and displays their tokens. Local pricing adds no credential, telemetry export, network request, or user-config mutation.

6Unknowns refuse to guess chosen

Unknown model, service tier, or parent attribution stays explicit. There is no “nearest model” price and no cwd/time-based subagent join.

What is actually tracked

Codex rollout

Conversation id, source, exact model, effort, per-request and cumulative input, cached input, cache-write input, output, reasoning output, context window, and quota windows.

Codex SQLite

threads.tokens_used, model, provider, and rollout path—but only an aggregate. The rollout remains the richer pricing source.

Before this implementation

Mission Control parsed only the newest cumulative usage, set costUsd: null, and updated the live card without writing Codex usage to the daily ledger.

Not tracked

No per-session ChatGPT dollar/credit charge, authoritative bill, service-tier history, hosted-tool fee total, or safely attributable unlinked subagent total.

Data flow

Implementation design

  1. Add cost provenance.Add CostBasis and distinct pricing-model/version lists to SessionCost. Keep the calculator provenance in each ledger row while presenting both known bases as API-equivalent estimates. Existing Session.cost = byJson already enforces visible changes.
  2. Add a server-only harness usage capability.HARNESSES.codex supplies a request reader and estimator; Claude declares null because OTLP metrics remain its source. Consumers call usageFor(session).
  3. Read append-only JSONL safely.Resume from a durable byte offset, process only complete lines, preserve active model, cap catch-up at 1 MiB, and derive replay-stable event identities from conversation id + timestamp + raw record.
  4. Price with a pinned registry.Exact model match only. Separate uncached input, cache reads, cache writes, and output. Apply long-context rules per request. Persist full precision and round only in UI.
  5. Persist cursor and event atomically.Add usage_sources; migrate usage_ledger with basis, known, and pricing-version columns. An identity conflict preserves the original economic snapshot and updates only missing provenance, so replay cannot double count or reprice history.
  6. Drain through a generic collector.Start src/server/usage.ts beside runtime metadata. Require proven conversation id, catch up immediately while more, and hold a removed session for a final 30-second grace drain.
  7. Combine fleet SQL with completeness.Known Claude and Codex estimates use one sum. Tokens include every basis, including unpriced rows. Any unpriced row makes that time window partial, and cost/PR is withheld rather than understated.
  8. Update every UI vocabulary.Shared CostChip handles all three figure layouts and prefixes every dollar with ≈. Rail uses the same convention. FleetStrip renders one combined estimate while quota stays separate.
  9. Correct the contracts and docs.README, Settings, AGENTS, shared comments, fixtures, and tests stop claiming that Codex has only an opaque token scalar.

Critical SQL rule: existing Claude ledger rows must migrate to reported / known. An unknown-model Codex row still stores tokens, but any unknown row makes both the session and matching fleet-window dollar total null—never a silently partial estimate.

Resolved review decisions

  1. Semantics: every dollar uses ≈$ so subscription-plan activity is not presented as an incurred charge.
  2. Fleet scope: Claude and Codex API-token estimates combine into one daily value, rate, and cost/PR; quota remains separate.
  3. Default behavior: local Codex estimation needs no second Cost toggle or runtime network call.
  4. Completeness: unknown pricing marks the affected fleet window partial and withholds cost/PR.
  5. History: there is no first-install scan of ended historical rollouts; active sessions backfill on daemon restart and future events retain for 180 days.

The full signatures, SQL columns, sequencing, acceptance criteria, and known limitations are in plan.md.

Acceptance summary

Supported Claude and Codex sessions show consistently qualified estimates everywhere; fleet totals, rates, and cost/PR combine all known estimates; unknowns produce an explicit partial state; request events remain durable and replay-safe; quota stays separate; and the implementation adds no external configuration or credential dependency.
