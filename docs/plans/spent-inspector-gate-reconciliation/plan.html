Approved follow-up plan

Spent Inspector Gate Reconciliation

Make a stopped gate distinguish historical failure from current Inspector truth, then reuse the narrowest safe recovery path.

Approved approach

Truthful state plus the existing grant path. No schema, no Shipping change, no second budget, and no silent completion after an operator-set limit.

Goal

Make a spent workflow Inspector gate tell the truth when the current pull-request head has since been reviewed clean, and give the operator one clear, safe path to let that workflow adopt the clean head.

The follow-up preserves exact-head Inspector proof, durable workflow ownership, immutable Inspector-only repair audit, and the rule that Shipping never merges around an active workflow gate.

Approved decisions

  • Implement truthful state plus the existing grant path, including the contextual Adopt clean Inspector head action.
  • Create a phased implementation plan and schedule its implementation task or tasks after publishing the plan artifacts.

Evidence summary

PR #591 demonstrated two records that diverged. The workflow gate is frozen on 54d0bd2d with four finding fingerprints. The current Inspector ledger is on fbba204b with zero open findings, and all four historical fingerprints are resolved.

Existing seamFinding
Run detailAlready returns both the historical gate and current Inspector records.
EvaluationInspector updates are scheduled, but the blocked-run guard returns before refresh.
RecheckReports success and schedules the same evaluator, so it no-ops on a spent run.
PresentationReads the historical waitReason without qualifying it against current evidence.
RecoveryThe existing grant route already restores safe, audited exact-head evaluation.

Constraints

  • Do not release Shipping merely because historical rows are resolved.
  • Do not complete from a stale or non-current Inspector head.
  • Do not let the browser decide that a gate passed.
  • Do not create a second source of Inspector truth.
  • Keep the failed head and findings visible as history.
  • Preserve the repair budget as an operator boundary unless the selected option explicitly changes it.
  • Cover every visible change with Playwright.

Selected solution

Approved

Truthful state plus existing grant

Show historical and current Inspector state separately. When the current exact head is clean, label the existing grant move Adopt clean Inspector head. The existing daemon path then revalidates and completes.

No schema, endpoint, Shipping, or budget-policy change.

Decision rationale

The selected approach fixes the false statement and dead action at their source, uses current data already on the wire, and reuses the recovery path whose compare-and-swap, round grant, immutable Inspector-only submission, and exact-head checks already exist.

Proposed implementation

  1. Add one shared browser-safe derivation for historical findings, current review freshness, exact-head cleanliness, and unavailable evidence.
  2. Use it in run detail, the workflow ladder, compact preview, next-move descriptor, and no-move sentence.
  3. Keep historical state in the facts and audit packet. Never rewrite it from browser state.
  4. For a spent gate with a clean current head, reuse grant-rounds and label it Adopt clean Inspector head.
  5. Remove Recheck GitHub Inspector from spent blocked gates; keep it where the evaluator can act.
  6. Update the Workflows guide with the historical versus current distinction and contextual recovery label.

Recommended state flow

Acceptance criteria

  • A spent gate never claims its retained findings remain unresolved when they are resolved.
  • Run detail separates last workflow observation from current Inspector status.
  • A clean current Inspector head yields one primary action named Adopt clean Inspector head.
  • The action uses the existing grant route and cannot directly complete the workflow.
  • The daemon still proves an adopted open PR, exact current head, live review, and zero findings.
  • Dirty, unreviewed, mismatched, closed, and unavailable evidence cannot produce the clean-head action.
  • A spent blocked gate does not offer a recheck action that can only no-op.
  • Ordinary grant and cancel recovery remain available where current evidence is not clean.
  • Shipping behavior and historical audit remain unchanged.

Verification

  • Focused node:test coverage with the required test/setup-state.mjs preload.
  • Workflow manager coverage for adoption of a later clean exact head and refusal of inconsistent evidence.
  • Rendering tests for run detail and ladder copy.
  • A Playwright specification for the spent historical gate and clean current Inspector recovery.
  • npm run typecheck, npm run lint, npm run build, then npm run test:e2e.

Out of scope

  • Changing Shipping's merge gate order.
  • Automatically retiring or completing spent runs.
  • Adding a new Inspector budget or workflow setting.
  • Rewriting historical gate snapshots.
  • Recovering PR #591 during implementation verification.
