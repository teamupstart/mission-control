Turning voice on

Enabling the Voice preview offers to turn on the two previews it needs (async-input, shown as "Ask without stopping", and inbox, shown as "Reports and inbox upgrades"). macOS asks for the microphone. The Parakeet speech model is downloaded the first time, with progress, then its checksum is verified and it is kept in the state home. A missing or broken model is reported by the existing Setup checks.

Fixed in every variant: the flag is switched in the Feature flags list, the offer names both prerequisites and says which is already on, the download shows size, speed and Cancel, a failed checksum deletes the file and offers Retry, and Setup gains a "Voice speech model" check. What varies is where the sequence runs and whether it blocks. Each variant shows five moments: the offer, the microphone, the download, verified and ready, and failure. The 600 MB size is illustrative.

  • The spec already wants the model in Setup. This puts first run and later repair on the same rows, with no second flow to keep in step.
  • Setup checks are probes with a Fix today (src/shared/setup-catalog.ts). A row that owns a long download with progress and Cancel, and one that toggles feature flags, are new kinds of remedy.
  • The Setup banner already tells the operator when required checks need attention, so a broken model can surface without new banner code if the check is marked for it.
  • Setup reads as machine plumbing. Sending a first-time user there to switch on a headline feature is the least welcoming of the five.
