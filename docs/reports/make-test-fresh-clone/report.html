Fresh-clone make test audit

Question: does a fresh Mission Control clone pass make test without relying on operator-specific environment variables or existing state?

Finding: yes, with one test portability repair. The repair classifies GET /api/environment/checks as host-dependent in the route oracle. The existing checkout then passed the full target outside the macOS sandbox, and a separate clone passed under an isolated HOME, TMPDIR, and environment.

Root cause and repair

test/route-surface-oracle.test.ts already normalized several machine-dependent routes to stable field names. It omitted GET /api/environment/checks, even though that route calls module-level environment probes and necessarily reports the current machine. The fix adds the route to HOST_PROBING; the documented regeneration command updates test/fixtures/route-surface.json from the machine-specific body to 200 fields{checks}.

Changed files: test/route-surface-oracle.test.ts and test/fixtures/route-surface.json.

Additional checks

  • npm run typecheck: passed.
  • npm run lint: passed with pre-existing warnings; no new warning was introduced by this change.
  • The isolated route-oracle test passed after regeneration.

Limits

The clean clone used the local Node 24 installation and an already available network connection for dependency installation. It did not test a different Node major, an offline registry, or a non-macOS host. The sandbox baseline is not evidence that the product fails on a normal macOS host because the repository documents the need for outside-sandbox approval for these geometry and OS integration tests.
