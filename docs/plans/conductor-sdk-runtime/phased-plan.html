Why identity comes first

An SDK session stays in the primary checkout, so it cannot inherit the terminal home's worktree correlation. Prebinding the provider key removes that accidental dependency before the new host is introduced.

Cross-phase contracts

One provider keyProvider, repository, and canonical idea slug are fixed before launch.
One live ownerA duplicate task or existing provider worktree refuses a second host.
Two host shapesTerminal uses homeName; SDK uses sessionId; both use pipelineRun.
One completion ownerOnly the exact processed provider projection settles either task.
Legacy remains readableOld null-link terminal tasks still bind from home and discovered worktree.
No hidden fallbackSDK errors stay errors until Retry or an explicit Terminal selection.
