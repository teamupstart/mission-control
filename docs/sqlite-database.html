A field guide to harness.db

The durable memory behind tasks, reviews, automation, workflows, schedules, usage, and ensembles. This guide explains where it lives, how to inspect it safely, and what each of its 63 tables owns.

Operator entry point

Open the same file the daemon uses

Run make db from the repository root. The command calls the shared state-directory resolver, refuses to create a missing database, opens SQLite with -readonly, and enables PRAGMA query_only.

The shell is intentionally read-only.

Mission Control treats the daemon as the sole database writer. Read while it runs. For manual repair or mutation, stop every Mission Control process, make an offline backup, and prefer a reviewed migration or application route over ad hoc SQL.

Operating model

The daemon owns persistence

The browser, MCP bridge, hooks, and Foreman reach the daemon over HTTP or event channels. They do not open SQLite. This gives write policy, migrations, transactions, and event publication one owner.

Durable, not live

Terminal sessions are rebuilt from the operating system and are not stored as session rows. State the OS cannot reconstruct is persisted, including tasks, reviews, work episodes, and event history.

SDK sessions are different

sdk_sessions is a durable supervisor ledger because daemon-owned embedded processes are deliberately excluded from terminal discovery and must resume after restart.

WAL supports readers

The daemon selects write-ahead logging. A read-only shell can inspect a running database while the daemon writes, subject to SQLite snapshot behavior.

Transactions guard side effects

Uniqueness, partial indexes, claims, operation keys, and explicit transactions protect exactly-once work and recovery boundaries where duplicate dispatch or delivery would be costly.

Schema atlas

What every table owns

The catalog groups tables by responsibility. Open any family below. For exact columns and indexes in your installed database, use .schema TABLE because migrations may add columns after the original CREATE TABLE block.

Tasks and work episodes8 tables
tasks

The backlog and execution record: intent, harness choices, repository and worktree coordinates, current session binding, source or schedule provenance, status, and outcome.

task_repos

The secondary repositories attached to a multi-repo task, one row each, with the worktree, branch, provider and baseline commit provisioned for it. The primary repo is never in here - it stays on the tasks row - so a single-repo task has no rows at all.

session_work_episodes

The current unit of work associated with a live session, including branch and pull request provenance plus restart rebind state.

session_work_episode_prompts

Prompt timestamps for one session and episode, used to make prompting idempotent.

work_episode_prs

One work episode's pull request in a SECONDARY repository of a multi-repo task, one row per repo, with its state, head and merge instant. The primary repo's pull request is never in here - it stays on the episode and binding rows - so a single-repo task has no rows at all.

task_work_episode_bindings

The current one-to-one task and work-episode association. A unique session index prevents two active tasks from claiming the same session.

historical_task_work_episode_bindings

Retained task-to-episode provenance after the current binding moves on.

task_source_seen

A durable deduplication ledger for external task sources. Its rows outlive deleted tasks so a deleted imported item stays deleted.

session_agent_bindings

Maps a transient synthetic session ID to the harness-native agent session ID used as a durable note and queue key.

Sessions, reviews, and operator state10 tables
reviews

Human review requests and resolutions, including kind, body, structured decisions, answer selections, status, response, and attribution.

session_events

An append-only session event log written by hook ingestion. It also proves whether precise hooks have ever been observed for a session.

session_notes

Current Foreman-facing note state for a stable note key: purpose, brief, recommendation, disposition, and last handled marker.

session_goals

The durable objective and latest prompt reconciliation state shown as a session goal.

sdk_sessions

Restorable daemon-owned session identity, runtime choices, lifecycle status, and whether a turn was interrupted.

pending_turns

The durable operator outbox for human messages not yet accepted by a harness, with sequence, revision, claim, retry, and uncertainty state.

skills_acks

The last skill catalog generation acknowledged by each stable session note key.

app_config

Generic JSON-encoded application settings stored as key and value text.

personas

Reusable, revisioned model-review definitions with exact operator-authored Markdown guidance and optional provider/model choices.

session_actions

Reusable workflow instructions with exact Markdown prompts, required skill capabilities, and server-owned completion proof kinds.

Foreman4 tables
foreman_episodes

Append-only decision history: situation, captured question or terminal pane, triage evidence, chosen action, delivery, and resolution attribution.

foreman_queues

One current queue header per stable note key, including checkout reattach hints and wrap-up guards.

foreman_queue_items

Ordered durable instructions and their propose, send, verify, recover, complete, or escalation lifecycle.

foreman_invites

Whether Foreman may act in a session, per stable note key: a dispatch or operator grant, or the withdrawn tombstone that beats even the implicit SDK-runtime grant.

Native worktree pools2 tables
worktree_pools

Daemon-owned pool identity keyed by the repository's physical Git common directory, including its managed root and latest reconciliation outcome.

worktree_slots

Append-only slot identity, lifecycle state, exact active lease owner, last released lease tuple, Git commit state, and quarantine evidence.

Workflow definitions and execution14 tables
workflow_commands

The Global Command catalog: one row per built-in workflow slot (test, lint, typecheck, build) holding its optional repository-neutral default argv, revision, and timestamps. Seeded on first open, so all four rows exist before anything is configured.

workflow_command_overrides

One repository or subdirectory exception to a slot's default command, keyed uniquely by slot and repository root. The longest matching root wins at resolution time, which is how a monorepo package overrides its repository.

workflow_definitions

Mutable workflow identity, draft graph, policies, draft revision, archive state, and pointer to the current published version.

workflow_versions

Immutable published graph and policy snapshots, numbered within a workflow.

workflow_bindings

A published version attached to a stable session note key, with frozen compatibility facts, trigger and delivery modes, and repair budget.

workflow_runs

One execution of a binding: status, phase, trigger identity, Inspector gate state, timestamps, and retention markers.

workflow_submissions

Immutable evidence snapshots scoped by run, repair round, and continuation segment.

workflow_node_attempts

Each attempt to execute one graph node against one submission, including frozen Persona or session-action snapshots and its verdict or output.

workflow_edge_receipts

Deduplicated proof that a source attempt activated one graph edge for a submission.

workflow_deliveries

Durable packets sent to sessions, including payload hashes and prepared, sending, delivered, uncertain, refused, or cancelled lifecycle.

workflow_llm_calls

Provider/model, timing, bytes, cost, state, and error metadata for workflow-owned model calls.

workflow_events

Append-only operator-visible run audit events.

workflow_binding_claims

Idempotent external-orchestrator ownership of a workflow binding.

workflow_check_leases

The durable owner and cleanup state of a worktree held by a workflow Check node.

Usage and source cursors2 tables
usage_ledger

Deduplicated token and cost cells by stable note key, model, query source, and high-precision source window identity. It separates session and automation spend.

usage_sources

Durable byte cursors and file identity for append-only usage inputs so a crash may replay data but cannot skip it.

Inspector2 tables
inspector_prs

The pull requests Mission Control is allowed to inspect, plus last reviewed head, last observed remote state, retry state, merge posture, and adoption provenance.

inspector_comments

One deduplicated finding per pull request fingerprint, with path, line, title, scrubbed body, severity, round, reply state, and status.

Recurring missions3 tables
mission_schedules

The current schedule catalog and durable next-run cursor, pointing at the active immutable revision.

mission_schedule_revisions

Immutable copies of the task template, cadence, timezone, and execution policies for historical explanation.

mission_schedule_occurrences

One claim for each schedule and instant, recording overlap or missed-run decisions, task identity, recovery status, and terminal result.

Multi-agent ensembles10 tables
ensemble_runs

The root aggregate: idempotent source identity, compiled strategy plan, pinned repository base, current stage, optional workflow handoff, terminal outcome, and error.

ensemble_members

One durable logical role per compiled plan, independent from any specific launch attempt.

ensemble_attempts

Each member launch, recording requested and observed runtime facts, worktree and branch, timestamps, and result state.

ensemble_artifacts

Immutable evidence locators and digests. Git or another external store owns the actual bytes.

ensemble_stage_attempts

Idempotent execution of a compiled strategy stage, pinned to an exact versioned driver.

ensemble_evaluations

Review-stage judgments over fingerprinted artifact inputs, with provider/model and structured results.

ensemble_llm_calls

Cost, timing, byte counts, operation identity, and state for ensemble-owned model calls.

ensemble_events

Append-only, deduplicated transition audit trail for a run.

ensemble_decisions

Versioned human selections and rationale under the evidence visible at decision time.

ensemble_deletion_intents

A recoverable, single in-progress deletion record for external refs that must be cleaned before the run is removed.

Archives (disposable index)6 tables
archives

One row per discovered bundle under a library root: composite archive key, producer and archive identity, the kind the manifest declares (null when the manifest could not be read), format version, ready/partial/unreadable status, frozen manifest display fields, digests, the library root and relative bundle path, manifest fingerprint, counts, bytes, safe error, and reconciliation epoch.

archive_artifacts

One archived file per row, addressed by generated artifact id rather than by path: role, repository slot, original and archive paths, media type, bytes, and digest.

archive_search_segments

Bounded, case-folded text a literal search scans, including visible report text extracted once at index time. Deliberately not an FTS5 table, because FTS5 is a compile-time option.

archive_capture_jobs

Local coordination for archives still being written, one row per archive a task work episode owes - one for a scout, one per plan directory for a plan: the kind being captured, the reserved producer and archive identity, the scope that row covers, the submitted report path, summary, tags and supporting locators, the server-derived checkout roots a resumed capture reads from, and the published bundle path once it exists. Never evidence - a finished archive needs none of it.

scout_prompt_contexts

Where a scout's conversation started, frozen at the task-delivery seam: the session name the card was showing, the transcript path and byte offset the episode begins at, and whether any bound was reached. Terminal dispatch and assignment freeze it immediately before the prompt crosses into the runtime, because the anchor is the transcript's size right then; embedded dispatch freezes it immediately after the driver starts, because on that runtime the prompt IS the start and its anchor is byte zero rather than a measured size. One row per task work episode. The frozen name is the archive's title of last resort once the live session is gone.

scout_prompt_turns

One user-role turn this daemon saw delivered into a scout episode, in delivery order. Human rows keep their text, trimmed of surrounding whitespace and clipped to a per-entry UTF-8 byte bound (the context is marked truncated when either bites); a Foreman, Workflow or harness row keeps only its origin and a fingerprint, because an automated turn's payload is needed to exclude it from the archive rather than to archive it. Exists because attribution is otherwise in memory only, so a restart would publish a machine's instruction as the operator's own words.

The first three are the one exception to "durable, not live" in the other direction: they are a cache of directories on disk, carry no foreign key to a task or a session, hold no evidence bytes, and are rebuilt from the library by a background reconciler if the database is deleted. That is why the rename to these names dropped and rebuilt them rather than copying rows. archive_capture_jobs is the opposite kind of row again - purely local bookkeeping about work in flight, referring to task and session ids as values with no foreign key or cascade, because a published archive has to outlive both, and its rows were MIGRATED rather than dropped because an interrupted capture cannot rebuild them from anywhere. The two scout_prompt_* tables are local bookkeeping of the same kind and on the same (task, episode) key, and they are the only rows here that cannot be rebuilt from anything at all: they record what a live session was told and what it was called at the moment it was told, both of which stop being derivable the instant that session is evicted.

Pipelines (disposable projection)1 table
pipeline_runs

One row per feature an external SDLC engine is driving in a repository an operator consented to, keyed by that engine's own identity for it: the provider id, the repository root, and the plan-stem slug. Holds the serialized projection the dashboard reads plus the byte offset the engine's event ledger was last tailed to. Rows arrive only for a repository switched on in Settings, and go the moment that consent is withdrawn.

A cache, in the same family as the three archive index tables above and for the same reason: every column is derived from files the engine owns and rewrites, so deleting this table - or the whole database - costs one refresh pass and nothing else. Nothing may be stored here that is not already on disk under the engine's control; a label, an annotation or an operator's own note would be lost the first time the projection was rebuilt, and belongs on a task. It exists so a dashboard connecting before the watcher's first pass sees the last known truth rather than an empty page, and so the events tail can resume at the byte it stopped at rather than re-reading a feature's whole ledger on every daemon start. It declares no foreign key and holds no reference to any other table.

Relational design

Constraints carry business meaning

Most table families relate through identifiers enforced by their store code and focused indexes. The ensemble family is the exception: it declares foreign keys and cascading deletes, and the daemon enables PRAGMA foreign_keys = ON on its connection.

PatternExamplesReason
Stable note keysession_notes, session_goals, queues, usageHarness-native session identity survives replacement of a synthetic terminal process identity.
Append-only auditevents, Foreman episodes, ensemble decisionsHistory explains what happened without overwriting the prior state.
Immutable revisionworkflow versions, schedule revisionsAn execution remains explainable under the exact configuration that started it.
Idempotency keytrigger keys, source keys, operation keysA retry after a lost response or crash returns to the same durable operation.
Partial unique indexone active workflow binding, one sending turn, one live leaseThe database rejects unsafe concurrent live states while retaining terminal history.
Explicit foreign keysensemble_runs descendantsUnreachable children are corruption, so run deletion cascades through the family.
Do not assume every *_id is a declared foreign key.

For most families, relations are application contracts rather than SQLite REFERENCES clauses. Check the owning store and schema source before deleting or rewriting related rows.

Reading rows correctly

Storage conventions

Time is epoch milliseconds

Most *_at, ts, and schedule timestamps are integer Unix epoch milliseconds. Nanosecond usage source identities stay as text to avoid JavaScript precision loss.

Booleans are integers

Flags such as enabled, turn_in_progress, and cost_known use 0 and 1.

Structured values use text JSON

Columns ending in _json and several named fields such as labels, dependencies, menus, and app-config values contain serialized JSON owned by application schemas.

Null has domain meaning

Null often means not observed, not applicable, or no override. Empty string is used when a uniqueness key needs one normalized unknown value. They are not interchangeable.

Enums are durable identifiers

Status, kind, role, and strategy strings are persisted contracts. Renaming one can orphan history or make a row unreadable.

Payload retention is selective

Workflow retention can prune evidence and delivery payload content while keeping lifecycle and audit rows. Ensemble artifacts store locators and digests, not full patches.

Schema lifecycle

Fresh schema first, idempotent upgrades second

openDb() creates every current table and safe initial index, then migrate() upgrades existing files. Each migration runs on every open and must be idempotent.

// The project contract for adding a column
1. Add it to the fresh CREATE TABLE definition.
2. Add the same column through addColumn() in migrate().
3. Create indexes that name it only after addColumn().
4. Add an upgrade test seeded with the older schema.

This ordering matters because CREATE TABLE IF NOT EXISTS does nothing to an existing table. An index in the initial block that names a newly migrated column would run before the column exists and prevent every upgraded database from opening.

The source file is the contract, not a diagram.

Use src/server/db.ts and the subsystem stores for implementation work. This guide explains intent and navigation. It does not replace migration tests or live schema introspection.

Columns per table

SELECT name,
  (SELECT COUNT(*) FROM pragma_table_info(name))
    AS columns
FROM sqlite_schema
WHERE type = 'table'
  AND name NOT LIKE 'sqlite_%'
ORDER BY name;

Exact installed schema

SELECT type, name, sql
FROM sqlite_schema
WHERE name = 'tasks'
   OR tbl_name = 'tasks'
ORDER BY type DESC, name;

SQLite cannot parameterize a table name in a generic row-count query. For data volume, query the specific family you care about or generate statements from sqlite_schema and review them before running.

Recovery boundaries

Back up a stopped database

For an offline backup, stop Mission Control and copy harness.db together with harness.db-wal and harness.db-shm when present. Keeping the WAL sidecars matters because committed pages may not yet have been checkpointed into the main file.

# 1. Stop development processes
make stop-all

# 2. Copy all SQLite files from the resolved state directory
#    Default: ~/.mission-control/

# 3. Restore only while the daemon is stopped
#    Use the same or a newer Mission Control build.

Workflow and ensemble exports are portable audit artifacts. They are not database restore formats. If the daemon is packaged or installed as a login service, stop that owner too before replacing files.
