First-pass acceptance now depends on matching proof to intent

Review the reasons for Test Evidence Auditor rejections and present ideas to improve likelihood of acceptance on first pass.

The prompt-level transport fix worked, but generic evidence registration is no longer the bottleneck. Eleven of twelve recent first submissions carried a text artifact, yet only six passed. The rejected packets usually contained evidence; they failed because no retained item proved one material criterion, such as the exact focused test, rendered pixels, a before-and-after performance measurement, merge state, or the requested report.

What the current sample actually says

The live read-only aggregate covers 41 attempts across 29 runs from 29 August through 3 September. All attempts use No-Mistakes Review v10 and one guidance digest, so the sample is internally consistent. Rejection categories overlap.

Do not read 7 of 8 as “seven packets had no test output.” Five of the six failed first submissions already had one or more text artifacts. The category means the auditor still lacked completed output for a material behavior. A broad pass, an unrelated focused run, a no-op test target, or a functional browser run for a performance claim does not close that gap.

Transcript truncation is not the primary signal. Four of twelve first submissions were marked truncated, split evenly between passes and failures, and zero transcript-head bytes were dropped. Check tails omitted about 10.1 MB, but successful packets still passed by registering small, task-specific artifacts. The dedicated evidence channel is the right transport; relevance is the missing control.

Selected lead: a criterion-mapped evidence preflight

Operator selection: Criterion-mapped preflight. Before the first Persona call, Mission Control should show every material acceptance criterion beside the registered evidence that claims to prove it, then stop high-confidence structural gaps before they spend a review round.

  1. Give criteria stable identities. Preserve the acceptance criteria already captured in workflow context, but expose a stable criterion id for evidence mapping. Let each submitted command, image, log, or Check declare the criterion ids it supports. Do not infer the mapping from filenames alone.
  2. Apply a behavior-aware matrix. Internal logic needs the exact focused regression output. API, persistence, and process boundaries need an integration result showing the state transition. UI needs browser coverage plus registered pixels. Performance needs retained baseline and post-fix measurements under the same conditions. Investigation and documentation work needs the requested report or rendered document, not unrelated production code.
  3. Validate structure before semantics. Deterministically block a UI criterion with zero images, a performance criterion with no measurement artifact, or any material criterion with no mapped evidence. Warn, rather than guess, when an artifact exists but semantic relevance is uncertain. An explicit operator override should record why submission is still appropriate.
  4. Show the exact gap in the completion surface. Replace a generic evidence count with rows such as “AC-3: browser run registered, screenshot missing” or “AC-2: focused run covers a different test file.” Let the agent repair the packet before the immutable first submission.
  5. Measure the intervention by guidance and workflow version. Keep the existing 70% first-pass target, but add preflight warning/block counts and criterion-coverage rates. The current rolling aggregate needs eight consecutive first-pass accepts to move from 6 of 12 to at least 70%.

Why this is stronger than a simple “require one artifact” gate: one artifact was already present on 11 of 12 first submissions, and several rejected packets had multiple artifacts. The preflight must answer “does this item prove this criterion?” rather than “does an item exist?”

Two supporting ideas

Follow-on 1

Atomic run-and-register

Add a bounded focused-check path that retains the command, exit code, reviewed HEAD, and useful head/tail output as one server-observed artifact. This directly reduces the seven execution-proof requests and prevents a transcript summary from becoming the only surviving record.

Follow-on 2

Task-specific prompt checklist

Render the same evidence matrix in the session prompt with examples derived from the task type. Keep this as guidance for collecting proof, while the preflight provides the enforcement the current generic prompt lacks.

Avoid

Loosening the auditor

Do not accept prose claims, generic pass lines, or DOM assertions as substitutes. The current sample shows no later-stage overreach. The auditor is mostly enforcing its published contract correctly; the packet should improve instead.

Why prompt-only changes are insufficient

The ship-task appendix already tells agents to map evidence to every material acceptance criterion, register exact command output, add images for rendered UI, and avoid relying on ordinary tool-result bodies. That change improved text-artifact adoption dramatically relative to the August baseline, but the current 50% first-pass result shows that an instruction is not a readiness check.

The auditor guidance is also explicit: it judges demonstrated intent, requires focused output for internal behavior, requires integration evidence across process boundaries, requires pixels for UI, and rejects prose claims. The six current failures are predictable under that published matrix.

A criterion-mapped preflight still needs a product design for stable criterion ids, ambiguous mappings, override policy, and multi-repository scope before implementation.

Finding: evidence transport adoption improved, but first-pass acceptance is now limited by intent-to-proof coverage. Lead with a criterion-mapped preflight, then make focused command capture atomic.
