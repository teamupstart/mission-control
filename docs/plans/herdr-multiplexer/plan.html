Add Herdr as a supported multiplexer

An investigation-backed plan for reusing Mission Control's tmux/cmux capability interface while correcting two generic assumptions exposed by Herdr.

Answer: yes. Herdr belongs behind the existing Multiplexer registry. Its workspaces, tabs, and panes map to sessions, windows, and panes. The production-quality path needs PID-ancestry correlation, explicit create-selection intent, and a validated Herdr socket client inside the adapter.

Recommendation

Build a socket-backed herdrMultiplexer, register herdr after tmux and before cmux, and keep Herdr commands, schemas, timeouts, and environment rules inside src/server/terminal/herdr*.ts.

Use Herdr's full client for attach. Select the agent pane before attach, then let the existing emulator fallback open a namespace-scrubbed wrapper around herdr. Declare clients: null because the stable API does not publish client ttys. This means Mission Control cannot raise an existing Herdr client and a repeated Focus may open another client.

Do not use direct-attach takeover as the default. Herdr allows only one writable direct controller per terminal. --takeover would evict the operator's existing attachment, violating Mission Control's no-yank focus rule.

What the investigation confirmed

  • Herdr documents a background server, detachable clients, and public workspace/tab/pane socket operations.
  • Normal detach preserves live pane processes. A full server stop restores shape but not arbitrary processes, which matches the practical multiplexer boundary.
  • Herdr v0.8.2 source sets process-info tty to None while returning the shell PID. Mission Control's tty-only multiplexer join is therefore the first real blocker.
  • pane.send_input honors live bracketed-paste state. pane.send_text sends raw text. A safe multiline paste should use the socket API.
  • Creation leaves focus unchanged unless requested. Mission Control needs that distinction for background dispatch versus an operator launch.
  • status server --json reports running and compatibility state. Noninteractive workspace commands do not auto-start the server.
  • The stable schema contains exact raw pane.focus, but the published method table omits it. This plan uses documented agent.focus instead.

Architecture and data flow

The same generic handle emerges from either exact discovery key. Herdr does not introduce a second session producer or any persisted Herdr state.

Implementation plan

Prove and add PID-ancestry correlation

In discovery/correlate.ts, keep tty as the strongest key. For a mux pane with null tty, match only when its current panePid is in the agent's actual parent chain. Choose the closest same-backend ancestor and decline ambiguity. Update the stale type comments and add nested, recycled-PID, missing-chain, and ambiguity tests.

Add explicit create-selection intent

Add select: boolean to DetachedSessionSpec. Dispatch passes false; operator launch passes true. tmux may ignore it. cmux and Herdr map it to their focus controls, with side panes created without focus.

Build the bounded Herdr socket client

Create herdr-client.ts for status, newline framing, request IDs, Zod validation, size and time bounds, batched process-info, and exact unknown-outcome handling. Workspace creation ensures a compatible server, starting herdr server as a detached child only when absent. Reads and existing-target mutations never start it.

Implement and register the adapter

Create herdr.ts, map snapshot records to MuxPane, implement pane I/O and workspace lifecycle, exhaustively map keys, use documented agent focus, declare honest null capabilities, isolate the default namespace, and register the new ID between tmux and cmux.

Cover contracts and user surfaces

Add socket, adapter, correlation, home, target, focus, registry, and setup tests. Extend E2E fakes with a deterministic Herdr binary and add Playwright coverage for the menu, shell launch, selection intent, cwd, focus attach, and incompatibility message. No real agent or Herdr daemon may run in tests.

Document the supported boundary

Update README and terminal docs with the version/protocol, HERDR_BIN, default-session scope, lifecycle features, client-raising limitation, and detach versus full-stop persistence. Do not edit CHANGELOG.md.

Validation and done criteria

  • Focused contract tests pass with the required test preload, then typecheck, lint, and the full unit suite pass.
  • Build, smoke, and Playwright E2E pass because a visible terminal backend is added.
  • Live stable-Herdr verification proves create, discovery, safe multiline paste, capture, focus, rename, detach/reattach, and close in a disposable workspace.
  • Proof stays gitignored and attaches to the implementation PR. No test starts a real agent or leaves a Herdr server.
  • No generic caller branches on herdr. Documentation matches the shipped version and limitations.

Decisions taken

  1. Integration architecture: use a socket-backed adapter behind Multiplexer, with bounded polling, safe multiline paste, and exact PID-ancestry fallback when no tty is available.
  2. Server namespace: support only Herdr's default local server session in the first release and clear namespace overrides at the adapter boundary.
  3. Outward focus: return clients: null, select inside Herdr, and use the existing new-client fallback. Never take over an existing direct attachment.
  4. Follow-up: create merge-aware phase plans and schedule dependency-linked implementation tasks after their paths land on the default branch.
