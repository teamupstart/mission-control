Implementation plan

Pi-managed Amazon Bedrock models

Answer: integrate Bedrock through Pi's first-class TypeScript SDK, not through a new AWS client or Bifrost. Keep Pi's current terminal runtime, add the shared managed SDK runtime, preserve provider-qualified model ids, and leave all AWS credentials under Pi's ownership.

2 mergeable phases 1,100-1,650 production LOC No database migration expected No AWS secrets in Mission Control

Outcome

Operators sign in with Pi's /login amazon-bedrock, select a live amazon-bedrock/<model-id> in Mission Control's existing picker, and run it in either Pi terminal or managed SDK mode. Managed sessions gain the lifecycle and interaction behavior already expected from Claude and Codex sessions.

The current terminal route already works: Pi discovers provider-qualified model ids and the dispatcher passes the selected id to pi --model. The feature is therefore a managed-runtime integration and product-hardening effort, not an Amazon Bedrock API implementation.

Architecture and request flow

Mission Control owns orchestration and projection. Pi owns provider configuration and model execution. Both runtime choices consume the same model identity.

Requirements

Discover and dispatch

Show Bedrock exactly when Pi reports it. Preserve the full model id through terminal and SDK paths, including stored-model fallback behavior.

Launch and restore

Bind the Mission Control session to a durable Pi session file. Restart restoration must reopen that exact conversation or fail explicitly.

Normalize lifecycle

Map Pi events to bound, state, activity, text, thinking, tool, usage, turn completion, question, and exit events without duplicate turns.

Control sessions

Support prompt, steer/follow-up, interrupt, model/thinking, clear/new-session, stop, and terminal handoff through the shared SDK contract.

Trust and UI

Resolve project trust before local resources load. Correlate select, confirm, input, and editor prompts to one answer or cancellation.

Automate safely

Enable Work Queue only for idle managed sessions after question and turn-completion invariants are proven. Attribute PR creation from observed tool output.

Failure contracts

SDK unavailableRefuse managed launch with a focused diagnostic while terminal Pi remains usable.

Stored model disappearsRetain the configured id visibly and fail launch. Never substitute a different model.
Session file missing or corruptRefuse resume. Never create a new conversation under the prior Mission Control id.
Project trust unresolvedDo not load local executable resources.
Question consumer disappearsCancel or time out the Pi promise exactly once so the session cannot deadlock.
Terminal session queuedRetain the shared SDK-runtime eligibility refusal.

No schema migration is expected. The existing runtime, driver session id, usage, question, and event records are reused. Any essential persisted-field discovery follows the additive database upgrade path and is documented as a deviation.

Delivery shape

Phase 1: Managed Pi Bedrock runtime

650-950 production LOC. Pin the SDK, add the Pi SdkSpec, normalize core events and lifecycle, wire capabilities, harden provider diagnostics, and prove terminal plus SDK Bedrock dispatch with fakes.

Phase 2: Structured interaction and automation

450-700 production LOC. Add project trust, the SDK UI bridge, question cleanup, Work Queue eligibility and acknowledgement, and pull-request provenance.

Phase 2 depends directly on Phase 1 and cannot run concurrently. The split makes direct managed sessions independently usable while isolating the harder question/concurrency boundary from the base transport.

Verification

  • Inject fake Pi SDK dependencies for unit and supervisor tests. Never read ~/.pi, contact AWS, renew SSO, or spend model tokens.
  • Cover provider-qualified ids, session persistence, event ordering, usage, control methods, trust, questions, and diagnostic classification.
  • Add Playwright coverage for selecting a fake Bedrock model, choosing SDK, dispatching, answering, interrupting, clearing, handoff, and queue follow-up.
  • Run focused tests, npm run typecheck, npm run lint, npm test, npm run build, npm run smoke, and npm run test:e2e. Add npm run package when packaged asset loading differs.
  • An opt-in harmless real Bedrock prompt is supplemental manual evidence only.

  • Existing Pi terminal, Claude, and Codex behavior remains green.
