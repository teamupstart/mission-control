Root cause

  1. The top strip is intentional shipped behavior. Commit 2da0eddc, merged as PR #699 under the title Show a dispatched task before its session exists, introduced StartingStrip to close the gap where a dispatched task had no session and appeared nowhere.
  2. The in-column redesign remained inside a failed task worktree. The retained task plan recommends the Working-column ghost and the retained diff implements it by replacing StartingStrip with PendingDispatch inside Board and Console layouts.
  3. There is no delivery record. The live task has status failed, no branch, and the exact error says the agent session ended with no outcome recorded. The retained files are uncommitted. There was therefore no commit or pull request to move this design into the shipped branch.
  4. This is not the SDK restore feature. Commit 9a073f7f, merged as PR #840, displays persisted SDK sessions while they restore after daemon startup. It does not project newly dispatched tasks before their first session exists.

Conclusion: the behavior did not regress after a successful delivery. The in-column task never completed its delivery lifecycle, so the application correctly continues to execute the older top-strip implementation.
