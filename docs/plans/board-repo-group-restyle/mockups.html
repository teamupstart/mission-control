Board: how a repository group looks

The grouping itself does not change here - same partition, same counts, same one-click disclosure, same accessible name. What changes is how the frame and its header are drawn. Every column below is the real board column at its real width, with the real cards rendered by the shipping components: two groups open, one folded away.

Three repositories, three palette entries: acme-api rose, acme-docs cyan, acme-web indigo - hashed by the same repoColor() the board uses, so the colours are real even though the repositories are fixtures. Every path, name and branch on this sheet is synthetic: a committed page carries no operator data.

The proposals, side by side

What the board drew until this change: a tinted frame, a tinted header band and a text-glyph chevron. Every group is a box inside a column, and each card is a box inside that.

What each one trades

A - Before

  • Three nested boxes - column, group, card - and the group's tint sits between the other two, so the card's own tone spine competes with it.
  • The hue is spent on area. A 6% wash over the body plus 11% over the head is enough colour to read as a state, which is the one thing a repository must not read as.
  • The chevron is a text glyph (⌄), so it sits off the row's optical centre.
  • 16px of the column goes to the frame's border and inset on every group.

B - Flush rule

  • Nothing nests. The cards sit at the same width and indent as an ungrouped card, so the group costs one 15px row and no horizontal space.
  • The colour becomes a line - a swatch and the near end of the hairline - which is about a tenth of the pixels the current tint spends on it.
  • Weakest containment of the four: where a group ends is read from the next header, not from an edge. Least suited to a column with many small groups.

C - Spine

  • The group's extent is visible without a box: the spine starts at the header and stops at the last card, which is exactly the fact the frame was drawing.
  • The colour lands on an edge, where a hue can run near full strength without reading as a fill - the same trick the card's own tone spine already uses.
  • The 14px gutter is the cost, and it is paid once per group rather than twice.
  • Two vertical rules, 12px apart - the group's spine and the card's own tone spine - which is the honest weakness here. Kept at 48% so the saturated one stays the card's.

D - Quiet box

  • Keeps the frame, so nothing about scanning or drag targets changes - this is the smallest departure from what is on the board now.
  • One 2px top edge instead of two translucent tints, and on the top rather than the side so it never reads as a second card spine. The head is a band, not a coloured pill.
  • The count becomes a tag, which is what separates it from the name now that there is no tint to do it.
  • Still nests: 14px of column width per group, and a run cluster inside is still a box in a box.

E - Sticky strip

  • Survives the scroll. The only proposal that answers "which repository is this card in" after the header has scrolled past - scroll a column to see it.
  • Full-bleed to the column's edges, which is what makes it read as a section band rather than as a floating pill.
  • The cards keep the full width, as in B - the strip is the only structure.
  • Costs the strip's opacity: it must hide the cards passing under it, so it is the one proposal that puts a solid surface over the column background.

F - Section label

  • Not a new invention. This is the section heading the settings pages already draw, so a repository group reads like every other group of things in the app.
  • The rule runs the column's width and sits under the label, which is what makes it a section rather than a card with a title.
  • The name goes uppercase and letter-spaced, so it stops competing with the card titles below it - and stops being monospace, which is the one identity cue it gives up.

G - Chip

  • Nothing spans the column but the cards. The header is as wide as its words, so the column's background reads through beside it and the cards are the only full-width thing in the column.
  • The tint comes back, but on 90px instead of a whole frame - a chip is small enough to carry the repository's hue without reading as a state.
  • Smallest hit target of the set: a pill, not a row. Still 24px tall, which clears the minimum, but it is the one option where the control is not the full width.

H - Merged list

  • Removes the nesting by removing the inner box. Two thirds of what makes today's frame look heavy is the card's own border repeating 8px inside the frame's, and this is the only proposal that addresses that directly.
  • Densest of the set. The gaps between cards inside a group go to zero, so a four-card group is about 30px shorter.
  • The only proposal that changes the card. A card inside a group stops looking like a card outside one, which is a real cost: the board teaches that a tile is a tile.

I - Quiet box + spine

  • Containment and identity, separately. The box is the group and the coloured bracket is the repository, so neither has to be read off a tint - which is the one thing today's frame asks a translucent wash to do twice.
  • Both edges, one mix. The 2px top and the 3px spine are the same colour, so the miter where they meet is invisible and they read as one bracket rather than two marks that happen to share a hue.
  • The swatch goes. A dot 9px from a 3px rule of the same hue is the same fact twice.
  • Two vertical rules again, about 10px apart - but unlike C there is a border and a background between them, and the spine is held at 78% so the saturated one stays the card's. This is the most colour of any proposal here.
  • Costs the same 14px of column width per group that D does.
