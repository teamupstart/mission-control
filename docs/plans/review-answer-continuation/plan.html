Implementation plan

Durable review answer continuation

Preserve the blocking fast path, then use the existing pending-turn outbox when the MCP result channel has ended.

Goal

Make a human review answer reach its session even when the original blocking MCP tool call has already been canceled by the host.

Progress notifications are not an unlimited lease. The fallback must be durable and independent of any one MCP client's timeout policy.

Approved decisions

  • Use durable review-answer continuation through the existing pending-turn outbox. Raising the MCP timeout and replaying an identical ask remain defense-in-depth ideas, not the primary solution.
  • After finalizing this source plan, create a phased implementation plan and schedule its dependency-linked Mission Control task.

Flow change

Implementation

  1. Add nullable detach and continuation timestamps beside the review migration.
  2. Add an authenticated, session-bound detach route called when the MCP request is canceled.
  3. Format one semantic review result for both the MCP fast path and fallback turn.
  4. Atomically create an idempotent pending turn and stamp the review.
  5. Queue detached human answers and reconcile unfinished deliveries after restart.
  6. Correct timeout documentation and comments.

Verification

  • Cancellation before and after resolution.
  • Restart recovery and idempotence.
  • Session ownership and cross-session refusal.
  • HTTP, MCP bundle, and Playwright coverage.
  • Focused tests, typecheck, lint, build, smoke, and focused end-to-end run.

Alternatives

Raise timeouts: smaller, but only moves the deadline and is host-specific.

Replay an identical retry: useful defense in depth, but depends on a retry and lacks a stable request key.
