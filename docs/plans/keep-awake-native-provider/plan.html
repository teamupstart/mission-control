Approved engineering plan · 19 August 2026

Native Keep Awake provider

Replace Mission Control's macOS /usr/bin/caffeinate child with a daemon-owned, in-process IOKit assertion. The display must still dim, turn off, and lock normally while user-idle system sleep is inhibited.

Selected direction: option 1 from the Scout report, implemented through a small Darwin-only raw Node-API addon. This is a provider replacement, not a Keep Awake redesign.

Outcome

Local agents and recurring work continue behind a locked screen without depending on the process that was observed exiting under SIGKILL. Lid close, manual Sleep, low battery, thermal protection, shutdown, and power loss still win.

This is not authorization to evade an intentional endpoint control. If the native assertion is denied or all local sleep inhibition is prohibited, verification stops and reports that boundary.

Why change the provider

The current manager starts /usr/bin/caffeinate -i -w <daemon PID>. On the checked managed Mac, that child started and was then terminated with SIGKILL, leaving Mission Control in live · awake failed. The evidence did not establish which process or policy sent the signal.

Apple exposes the same narrow behavior through kIOPMAssertionTypePreventUserIdleSystemSleep. Calling it in the daemon removes the observed executable and child-process surface without simulating activity or keeping the display awake.

Approved decisions

Daemon-owned IOKit

Use kIOPMAssertionTypePreventUserIdleSystemSleep with a bounded, human-readable Mission Control reason.

No Electron ownership

powerSaveBlocker cannot uniformly serve browser, adopted-daemon, standalone, and LaunchAgent modes.

Test command remains

Keep MISSION_KEEP_AWAKE_BIN only as the explicit Linux-safe unit and browser-test provider, never as production fallback.

Transient lifecycle

Every daemon starts off. Enablement stays explicit and releases on disable, shutdown, crash, or restart.

  • No display-sleep assertion or synthetic user activity.
  • No persistence, automatic retry, or coupling to Away mode or schedules.
  • No command fallback after a native load or IOKit failure.

Current contracts that stay intact

  • KeepAwakeManager serializes transitions and publishes observations, never request echoes.
  • GET /api/keep-awake and PUT /api/keep-awake remain the only control path.
  • Registry snapshot plus keep_awake_status SSE remain the browser's only state source.
  • The control keeps reconnecting precedence and the promise that the screen locks normally.
  • No database row, config key, startup restore, or automatic reacquisition is introduced.
  • The same daemon implementation serves packaged, adopted, browser, standalone, and LaunchAgent modes.

Runtime design

Native assertion handle

A Darwin-only Objective-C++ addon exposes side-effect-free create and release operations. Create returns an opaque handle only after kIOReturnSuccess. Release deactivates that exact assertion. A finalizer is a leak backstop, while normal disable and shutdown release deterministically. Process death lets macOS remove the process-owned assertion, replacing -w <daemon PID>.

Provider boundary

The manager owns state and serialization. Resolution prefers the explicit command test override, then native IOKit on Darwin, then unsupported. Native failures are visible and never fall back to caffeinate. Append iokit to the live provider union while retaining caffeinate for the fixture.

Request and status flow

Build and package design

  • Declare node-gyp directly and compile only on Darwin.
  • Copy the output to dist/native/keep-awake.node; Vite clears only dist/web.
  • Build before source daemon startup and before the production bundle.
  • Resolve one explicit path from import.meta.url in source and bundled execution.
  • Keep the addon external to esbuild. Existing dist/**/* packaging captures it.
  • Use stable Node-API supported by Node 24 and Electron 43's Node 24 utility process.
  • Fail clearly on unsupported requested Darwin architecture instead of copying a misleading host binary.

There is no database, configuration, or downgrade migration. A downgrade cannot inherit the old process-owned assertion.

Verification

Automated

  • Injected fake providers only; ordinary tests never call IOKit or alter host power.
  • Cover selection, override precedence, unsupported platforms, create/release errors and retry, concurrency, bounded errors, and shutdown.
  • Keep HTTP, Registry/SSE, render, reducer, and Linux Playwright coverage green.
  • Build the addon on Darwin, skip deliberately on Linux, and load it side-effect free in smoke.
  • Package on macOS arm64 and load it from the Electron utility process.

Real macOS receipt

  1. Confirm no caffeinate -i -w process appears.
  2. Confirm the Mission Control daemon owns PreventUserIdleSystemSleep and no display assertion.
  3. Lock the screen, wait past display sleep, require authentication, and observe continuing non-destructive work.
  4. Disable and confirm the assertion disappears.
  5. Enable, kill the daemon, and confirm the assertion disappears.
  6. Restart off and repeat through packaged, adopted, and LaunchAgent paths.

Stop condition: if endpoint policy denies or terminates the assertion, preserve that evidence and do not add an evasive fallback.

Non-goals

  • Keeping the display awake, simulating input, or overriding manual and safety sleep causes.
  • Persistence, automatic reacquisition, Electron ownership, Windows/Linux production providers, or remote execution.
  • Changing UI layout, copy, routes, SSE event names, or database state.
