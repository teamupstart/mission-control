Six alternatives to the + workflow chip, each drawn into a full Console detail header so it is judged at real density. They are live - hover option 3, click the ⋯ in 4, click the tabs in 5.

The reason it grates: .workflow-bind-chip shares its entire visual definition with .workflow-chip (styles.css:87-103) - same --working blue pill, same border. But they are opposite things. One reports state that exists; this one offers an action for state that doesn't. So a call-to-action sits in the status row wearing the status colour, two chips away from the real working badge - and it renders on every session with no workflow bound, which is nearly all of them.

Picking one

  • 1 is the fix if the complaint is purely visual - one CSS rule, no behaviour change, nothing to replicate elsewhere.
  • 4 and 5 are the fixes if the complaint is that the header is full. Both remove the chip rather than restyling it, and both scale to the next feature that wants a slot there.
  • 5 is the only one that also improves the bound case - today a run is a chip that opens a modal.
  • Whichever wins, it lands in two files: SessionCard.tsx:240-252 and ConsoleDetail.tsx:254-263 carry copies of this chip. Per the layout-parity rule a shared leaf belongs in session-bits.tsx - this one never got one, which is why there are two copies to keep in step. Option 5 additionally touches SessionTile and RailRow, since a tab is not a mark those two can show.
