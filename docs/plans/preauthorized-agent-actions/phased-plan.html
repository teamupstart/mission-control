One vertical phase applies the same scoped authorization to initial task delivery and every workflow continuation, without changing capabilities, frozen workflows, or dashboard UI.

Repository investigation

Initial task delivery

withTaskKindContract is shared by fresh dispatch and live-session assignment. The old byte-identical ship invariant becomes exact human-intent prefix plus platform authorization and narrower task contracts.

Workflow continuations

src/server/workflows/feedback.ts owns Persona, Inspector, unchanged-evidence, legacy PR, and SessionAction packets. Authorization belongs in the truncation-safe suffix and, for SessionActions, in the runtime envelope before immutable authored Markdown.

Compatibility

Do not edit actions/pull-request.md, generated action sources, or No-Mistakes v1-v10. Do not change MCP registration, sandbox posture, evidence schemas, routes, storage, or repository validation.

Sizing and phase count

Estimated non-test production change: 90-160 lines.

This is below the 200-line threshold, so it is exactly one one-shot phase. Splitting task delivery from workflow continuations would ship an incomplete policy and duplicate one wording contract across merge units.

Compatibility decisions

  • Preserve the original human intent as the exact task-prompt prefix.
  • Place broad authorization before more-specific task-kind contracts, leaving the scout no-PR rule authoritative.
  • Keep SessionActionSnapshot.promptMarkdown byte-for-byte and at the end of its packet; policy is runtime envelope data.
  • Leave prepared delivery payloads and No-Mistakes v1-v10 unchanged.
  • Keep MCP, sandbox, evidence validation, and repository enforcement unchanged.
  • Leave workflow resubmission to the engine or Runs UI; the agent repairs, stages evidence when useful, and stops.
