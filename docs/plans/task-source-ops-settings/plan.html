Task source operations overview in Settings

Rendered from the authoritative implementation plan.

Goal

Replace the one-large-card-per-source Task sources panel with the operations-first Settings layout selected from mockup #3. It must make dozens of configured sources scannable by health, type and schedule, while retaining access to every existing per-source setting and safety action.

Scope

  1. Add configured, healthy, attention and pending counts with compact source rows.
  2. Show the existing source editor only for a selected source.
  3. Provide all, healthy, attention, pending and paused health filters, text search and type filtering.
  4. Keep every existing source action and Add a source.
  5. Invalidate health from before a pause, including an in-flight result, while preserving a manual sweep begun while paused.
  6. Restore focus to the former row, or the directory when filters hide it, and consume the restoration request.
  7. Extend panel and sweeper regression coverage.

UI behavior

The default pane is a directory with summary cards, an attention callout, filters and compact rows. Selecting a row replaces it with the existing source editor and an “All task sources” back control. Search and filter state survives that round trip, and focus returns to the former row or the directory container. Add source retains the current selector and repository chooser; this change does not implement Jira, Slack, Linear or other connectors.

Data flow

The API response shape remains unchanged. The daemon clears pre-pause health and rejects a late result from a sweep begun before that transition; a manual sweep begun while paused remains current after re-enabling.

        ↓                     ↓
existing TaskSourcesState callbacks → existing task-source routes
