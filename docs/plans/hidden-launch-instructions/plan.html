Mission Control product plan

Hide launch instructions from conversations

Keep the complete launch contract in the agent transcript and every evidence path, while giving the dashboard a cleaner top-of-conversation experience.

Approved for phased planning

Decision

Show only the human task request.

Mark every non-empty prompt used to start a fresh Mission Control-managed agent conversation as launch metadata. Retain the complete text in the native transcript and every server-side evidence path, but render only the original human-authored Task.intent as the first user turn.

This keeps the natural request-response shape while removing repository manifests, execution authorization, task-kind contracts, and other platform-owned launch instructions from visible scrollback. The display is an explicit projection of the full native turn, not a rewrite of the transcript.

Problem

Mission Control composes a launch prompt from the task intent plus platform-owned context such as repository manifests, execution authorization, and task-kind contracts. That payload is important to the agent and intentionally preserved in the native Claude, Codex, or Pi transcript. Today the conversation window renders it as an ordinary message from the user, creating a large and confusing first turn.

The change is presentational, not destructive. The exact prompt still reaches the agent, native transcripts stay untouched, and Goal, Workflow, Foreman, archive, review, and retro consumers retain the full turn. Only the dashboard conversation and its search results treat the turn differently.

Current and proposed flow

One durable classification separates the visible conversation from the evidence record without creating a second transcript.

Chosen presentation: show the human task request

Approved

The marker carries a safe display projection. The agent receives the composed prompt, but the conversation renders only the original Task.intent.

Benefits

  • Preserves a natural request-response conversation
  • Removes the platform-owned text most likely to confuse a user
  • Makes the first turn agree with the human-authored task record

Trade-offs: visible text differs from the native transcript, launch sources without a distinct intent need a fallback, and prompt composition must keep visible and hidden segments separate.

Shared technical design

The approved presentation uses one control-plane foundation across every supported harness.

Classify at the delivery boundary

Record an exact non-empty launch prompt at terminal task dispatch, Pi's positional launch, ordinary embedded SDK dispatch, and pipeline tasks that directly launch an SDK agent conversation. The terminal Conductor pipeline host is not itself a streamable agent conversation, so it has no conversation turn to classify and remains unchanged. Do not classify:

  • a task assigned into an already-running conversation;
  • a human follow-up;
  • a Foreman or Workflow instruction;
  • an empty resume prompt;
  • a manually discovered session that Mission Control did not launch.

Persist the marker against the same logical conversation identity used by Goal and notes, including provisional-to-native key rotation. This makes it stable across restart, restoration, paging, and late hook binding.

Attach semantic metadata during normalization

Extend the normalized message contract with an optional semantic value such as presentation: "launch". Match against the recorded conversation identity and prompt fingerprint, not a global "first user message" heuristic. Keep text, tools, timestamp, role, and native id intact for every server-side consumer.

Apply presentation in one browser selector

Derive visible messages before transcript rows, conversation merge, find indexing, empty-state calculation, and both Chat and Native renderers. Keep transcript history and SSE resume offsets based on unfiltered native bytes so presentation cannot break pagination or reconnect.

The selector substitutes the recorded human-intent projection. If a source has no distinct human-authored projection, it omits the marked launch turn rather than showing platform instructions or inventing user-authored text.

Compatibility and lifecycle

  • Existing unmarked transcripts render unchanged. There is no heuristic backfill.
  • A context clear starts a new logical conversation and does not inherit the marker.
  • Goal, Workflow, Foreman, Scout archive, review, and retro paths retain the full prompt.
  • The wire change is additive. Older dashboards ignore the optional marker.
  • Cleanup follows the existing logical-key lifecycle and does not add another session eviction path.

Verification

Start from a Playwright reproduction against the built dashboard and fake agent fixture that proves the long launch contract is visible before the change. The final spec covers:

  • the selected presentation in Chat and Native views;
  • absence of the hidden text from find-in-conversation results;
  • complete composed launch-prompt receipt by the fake agent;
  • a human follow-up with identical or similar text;
  • manual and resumed sessions retaining their first human turn;
  • reload and pagination never making the launch turn reappear;
  • the correct empty state until the agent replies.

Focused tests pin persistence and key rotation, cross-harness normalization, wire compatibility, the web selector, and unchanged evidence windows. Run typecheck, lint, focused Node tests, build, smoke, and the required end-to-end suite.

Documentation

Update session and conversation documentation to explain that Mission Control-managed launch prompts remain part of the agent transcript and evidence history but may have a different dashboard presentation. State the exact scope so users do not assume follow-ups or workflow instructions are being deleted.

Non-goals

  • Deleting or rewriting native transcripts
  • Withholding any launch contract from the agent
  • Hiding follow-ups, live-session task assignments, Foreman turns, or Workflow repairs
  • Changing Goal derivation or evidence retention
  • Guessing at old sessions that have no launch marker

Approved decisions

  • Conversation presentation: show only the human task request. Keep the complete composed launch prompt in the native transcript and every server-side evidence path.
  • Implementation follow-up: create a repository-verified phased implementation plan and schedule its dependency-linked Mission Control tasks.
