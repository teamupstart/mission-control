Resume permission loss

Why did a resumed agent lose repository permissions?

Resume rebuilds a session from its stored configuration but never replays the repository grant, so the relaunched session starts with an empty allowlist. Every resumed session loses repository writes at its first tool call.

Evidence

StepGrant presentSource
Initial launchyesdispatcher.ts:214
Stored configyesharness.db tasks.grants
Resumenoregistry.ts:412

What we ruled out

  • Grant expiry. The stored record carries no TTL and the row is unchanged across the resume.
  • Harness differences. Codex, Claude and pi sessions all lose the grant at the same point.
  • Filesystem permissions. The checkout stays writable throughout; the refusal is the allowlist check.

Limits

Only resumes through the dispatcher were exercised. A resume triggered from the Fleet page shares the registry path and is very likely affected, but that was not reproduced here.
