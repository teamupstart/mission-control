Mission Control / Product plan / Scope 1

Observed activity, without pretending it is telemetry.

A compact Conversation sideband built from transcript data Mission Control already receives. It helps people scan agent actions while staying honest about what the system can prove.

The promise

Show that a tool invocation was observed, its approximate transcript time, and a display-safe target. Never claim that it is running, complete, successful, failed, or of a known duration.

Problem

Agent prose is readable. Agent action is buried.

Conversation already contains inline tool chips, but they are hard to scan across a long exchange. The Duplex Console concept adds a secondary channel that answers a narrower question: what actions has the agent attempted while producing this conversation?

AVAILABLE NOW

Tool name, optional recorded input, and approximate message time.

ALREADY STREAMED

Per-session transcript SSE with reconnect and older scrollback.

NOT UNIFORM

Result, duration, lifecycle state, and stable invocation identity.

Intended experience

One source, two reading modes.

Wide surfaces

A right-side Observed activity rail shows time, tool label, and a compact target. Transcript and rail scroll independently; composer stays pinned.

Narrow surfaces

Activity stacks or collapses instead of permanently squeezing the transcript. Console detail and expanded cards share the same behavior.

Find interaction

Find owns the secondary rail while open. Closing Find restores activity. Search remains canonical to the transcript, without duplicate matches.

Empty state

The rail says “No observed tool activity yet.” It does not imply a connection failure or disable an otherwise usable composer.

History

Older loaded messages add older activity. The activity window intentionally matches the loaded transcript window.

Reconnect

The rail re-derives from deduplicated transcript state rather than maintaining a second event cache.

Data flow

The server path stays exactly where it is.

Requirements

Small surface, strict contract.

  1. Derive activity only from messages already held by TranscriptPanel.
  2. Include every loaded invocation once, including tools attached to prose turns.
  3. Reuse the existing tool label and target projection.
  4. Avoid result, status, duration, and process-coverage implications.
  5. Preserve stream, scrollback, reconnect, composer, and eviction behavior.
  6. Give Find temporary ownership of the secondary rail.
  7. Preserve geometry in both Conversation hosts and at narrow widths.
  8. Use semantic, keyboard-accessible controls without data-testid.
  9. Document the observed-only meaning in the README.

Explicitly outside Scope 1

  • Operating-system process capture
  • Raw command output
  • Success, failure, duration, or counts
  • New server events or database state
  • Cross-source lifecycle reconciliation
  • Changes to harness transcript semantics
  • Replacement of inline tool chips
Compatibility and privacy

No new contract, and no extra raw input.

Wire contracts, persisted schemas, and harness protocols remain unchanged. Missing or partial input falls back to the normalized tool name. The sideband may expose no more raw input than the existing toolChip() projection already considers suitable for display.

Verification strategy

Prove projection, geometry, and real browser behavior.

Pure model

Mixed turns, multiple tools, missing input, ordering, rerenders, and prepended history.

Electron geometry

Both hosts, wide and narrow, Find open and closed, pinned composer, and independent scroll.

Playwright

Built dashboard and fake agents only, including Find takeover and narrow operation.

Release bar

Typecheck, lint, unit tests, build, smoke, and relevant full e2e.

Visual pass

Desktop and narrow comparison to the Duplex Console direction.

Documentation

README describes loaded-transcript scope and the absence of lifecycle guarantees.

Acceptance

What must be true when the phase lands.

Tool invocations are scannable without leaving Conversation.
No unsupported lifecycle fact appears in the rail.
Live updates, reconnect, and older scrollback remain consistent.
Find and activity never compete for the same secondary space.
Composer and transcript remain usable without host-page overflow.
Console detail and expanded cards behave the same.
Browser coverage proves the feature with fake-agent fixtures.
README and UI use the same observed-only contract.
Delivery

One coherent phase. Projection, UI, responsive geometry, tests, and documentation form one merge-safe vertical slice. Review the scheduled implementation route.
